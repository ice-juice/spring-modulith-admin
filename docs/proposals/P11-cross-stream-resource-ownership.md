# P11 跨专项资源与账本归属

日期：2026-11-12　版本：v1　归属：可复用基座约束　状态：**用户已确认执行；本文是跨线约束，不单独交付功能**。

本文不新增功能，只统一四条并行专项共用底座资源时的归属规则：[P08 缓存治理](P08-cache-governance-and-cluster.md)、[租户平台](P10-tenant-branding-and-storage.md)、[P09 身份/邮件/存储](P09-identity-mail-storage-and-secure-upload.md)、[安全专项](P10-security-defense-and-branding.md)。四份方案各自有效，冲突项以本文为准，并在各自进度文档中逐项验收。

依据为 2026-11-12 工作区源码与四份专项进度的静态核对，不是运行时验证。本文的结论不代表任何阶段已经交付。

## 1. 为什么需要这份约束

四条线分别要求“与业务写入同一个数据库事务提交”，而租户平台计划把业务数据迁往按租户绑定的独立 MySQL。两项要求在分库之后不能同时成立：

| 账本 | 当前位置 | 要求 | 分库后是否成立 |
| --- | --- | --- | --- |
| `common_request_execution` / `common_request_mutex` 幂等账本 | 平台库 | 执行权与业务写同事务提交 | 否，变成跨库 |
| `common_cache_revision` 失效代次 | 平台库 | 版本行更新与业务写同事务 | 否，变成跨库 |
| `common_id_block` 主键块 | 平台库 | 预分配块，块内不需要同事务 | 是，不受影响 |
| 各模块预算表 | 平台库 | 独立提交，不随业务回滚 | 是，本就独立 |

今天两项之所以成立，是因为 [PersistenceConfiguration](../../backend/src/main/java/com/sma/admin/common/internal/PersistenceConfiguration.java) 把 `com.sma.admin` 与 `com.sma.business` 两个包根扫描进同一个 SqlSessionFactory 和同一个数据源。该前提在租户平台 S6 接入业务路由时消失。

## 2. 归属规则

**规则 1：要求与业务写同事务的账本随业务资源走。** 业务模块写入独立业务库时，其幂等执行权、互斥记录、缓存失效登记和 Outbox 必须落在同一个业务库，由宿主存储运行时按模块与框架迁移登记创建。平台库只保留目录、跨库对账与运维视图，不得先提交平台账本再声称与业务写入原子。

**规则 2：平台自有写入继续使用平台库。** 平台模块（auth、iam、config、tenant、monitor、audit、message、file 元数据、identity、mail、openapi、rule、extension）的写入本就在平台库，其账本不变，仍为同库本地事务，不受分库影响。

**规则 3：跨平台库与业务库的联动不假装原子。** 一个本地事务只覆盖一个数据库资源。联动使用业务库同事务 Outbox、稳定幂等键与重试补偿；结果未知保持 UNKNOWN 并对账，不盲目重发。

**规则 4：代次汇聚延迟必须显式承认。** 业务库内的失效登记由所属业务资源提交，平台侧的目录汇聚是异步的。该汇聚窗口是有界陈旧，不得宣称与业务提交强一致；跨资源的权威校验仍以各自资源内的版本行为准。

**规则 5：主键块与预算表不改。** `common_id_block` 按块预分配，块内无需跨库协调；各模块预算表本就独立提交、不随业务回滚，继续留在各自模块所属库。

## 3. Redis 归属

部署级 Redis 仍由 P08 的受控连接工厂拥有，provider、地址、拓扑、协议版本与命名空间保持**重启生效**，不在网页在线换集群。租户平台的资源登记只负责“某租户的可重建业务缓存绑定到哪个已登记物理资源”，并提供连接池与客户端预算；它不得改变 P08 的区域语义、键布局、失效协议或配额实现。

- 共享实例复用同一客户端；只有显式绑定专用资源才新增客户端，统一有界网络线程、超时、TLS、ACL 与连接预算。
- 租户级资源改绑只对新解析生效，必须走冷启动或限速预热，不得对在途请求热切换。
- PROTECTED 状态（会话、票据、验证码、TOTP、限流、nonce、幂等）永远不随业务 Redis 迁移，也不因资源故障降级到本地。
- 单个资源故障按资源＋租户隔离熔断与并发配额，不得耗尽宿主全部回源与线程。

## 4. 预算与并发口径

各模块的持久预算表（auth `SecurityRateLimit`、openapi `LoginBudget`、identity `IdentityEmailBudget`/`IdentityLoginBudget`、file `TaskBudget`、common `RequestBudget`、tenant `BrandWorkBudget`）保留各自语义，不合并实现。但必须在[接口清单](../security-endpoint-inventory.md)中统一登记以下字段：

- scope：`shared`（数据库持久、跨实例累计）或 `node`（单进程内并发门禁）。
- 存储位置：所属模块与库。
- 多实例换算：标注 `node` 预算在 N 个实例下的实际受理容量为 N 倍，部署文档据此给出总量。

节点级并发门禁（当前 `/app/**` 默认 64、`/api` 写默认 8）不是集群总量。任何“系统每分钟最多 X 次”的说法必须注明是共享预算还是节点预算。

## 5. 品牌公开资产的验收顺序

品牌素材经 file 模块上传并通过匿名白名单入口对外投影，而 P09 的文件安全流水线（C4d）尚未完成。因此：

- 品牌资产的类型校验、URL 策略、公开投影字段与权限验收**不排在安全专项队尾**，提前到攻击采集（S2）之前执行。
- 在 P09 C4d 完成之前，品牌公开入口只接受已验证的受限图片类型，不得因“已在 S3/S4 标记完成”而跳过后续安全验收。
- 两份文档对品牌只保留租户平台一处实现，安全专项不重复建表或建管理页。

## 6. 联合验收

四条线各自使用独立测试库与输出目录，这对并行隔离是必要的，但不能替代合流验证。在任一条线标记整体完成之前，必须存在一次**联合验收**：同一个数据库、同一对双实例，覆盖交叉矩阵。

| 场景 | 覆盖的冲突 |
| --- | --- |
| 业务库写入 ＋ 缓存失效 ＋ 跨节点读取 | 规则 1、规则 4 |
| 同键幂等重放跨实例、业务库事务回滚 | 规则 1、规则 3 |
| 应用用户登录 ＋ 后台会话 ＋ 机器调用三类身份互拒 | 第 4 节口径 |
| 文件上传与另一节点下载、品牌资产公开投影 | 第 5 节 |
| 单个业务 Redis 故障下正常租户 p95 不劣化 | 第 3 节 |

联合验收使用专用可清空库与隔离端口，不使用开发库、不重启现有服务。
