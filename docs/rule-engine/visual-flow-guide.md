# 可视化流程编排使用方法

面向开发和专业实施人员。入口：“规则中心 → 规则模板”，打开已有FLOW模板，或在允许“流程编排”的场景下创建模板。方案与实际验收状态见[visual-flow-design.md](visual-flow-design.md)。

## 编排步骤

1. 在组件库把“表达式、条件分支、多路选择、子规则、决策表、返回结果”拖入画布。也可点击组件添加，供键盘与触屏操作。开始节点自动创建且唯一；节点上限64。
2. 从源节点底部端口拖到目标节点顶部；也可选中节点，在配置栏选择各出口。条件节点分别指定成立/不成立出口；多路选择按匹配值配置各出口和默认出口。开始不能作为目标，禁止自连、循环和不支持的端口。
3. 选中节点设置取值与输出类型；计算节点结果用`context.steps.<节点ID>`访问。配置栏展示当前节点可用的input/params及共同前驱结果，不提供分支另一侧的结果作为可用输入。
4. 条件节点选择“条件构建器”，添加条件/条件组，配置AND/OR/NOT、字段、比较符和常量；或选择布尔表达式。切换方式会确认替换内容。常量为JSON值，数字`100`、字符串`"gold"`、布尔`true`对应不同类型。
5. 子规则节点点击“浏览模板 / 加载更多”，选择模板，读取版本，选择不可变版本并点击“应用此版本”。按字段设置子规则输入和参数，来源可以是父级字段、保证执行的前驱结果或受限表达式。决策表节点只列出决策表版本。输出契约跟随固定版本，不能随意改成另一类型；换版本后检查原映射。
6. 返回节点选择字段/前驱结果或填写受限表达式，返回值须符合场景最终输出契约。复杂对象表达式仍走原服务端校验，不允许Java、Bean调用或业务写副作用。
7. 打开“模拟与解释”，输入测试数据与实例参数，校验并模拟。通过追踪定位执行节点，检查真假分支和跳过节点；修改规则或数据后旧结果自动失效。添加代表性发布断言，再保存草稿并明确发布。

## 资格判断与计算示例

前置：建立比例折扣示例场景，同时允许FLOW，先创建并发布一个比例折扣子规则。然后创建空白FLOW模板：

| 节点 | 配置 | 出口 |
| --- | --- | --- |
| start | 使用场景amount输入和ratio参数 | 指向条件节点node1 |
| node1 | 条件构建器：input.amount ≥ 常量100 | 成立→node2，不成立→result |
| node2 | 固定折扣子规则版本；输入amount←input.amount，参数ratio←params.ratio | 指向node3 |
| node3 | 返回context.steps.node2 | 终止 |
| result | 返回input.amount | 终止 |

ratio=0.9时，amount=100得到90，99.99得到99.99，0得到0。node3只能位于node2之后，不能让另一条没有执行node2的分支直接引用它。实际业务绑定仍需其所属模块授权，示例不自动绑定真实商品。

## 编辑与运行边界

- 点选连线或用“选择连线”下拉，点击“断开选中连线”。删除节点需要确认并清理相连出口；开始不可删除。领域图变化可撤销/重做，未保存离开继续使用原确认。
- 画布坐标、选择和缩放只保留当前编辑会话，不写入执行文档，刷新后按列表重新布局。位置拖动不计入领域图撤销。高级JSON供专业兼容编辑，不是常用操作的必经入口。
- 场景输入和最终输出契约不可在单个流程中随意扩展；新契约建新场景。参数遵守场景策略。计算节点可配置独立输出Schema，对象可逐字段编辑。
- 固定版本不会自动切换到新发布版本。当前权限无法读取版本详情时保留原ID和映射，不能把空列表当作删除指令；实际执行/发布仍校验版本可用性、类型、权限和租户。
- 缺出口、孤立节点、不合类型、非确定可用前驱等最终由后端拒绝；当前编辑状态可能尚不完整，不代表能发布。没有循环、并行共享变量、外部HTTP或业务写动作。
- 当前服务沿用Vite模式，刷新即可加载源码变更；构建产物和真实隔离验收分别记录，不把HTTP200当成登录后的业务验收。
