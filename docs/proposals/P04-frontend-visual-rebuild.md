# P04 前端产品视觉与交互重构方案

日期：2026-11-10。

状态：用户已确定采用 shadcn-vue + Tailwind CSS，并接受完整重建前端。本文件为整体开发方案；工程创建、依赖安装、界面开发、环境切换均未执行。

## 1. 目标与范围

将现有后台重建为具有统一设计语言、清晰信息层级和可维护业务组件的产品界面。首期交付覆盖现有后台功能，建立后续开发能够复用的设计和工程基础。

本期目标：

1. 重建应用框架、登录、安全入口和全部现有业务页面。
2. 建立覆盖浅色、深色、中文、英文及不同屏幕宽度的设计规范。
3. 建立数据表格、筛选、表单、权限树和文件选择等业务组件。
4. 对齐当前路由、接口、授权语义、偏好和消息实时行为。
5. 通过代表性页面验证后，逐模块实施并验收，最后切换新前端。

后端既有 REST API 是迁移契约。发现缺失能力或接口问题时单独记录、评估；后端业务修改不自动并入本次视觉重构。

hiprint、AI 数智化中心及原验收范围外的功能继续作为后续项目。本次为它们预留页面和组件扩展方式，不提前创建没有业务内容的入口。

## 2. 当前基线与核查结论

依据：根 README、frontend/package.json、现有路由与业务源码、docs/acceptance.md、docs/browser-audit.md。

| 方面 | 当前情况 | 对重构的要求 |
| --- | --- | --- |
| 前端 | Vue 3、Vite、TypeScript、Element Plus、Pinia、vue-i18n；32 个 Vue 文件 | 重建组件与布局，逐项评估可复用的业务逻辑 |
| 管理页面 | IAM 管理页面通过资源配置覆盖多个业务入口 | 使用共享组件及独立业务页面，避免继续扩大单个通用管理组件 |
| 授权 | 服务端返回菜单、权限和导航；路由守卫与按钮授权 | 对齐现有权限 key、菜单层级、portal 与服务端授权边界 |
| 接口 | /api；ApiResponse；分页 items/total/page/size；长整型以字符串传输 | 集中转换表格状态和分页字段；业务 ID 保持字符串 |
| 认证 | Bearer 令牌；记住登录；401 清理登录；423 进入锁屏 | 重建全局反馈与安全界面，保持认证流程 |
| 偏好 | zh-CN/en-US、IANA 时区、浅色/深色/跟随系统、多标签 | 统一状态来源，支持刷新恢复及用户切换 |
| 消息 | 一次性 WebSocket 票据、角标、断线重连及补查 | 单实例连接管理，退出与强退时清理，避免布局重复挂载产生多条连接 |
| 编辑与文件 | Tiptap、受控文件请求、附件和头像 | 复用编辑内核及文件协议，重建工具栏、反馈与选择界面 |
| 工作区 | 已存在用户修改和新增文件 | 在实施前记录基线，不重置、不覆盖、不自动提交现有改动 |

历史巡检中的问题是回归检查依据，不直接等同于当前仍有缺陷。部分源码已发生后续修改，需要在新一轮实施前复核。

## 3. 产品视觉方向

### 3.1 默认设计方向

采用现代、克制的管理产品风格，以中性色和清晰排版承载业务内容。初稿延续现有青绿色品牌方向，主色仅用于主要操作、选中态和必要强调；不在每个模块中另设一套主题。

以下数值是首轮设计建议，在样板页面阶段统一校准：

| 项目 | 初稿规范 |
| --- | --- |
| 字体 | 中文使用系统中文字体；西文使用系统无衬线字体；标识与代码按需使用等宽字体 |
| 字号 | 正文和表单 14px，辅助文字 12px，页面标题 20–24px；允许浏览器缩放 |
| 间距 | 以 4px 为基础，常用 8/12/16/24/32px |
| 圆角 | 控件、菜单、浮层和容器统一分级，初稿以 6–10px 为主 |
| 层次 | 页面背景、内容表面、浮层分级；优先留白和分隔线，控制卡片数量 |
| 密度 | 提供标准与紧凑两档；初稿表格行高约 44px / 36px，内容过长时允许自适应 |
| 图标 | Lucide Vue；图标按钮具备可访问名称，重要动作保留文字 |
| 动效 | 简短过渡，尊重减少动态效果设置 |
| 主题 | 浅色、深色、跟随系统；首屏尽早应用主题，减少闪烁 |

颜色通过语义变量管理，包括 background、foreground、card、popover、border、muted、primary、destructive，以及业务状态色。页面使用这些变量和 Tailwind 工具类，避免各自硬编码颜色。深色模式单独检查状态色和层次，不做机械反色。

### 3.2 应用框架

- 左侧导航：品牌、菜单搜索、分组与折叠导航；折叠后仍有清晰图标、提示和可达的子菜单。
- 顶栏：导航折叠、面包屑、消息入口、主题/语言入口和用户菜单；安全操作集中组织。
- 顶部业务导航：保留服务端现有导航能力，与侧栏菜单共同工作，明确选中关系。
- 多标签：遵循现有“一个页面一个标签、更新该标签查询参数”的规则；状态按用户隔离，支持偏好关闭。
- 内容区：统一页面标题、简短说明、主要操作、筛选区、内容和分页的顺序。
- 页脚与登录页：沿用服务端系统名称和公开品牌配置，处理配置加载失败的默认状态。
- 菜单搜索限定为有权访问的现有菜单；首期不承诺跨业务全文搜索。

### 3.3 响应式与可访问性

验收宽度：1920、1440、1024、768、390px；补充检查 320px 的最低可用性。宽度之间也检查连续缩放，避免只在断点尺寸正常。

- 桌面侧栏在窄屏转换为抽屉导航，顶栏操作适当收纳。
- 筛选栏自动换行；窄屏折叠次要条件并显示当前条件数量。
- 表格在自身区域横向滚动；窄屏取消不适合的固定列，行操作收纳至菜单。
- 中短编辑表单采用弹窗或侧栏抽屉；复杂长表单采用独立页面。窄屏可转为全屏编辑。
- 弹层高度受视口限制，正文可滚动，主要操作保持可见；注意虚拟键盘与移动视口高度。
- 支持键盘导航、可见焦点、表单标签、错误提示关联、浮层关闭和焦点返回。
- 触屏主要操作目标约 44px；颜色同时配合文字或图形表达状态。
- 对照 WCAG 2.2 AA 检查对比度及相关交互；不把底层组件的无障碍能力视为整页已合格。

## 4. 技术方案与版本策略

| 层次 | 选择 | 实施说明 |
| --- | --- | --- |
| 工程 | Vue 3 + TypeScript + Vite | 延续现有 SPA 架构；保留当前工具链作为兼容性验证起点 |
| 组件 | shadcn-vue + Reka UI | 组件源码纳入仓库，按需添加；记录来源及重要定制 |
| 样式 | Tailwind CSS 4 + @tailwindcss/vite | CSS 入口和语义变量统一管理；以当前 v4 安装方式配置 |
| 路由与状态 | Vue Router + Pinia | 路由、用户状态、页面查询状态分工明确 |
| 表格 | @tanstack/vue-table | 以当前 shadcn-vue 官方 v9 示例作为验证起点，封装服务端列表协议 |
| 表单 | vee-validate 4 + @vee-validate/zod 4 + 兼容的 Zod 3 | 统一字段、校验和提交反馈；先验证完整类型与构建兼容性 |
| 国际化与时间 | vue-i18n + dayjs 及现有时区工具 | 复核后迁移语言资源与 UTC/IANA 处理逻辑 |
| 请求 | Axios + 现有接口协议 | 统一认证头、语言/时区头、业务错误及二进制响应 |
| 图标 | lucide-vue-next | 旧菜单图标名称通过显式映射兼容，未知名称使用统一回退 |
| 富文本 | Tiptap | 保留现有文档格式，重建工具栏及链接编辑界面 |
| 通知 | 项目统一通知接口，基于 Reka UI 相关能力封装 | 不依赖当前带 Nuxt peer 依赖的 vue-sonner 最新版 |
| 测试 | Vitest + Vue Test Utils；关键流程增加 Playwright | 业务逻辑、复杂交互、真实页面和视觉回归各有覆盖 |

2026-11-10 已读取 npm 发布元数据及 shadcn-vue 官方表格文档：

- shadcn-vue CLI：2.9.0；CLI 版本与生成后组件的运行时依赖分别记录。
- Tailwind CSS / @tailwindcss/vite：4.3.5；插件声明支持 Vite 8。
- Reka UI：2.11.0；@tanstack/vue-table：9.3.1；官方表格教程明确采用 v9。
- vee-validate / @vee-validate/zod：4.15.1；后者声明 Zod ^3.24.0，而 Zod 最新版为 4.6.7。
- vue-sonner 最新版 2.0.9 声明 Nuxt 相关 peer 依赖，不直接加入本项目。

这些是调研快照，不是已经完成安装验证的锁定清单。R1 必须完成实际安装、类型检查、生产构建和关键组件验证，再冻结 package-lock.json。禁止使用 --force 或 --legacy-peer-deps 隐藏冲突，也不为重构顺带升级所有已有依赖。

shadcn-vue 基础组件只做共性定制。业务数据、权限 key、接口请求和业务字段不进入基础 UI 组件；上游组件源码更新与底层依赖升级分别评估。

## 5. 工程组织与开发方式

### 5.1 独立工程渐进迁移

实施时在仓库内新建 frontend-next/，旧 frontend/ 继续保留。两套前端分别构建、分别运行，新工程使用独立开发端口（建议 5174；实施时检查占用并开启 strictPort），代理既有后端。

新工程不跨目录运行时导入旧前端源码。经核查可复用的协议、纯函数、类型和语言资源迁移到新工程，并带入有价值的业务测试，避免两套工程相互依赖。

并行开发阶段使用独立前端端口，现有开发脚本继续指向旧工程。最终验收后，在单独的切换步骤中统一主目录、构建脚本和部署文档。旧版本通过明确的版本记录与构建产物保留回退能力。

两套工程处于不同浏览器 origin，本地存储不会自动共享。验收时使用正常登录流程验证各自的令牌和偏好；不复制认证秘密实现跨端口同步。生产切换时核对同源部署下的存储键兼容性。

### 5.2 建议目录

```text
frontend-next/
  src/
    app/                 启动、路由、布局与全局错误处理
    components/
      ui/                shadcn-vue 基础组件源码
      business/          业务表格、表单、树与选择器
    features/
      auth/ iam/ config/ audit/ file/
      message/ monitor/ openapi/ workspace/
    shared/
      api/               HTTP 协议、分页适配与错误模型
      auth/              授权与会话公共能力
      lib/               时间、文件、菜单、标签等纯逻辑
      types/             跨模块稳定类型
    stores/              用户、偏好、品牌、消息连接等共享状态
    locales/             公共和模块语言资源
    styles/              Tailwind 入口、主题与排版规范
  e2e/                   关键流程和视觉回归
```

业务页面按 feature 组织页面、API、类型与相关逻辑。只在两个以上场景存在稳定共性时抽取共享能力；复杂授权和消息流程使用专门页面，不强塞进万能 CRUD 配置。

## 6. 必须建设的公共能力

### 6.1 数据表格与筛选

提供 PageHeader、FilterBar、DataTable、Pagination、RowActions、StatusBadge 和统一空状态。

- 服务器分页、筛选、排序以接口实际能力为准；不把当前页排序伪装成全量排序。
- TanStack 页码与服务端页码集中转换；page/size/total 进行显式边界转换；实体 ID 不转换成 Number。
- 关键词和筛选变更重置页码；请求支持取消或过期响应忽略，避免慢响应覆盖新结果。
- 查询条件按页面确定 URL 同步策略；同一路由的查询变化不新增重复工作标签。
- 明确正在加载、首次空数据、无匹配结果、失败及刷新状态；后台刷新保留已有结果。
- 行内操作不触发行选择或跳转；按钮权限、操作菜单、禁用原因统一处理。
- 跨页批量选择只有在业务和接口支持时提供，否则明确限制为当前页。
- 长标识、复制、时间、文件大小、状态及缺失值使用统一单元格呈现。
- 列显隐、密度与排序偏好按用户及表格标识隔离，设置版本和失效策略。
- 仅在实际大列表需要时引入虚拟滚动；以最大分页、树规模和真实交互测量决定。

### 6.2 表单与编辑容器

提供 FormField、Input、Textarea、NumberInput、Select、MultiSelect、Switch、DateTimeField、EntityPicker、TreeSelect、EditorDialog/Sheet 和 ConfirmAction。

- 统一必填标识、错误位置、帮助说明和异步校验反馈。
- 区分初始加载、编辑中、提交中、成功和失败；提交中避免重复请求，失败保留草稿。
- 校验文案随语言切换更新；服务器错误能够映射到字段或表单级提示。
- 编辑对象切换时复核草稿，防止把一个对象的数据提交给另一个对象。
- 有实质修改的表单关闭或离开时提示未保存内容；取消不触发写请求。
- 日期时间先明确字段语义：日期、用户本地时刻、UTC Instant 分别处理。验证已有夏令时转换语义，对不存在或重复的本地时刻给出明确处理。
- 保存偏好时同步当前语言/时区，保留未保存的其他编辑字段。
- 敏感字段按现有接口遮蔽与回显规则处理，错误和通知中不显示认证秘密。

### 6.3 权限树与层级选择

独立提供 PermissionTree、DepartmentTreeSelect 和资源树组件。权限树需具备搜索、展开/收起、复选框、半选态、禁用态、加载与空状态，并可用键盘操作。

授权规则以当前接口为准，先验证父子关联、可授权范围、菜单祖先补齐、内置节点和禁用节点的行为。搜索只影响可见性，不能丢失隐藏节点的勾选；保存不能意外扩大权限或移除未展示的权限。

### 6.4 跨页面能力

- HTTP：保留 ApiResponse 业务失败、400/401/403/423、网络错误及 Blob 错误解析规则；写请求不自动重试。
- 授权：路由守卫、菜单过滤和按钮检查使用统一权限函数；服务器仍负责实际访问控制。
- 消息：连接、票据、重连、角标及补查集中管理，页面只订阅所需事件。
- 文件：统一上传状态、图片预览、附件选择、下载反馈、引用保护提示和对象 URL 释放。
- 全局反馈：短通知、持续警告、表单错误和页面错误各有明确用途，避免同一次失败重复提示。
- 生命周期：路由离开、退出登录、会话失效和用户切换清理轮询、监听器和用户相关状态。
- 国际化：公共语言资源在框架首次渲染前可用，模块按需加载；保留现有 key/插值与界面原始文案检查。

## 7. 页面重构清单

| 模块 | 页面/能力 | 主要设计及回归重点 |
| --- | --- | --- |
| auth | 登录、验证码、记住登录、锁屏、改密、在线会话 | 登录回跳、失败反馈、423、强退及当前会话限制 |

| config | 字典类型/字典项、参数、个人偏好 | 主从选择、点击冒泡、类型化编辑、敏感值、恢复默认、偏好同步 |
| audit | 登录日志、操作日志、详情及对象回跳 | 时区、筛选、长内容、访问权限、目标记录准确定位 |
| file | 文件列表、上传、预览、下载、头像和附件选择 | 受控读取、图片校验、引用保护、错误及空状态 |
| message | 收件中心、通知管理、私信、个人/管理待办 | 富文本、五类通知受众、附件、回执、回收站、未读和实时状态 |
| monitor | 服务器、SQL、缓存、事件发布、数据库文档 | 数据采样时间、页面退出停止轮询、清理/重试反馈、空状态、导出 |
| openapi | 应用列表、详情、编辑、关联、密钥操作 | 一次性密钥显示、复制、轮换影响说明及旧令牌失效 |

每个入口建立“旧路由 → 新页面 → 接口 → 操作权限 → 自动检查 → 页面验收 → 未验证项”记录。32 个 Vue 文件不是功能验收数量，通用页面覆盖的多条路由也分别计入。

| R0 基线与设计 | 记录工作区现状；建立功能/路由/接口矩阵；复核历史问题；制定主题、导航和页面规范 | 基线清单、设计变量表、主框架及用户管理/授权/工作台设计稿 | 功能范围完整；主要视觉和交互决策形成明确版本 |
| R1 工程与基础组件 | 新工程、依赖兼容验证、主题、路由、HTTP、国际化、基础 UI 与组件展示入口 | 独立可运行工程、锁文件、开发态组件展示页、版本记录 | 类型/构建/基础检查通过；明暗与双语言可切换；组件展示入口不进入生产导航 |
| R2 代表性页面闭环 | 实现应用框架、登录、用户管理、角色授权、工作台；先验证复杂表格、表单与树 | 三类样板及其真实接口联调、关键交互测试、页面截图 | 能正常登录并在有权限账户下完成样板流程；主题/语言/窄屏和异常场景可用 |
| R3 核心管理模块 | 完成 IAM 其余页面、字典、参数、偏好、资料、在线会话及审计 | 逐路由验收记录和新增业务组件 | 核心管理功能对齐；授权、时区、标签和表单状态无已知阻塞问题 |
| R4 消息与文件 | 文件、头像、附件、富文本、通知、待办、私信和实时消息 | 消息/文件端到端流程、资源与连接生命周期验证 | 两用户场景和断线恢复成立；文件与附件流程有独立验收证据 |
| R5 运维与应用中心 | 监控、SQL、缓存、事件、数据库文档和 OpenAPI 应用管理 | 剩余页面及操作反馈、完整功能矩阵 | 全部在范围内路由完成；操作结果和权限限制正确 |
| R6 全量验收与切换准备 | 完整回归、性能和无障碍检查；构建产物、部署及回退说明；旧依赖退出检查 | 验收报告、版本产物、切换与回退步骤 | 满足第 9 节标准；未验证项明确列出；具备可执行切换方案 |

R0–R2 按顺序完成；样板验证发现的问题先回到公共组件修正，再扩大页面迁移。后续模块沿用稳定规范，避免每个模块单独设计。

本轮只形成方案，R0 的设计稿与清单尚未制作。工期在 R2 完成后，依据实际组件建设成本、接口差异和剩余路由复杂度重新估算；不把调研阶段的假设当作已验证工期。

## 9. 验收与质量门禁

### 9.1 功能与数据

- 现有范围内的入口、按钮操作、筛选与详情回跳均有对应新实现和验收记录。
- 普通用户、受限用户和管理员分别验证菜单、路由与关键操作；直接打开无权 URL 仍受阻。
- 验证登录/退出/过期/锁屏/强退，以及未保存表单、多标签、偏好、消息重连。
- 验证大整数 ID、分页、UTC/IANA 时区、夏令时边界、双语言切换与刷新恢复。
- 构建及测试使用可控测试数据；不将测试失败恢复操作用于真实业务数据。

### 9.2 自动检查

- 依赖锁定、干净安装、TypeScript、生产构建、ESLint、i18n key/插值与原始文案检查全部通过。
- 迁移现有协议和纯逻辑测试；重写依赖 Element Plus DOM 的测试，以用户可见行为为断言。
- 为表格请求竞争、行内点击、权限树勾选、草稿保存、标签身份及消息连接生命周期设置有意义的回归用例。
- 关键端到端场景覆盖登录回跳、用户编辑、角色授权、字典主从、通知/待办、应用详情回跳。
- 生产依赖及源码中移除 Element Plus 和旧图标库；不靠旧库残留实现尚未迁移功能。

### 9.3 页面、视觉和性能

- 所有页面覆盖正常、加载、空数据和错误状态；交互复杂页面补充禁用、提交和长内容状态。
- 三类样板覆盖两种语言、明暗主题和主要宽度；全量路由至少完成桌面与窄屏巡检。
- 检查焦点、键盘、对比度、长英文、长标识、200% 缩放及弹层操作区可达性。
- Playwright 视觉基线使用可控数据和稳定时间，人工检查版式；不以无差异截图替代功能验收。
- R1 记录初始产物体积，R2 测量真实表格/树交互及最大分页场景，再设置可执行的体积与性能预算。
- 路由按需加载；富文本、复杂树及大型组件避免进入所有页面的初始包；轮询、监听器及对象 URL 无明显泄漏。
- 上传、下载、敏感操作和多账户流程若受测试工具或环境限制，标注待验收及所需步骤，不记为通过。

## 10. 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| shadcn 组合开发使业务组件工作量被低估 | R2 先验证表格、表单、树和实际接口，完成后更新剩余估算 |
| 示例与依赖主版本不一致 | 记录官方文档及组件来源；以完整安装、类型和构建检查为准冻结版本 |
| 主题改造只覆盖常见组件 | 建立开发态组件展示页，统一检查下拉、浮层、日期、编辑器及树 |
| 历史问题属于接口或数据，重建后仍出现 | 复核后建立独立问题单，区分呈现、交互、接口与数据来源 |
| 通用 CRUD 继续膨胀 | 复用稳定组件与逻辑；业务页面保持独立，复杂规则就近维护 |
| 新旧并行产生状态混淆 | 独立端口与明确版本标识；避免测试时同时运行两端消息流程；生产切换复核同源状态 |
| 覆盖当前用户修改 | 实施前记录变更，保留旧工程；复用代码前核对当时最新内容 |
| 首屏和长列表性能下降 | 路由拆包、按需组件、服务端分页；在测量后决定虚拟滚动 |

## 11. 切换与回退方案

1. 记录旧版本提交/工作区基线及可用构建产物，保证现有用户修改有可恢复副本。
2. 在独立环境验收新产物，核对 BASE_URL、代理、部署路径、SPA history 回退、/api 与 WebSocket 配置。
3. 检查持久化 key、令牌处理、偏好和标签格式；无法兼容的 UI 偏好进行有版本的迁移或安全回退，不批量清除用户存储。
4. 在独立实施步骤中切换静态产物或部署指向，核对产物版本和缓存刷新策略。
5. 复查登录、深链、权限、多语言、主题和消息连接；观察接口异常及页面错误。
6. 出现阻塞问题时恢复旧前端产物和原部署指向。默认无数据库迁移；若另有接口变更，须提前验证向后兼容。
7. 稳定后统一工程命名、开发脚本和 README/开发手册/部署文档，清理废弃构建入口。

## 12. 方案决策与后续第一步

已确认：采用 shadcn-vue + Tailwind CSS，接受前端完整重建。

本方案建议：Vue SPA、独立 frontend-next 工程、青绿色主色与中性表面、样板先行、模块迁移、最终统一切换。

开始实施后的第一项交付为 R0：现有路由/功能/接口对照表、设计变量、主框架及用户管理/角色授权/工作台设计稿。基于这些成果校准设计，再进入工程与页面开发。
