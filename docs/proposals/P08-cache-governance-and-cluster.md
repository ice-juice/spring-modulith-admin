## 1. 目标与已核实基线

用户要求：配置切换 Redis；统一治理基座基础数据及二开缓存；所有缓存在现有“缓存管理”菜单按场景、分组管理；负载均衡、多实例下登录、日常访问与实时消息正常工作。

2026-11-11 源码基线（未代表运行进程或双实例验收）：

| 对象 | 当前行为 | 缺口 |
| --- | --- | --- |
| ParameterService | 本地 ConcurrentHashMap；租户＋key；300 秒；提交后本地失效 | 无 Redis、无可靠跨节点失效；超过 10000 条粗粒度清空 |
| CacheRegion / Monitor | 仅参数接入；当前租户统计/清理，不返回值 | 无分类、配额、任务与节点确认 |
| 字典、偏好、IAM 展示数据 | 多数直接查询本模块数据库 | 需逐项界定缓存对象、隔离与失效 |
| 规则表达式、流程 | JVM 编译对象；容量限制；流程使用租约保护在途执行 | 应统一登记，不能迁到 Redis 序列化 |
| 登录会话 | Bearer 随机令牌，MySQL 存哈希；每请求校验会话、账号、权限、安全版本 | 已具互通基础，但需要 LB 双实例并发验收 |
| 验证码、TOTP、认证限流 | 数据库共享状态、原子消费/独立提交预算 | 不属于可清理缓存；验证跨节点竞争 |
| OpenAPI | 令牌和 nonce 在数据库；登录限流仍在内存 | 限流必须共享且原子 |
| WebSocket | 票据和连接在本节点内存；事件监听器只推本节点 | 跨节点握手失败、远端连接漏实时提醒 |
| 文件、密钥 | 本地上传目录；部署提供密钥环 | 多节点共享文件、一致密钥和轮换流程 |
| 定时工作 | 各进程调度；部分租户发现来自内存 | 需认领/幂等、可信租户枚举、部署协调 |

## 2. 总体决策

1. 可重建数据使用同一公开契约，后端为 local（Caffeine）、redis、none。默认 local；none 查询权威来源。
2. 首版不采用 L1＋L2，减少副本与一致性复杂度。
3. 所有跨请求应用缓存必须登记；统一治理不意味着统一远程存储或允许统一清空。
4. 本地编译对象/文件缓存由适配器治理；安全状态只展示受限指标和所属模块入口。
5. MySQL 继续作为会话、挑战、安全版本和业务数据权威来源；不为集群引入 JWT 或普通会话缓存。
6. 集群验收关闭粘性会话。Redis 缓存上线不是集群功能验收完成。
7. 静态二开先接公开契约；热插件需发布专门 SDK/宿主能力；独立应用需远程治理协议，不自动纳入已交付范围。

## 3. 缓存注册目录与契约

新增 common :: cache 命名接口；Common 不依赖业务模块。区域描述与加载器由所属模块贡献，Monitor 调用治理契约。

每个区域注册：稳定 ID、双语 nameKey、说明、owner/module/businessId、group、scenario、kind、scope、schemaVersion、存储能力、TTL/负 TTL、抖动、最大条目/字节预算、单条大小、数据敏感性、允许操作、失效来源、依赖区域和预热能力。

- kind：DATA（可重建）、RUNTIME（本地运行时）、RESOURCE（文件/资源）、PROTECTED（受保护状态）。
- scope：TENANT、TENANT_PORTAL、TENANT_USER、TENANT_PORTAL_USER、NODE、PLATFORM。具体区域只能使用声明的维度。
- group 用于管理组织，不授予权限、不改变键；scenario 说明业务用途。
- 注册冲突、未知区域、不合法策略、禁止的隔离降级，启动失败。
- 每个公开 Region ID 与调用方声明一致；二开不能注册 config/iam 等基座命名空间。
- 缓存按不可变 DTO/序列化快照存取，不共享可被调用方修改的对象引用。
- 代码声明安全上限；部署配置和租户覆盖只能在允许范围内调整。
- 保留旧 CacheRegion 与 HTTP 形状，通过适配器兼容；旧 clearAll 不扩张到受保护/平台级对象。

## 4. 基座区域治理清单

| 区域/对象 | 存储与隔离 | 失效及保护 |
| --- | --- | --- |
| config.parameters | 可切换；租户＋参数 key | 保存、删除、恢复默认、初始化；安全决策参数逐项绕过普通陈旧缓存 |
| config.dictionary-options | 可切换；租户＋字典类型＋语言 | 类型/条目/翻译/启用状态变化；树完整性 |
| config.preferences | 可切换；租户＋用户；只缓存原始偏好 | 保存和 reset；默认配置读取时合成，不能固化调用者 fallback |
| IAM 部门/岗位展示 | 可切换；租户＋明确查询条件 | 所有写入口；数据范围必须继续过滤 |
| IAM 菜单/导航元数据 | 可切换；租户＋portal＋语言 | 结构/翻译变化；最终授权每请求实时计算 |
| IAM 用户展示 DTO | 可切换、按需；租户＋用户标识 | 禁缓存完整账号、凭据、安全版本用于放行 |
| 规则编译/流程计划 | 固定 JVM、租户＋内容/版本 | 保留容量和在途租约；只清空闲计划 |
| IP 数据库/框架元数据 | 节点级资源 | 显示版本/占用；不强制清空 |
| 插件制品文件缓存 | 节点级文件资源 | 活跃/回退引用保护、内容校验，委托所属模块 |
| SQL 统计 | 本地运行状态 | 重置统计与清数据分开；标明节点/时间窗口 |
| 会话/验证码/TOTP/限流/nonce/票据 | PROTECTED | 禁普通清理、预热、缓存模式降级 |

建议默认 TTL：参数/字典/原始偏好 300s；组织/导航展示 60～300s；负缓存 15s。最终按区域语义与压测验证。不存在值与调用者 fallback 分离。异常结果不缓存。

## 5. 配置与切换

拟定部署配置命名空间 `sma.cache`：provider=local|redis|none、namespace、deployment-mode=single|multi、默认 TTL、negative-ttl、ttl-jitter、max-entry-bytes、总容量，以及 regions 下的允许覆盖。Redis 连接复用 Spring Boot 的 spring.data.redis（ACL、TLS、standalone/Sentinel/Cluster）。依赖锁定当前 Boot BOM 兼容版本。

- provider、地址、拓扑、命名空间、协议版本属于重启生效配置，不在网页在线换集群。
- 管理页允许 TTL、配额、停用/恢复等已声明策略；数据库保存版本和审计，广播生效。
- 有效值＝区域声明 → 部署覆盖 → 允许的租户覆盖；禁止超出代码安全边界。
- 切换：预检 → 新命名空间代次冷启动 → 限速预热 → 观察 → 记录结果。
- 滚动混合模式期间所有存储都接收可靠失效；未验证组合使用受控切换窗口。
- 回退仍启用新代次，避免恢复旧配置时读到遗留缓存；禁止用 FLUSHDB 回退。

## 6. 可靠失效与一致性

业务写事务调用公开失效登记 API，在同一 MySQL 事务登记区域、可信范围、失效原因；不保存缓存值。回滚同时撤销登记。提交后快速执行，后台按持久记录重试和补偿。模块自己的持久数据只能由所属模块访问。

实现细化：以 `common_cache_revision` 保存每租户/区域的最新提交版本，作为可合并的持久失效记录。版本行更新与业务同事务，按行锁串行递增；各节点独立核对自身使用过的区域，无竞争消费或基于未提交事件 ID 的高水位跳跃。连续多次变更可合并到最新版本，不必逐条删除同一缓存。冷节点首次读取先检查权威版本；已使用区域后台每秒补偿，前台超过一秒未校验时也重新核对；校验失败绕过缓存。区域外没有本地副本的节点无需确认旧事件，首次读取仍须权威核对。区域/操作审计及节点确认任务由 S4 增补，版本表不存业务载荷。缓存读取中的版本核对使用独立 READ_COMMITTED 事务，不能读取业务旧快照；业务写事务只登记版本，不依赖 Redis 成功才能提交。

跨数据源边界（[P11 跨专项资源归属](P11-cross-stream-resource-ownership.md)，约束本方案 M3 与 S6）：上述“与业务同事务”成立的前提是业务 Mapper 与 `common_cache_revision` 位于同一数据源。租户平台接入业务分库后，写入独立业务库的模块必须把失效登记放在该业务库内，平台侧汇聚为异步且有界陈旧，不得宣称与业务提交强一致。会话、票据、验证码、限流、nonce 等 PROTECTED 状态永不随业务资源迁移。

- 首选区域＋已声明业务范围（如字典类型），避免所有变更都清整租户。
- 加载前捕获失效代次，回填原子比对；已变更则拒绝旧结果。Redis 脚本涉及的键必须同槽。
- 代次不循环复用；治理元数据缺失生成新代次，不允许旧键复活。
- 有事务快照/写后读要求的读取绕过缓存；旧事务或未提交内容不能回填共享缓存。接口需要明确读取上下文，不能简单把所有 @Transactional(readOnly=true) 等同于安全回填。
- 普通数据仅承诺有界陈旧；正常目标 1s，超过 5s 告警，有限绝对 TTL 兜底。不宣称 MySQL 与 Redis 强一致。
- TTL 抖动不得延长声明的最大陈旧边界，命中不续期。
- 本地缓存失效由每个节点独立消费；消费组竞争处理不能代替广播。
- 节点掉线/游标过期恢复时先清理对应本地数据；同一失效重复或乱序不倒退代次。
- Pub/Sub 只加速，持久记录补偿。共享后端失效与本地节点确认分别记录。
- 强一致、安全授权和资金决策始终查询权威状态。

## 7. 键、序列化、容量和故障

键逻辑包含环境 namespace、缓存协议、区域、可信租户/portal/用户范围、schemaVersion、失效代次、业务键规范化摘要。低熵敏感标识禁止进入 key 或使用带密钥摘要。Cluster 同槽设计不能把整个应用绑一个槽；热点区域需预算和测试。

采用显式 DTO、带版本 JSON 封装；禁止 Java 原生序列化、任意多态类型、Mapper 实体、Token/密码/密钥/完整请求和文件正文。损坏或不兼容条目视为 miss 并计数，不影响数据库业务数据。

Redis 存储实现采用协议 v2：每租户/区域一个有限大小 Hash，把版本、随机代次、容量计数和数据条目放在同一个可原子操作/淘汰的 Redis key。条目含绝对到期时刻，命中不续期；作用域 key 使用空闲 TTL 回收。这样 Redis 淘汰不会只丢配额索引而留下无法计量的有效数据；清理仅 UNLINK 对应租户/区域并创建新代次，不扫描 Redis。Hash 内的字段仍包含 schema、portal、用户和业务键摘要。区域容量预算按声明限定；相同区域不同租户仍独立隔离。监控不返回字段值，只返回计数。S2b 的 v1 原语作为历史验证，v2 与旧数据分命名空间共存，旧条目自然过期。

- Local 有全局与区域预算；Redis 有实例 maxmemory、区域/租户写入配额、单条大小限制。
- 配额满时按约定淘汰或跳过缓存写入；业务查询结果不因缓存写失败丢失。
- 绝对 TTL＋负缓存＋同键加载合并＋限速预热控制雪崩、穿透和回源。
- 超时、熔断、回源并发预算保护数据库；不得无限排队或缓存异常。
- 禁 KEYS、FLUSHDB、FLUSHALL；代次逻辑失效，后台限速回收/TTL 释放物理空间。
- 建议独立可丢弃缓存 Redis，最小 ACL、TLS；allkeys-lfu 只在不混放安全状态/工作账本时适用。
- Redis 不可用默认 bypass 回源，不暗中切 Local。启动配置错误明确失败；运行时允许回源由部署策略声明，健康状态可见。
- Redis 恢复/主从切换/旧快照回灌后，处理积压或新代次冷启动再逐步恢复；防止旧版本数据重现。

## 8. 缓存管理产品与操作契约

保留现有菜单和路由，新增四个页签：缓存目录、运行概览、操作任务、治理策略。

目录按归属、分组、场景、类型、后端、状态、节点筛选；显示名称、模块、隔离、TTL、条目、占用、命中率、实际后端和可用操作。详情展示有效配置来源、依赖、失效来源及限制，不暴露值。

操作：区域/业务范围/分组/选中项清理；当前租户全部可清理缓存；暂停/恢复；有注册加载器的限速预热；独立重置统计。禁止任意 Redis 命令、模糊 key 删除、网页填 SQL/脚本/类名。

- 提交前展示准确目标、租户/节点范围、跳过原因；服务端重新校验并固定目标快照。
- 批量任务有 ID、幂等请求键、进度和审计；超时先查询任务，不重复非幂等提交。
- 状态区分：已受理、逻辑失效、节点确认/回收中、完成、部分失败。离线节点不伪装成功。
- 暂停同时禁读写并失效；恢复使用当前代次；策略改变不能延长旧条目的最大陈旧边界。
- Redis 共享条目不按节点重复求和；本地逐节点显示。标明采样/估算/窗口及离线节点。
- 指标覆盖 hit/miss/bypass、回源/Redis 延迟、错误/熔断、写入拒绝、失效积压与最老延迟。监控时间序列只使用受控区域/节点/后端标签，不把原始 key、用户 ID 或秘密值变成高基数标签；租户详情走鉴权后的有界管理查询。
- 预热通过专用分页加载器，限速、可取消，不能绕过业务权限或扩大数据范围。

权限：保留 monitor:cache:view/clear；预热、暂停恢复、策略编辑、统计重置分离。默认当前租户；平台范围须专门运维授权。业务区域默认同时要求缓存操作权与区域声明的业务管理权。group 不授予权。审计包含原因、范围、前后策略和结果，不记录值/秘密连接。

## 9. 二开约束与自动门禁

适用于跨请求应用缓存；临时集合、请求内 memoization 不强制注册。

1. 未登记区域不可使用；区域归属、TTL、配额、隔离、格式和失效必填。
2. 仅依赖 common :: cache；禁止直接 Redis/Caffeine/自建长期 Map/未治理缓存注解。特殊运行时缓存须适配器＋例外登记＋测试。
3. 只缓存本模块拥有数据或公开契约 DTO，不跨表、不访问 internal。
4. 缓存不代替鉴权；对象范围/portal/租户/用户从可信上下文校验，不能由任意请求值授权。
5. 全写入口登记失效：新增、更新、删除、恢复、导入、后台同步、翻译、初始化。
6. 不自建一次性通知作为唯一失效机制；使用事务登记 API。
7. 衍生缓存通过公开事件声明依赖，不扫描别人的表或 key。
8. 不兼容 DTO 按 schemaVersion 隔离；验证新旧程序共存和回退。
9. 只用注册的安全预热加载器，禁止脚本/SQL执行入口。
10. 库存扣减、幂等、支付状态、安全预算不是可丢弃缓存。

提供隔离业务测试夹具和契约测试：扫描发现、命名冲突、跨租户/用户/portal、失效遗漏、禁止依赖、双版本 DTO、故障回源与配额。实际客户业务仍在业务分支，不进入 main。

## 10. 多实例访问连续性（正式验收范围）

### 10.1 会话和认证

随机 Bearer 的哈希、会话与账号安全状态继续在共享 MySQL。实例无 Servlet HttpSession 依赖。A 登录后 B 可解析同一 token；A 重启不因本地状态丢失而要求重新登录。

安全查询走权威库，不能因读副本延迟或缓存陈旧放行。共享一致密钥环、可信租户入口、时间同步和兼容配置。验证码/挑战一次消费，猜测预算共享且不能回滚退还。验证单终端并发、锁屏/解锁与 lastSeen 更新竞争、退出/强退/改密/角色撤销。撤销提交后的新鉴权拒绝；已通过鉴权的在途业务请求不自动回滚，敏感写前仍需必要重验。

### 10.2 WebSocket

一次性票据改为共享 MySQL 原子消费，保留短 TTL、哈希、会话绑定和所有拒绝路径。它是受保护状态，不受 cache.provider 或清理操作影响。

连接仍在所属节点，不能序列化到 Redis 或在故障后原样迁移。业务消息/必要事件可靠落库，跨节点广播最小对象 ID/范围，各节点验证自己的连接再推送。Pub/Sub 可加速但不能独自保证送达：重连补查＋在线周期对账或持久游标恢复未读状态；前端 REST 获取真实内容。撤销广播加快远端关闭，保留每次推送前与心跳权威校验。

### 10.3 其他集群依赖

- OpenAPI 登录限流改为共享原子状态，不能因节点数增加而放宽预算。
- OpenAPI凭据引导尚不知道租户，预算属于平台安全元数据，不能伪造默认租户。拟按来源及来源＋AppId分别预占固定窗口预算，失败/成功均不退还；只保存带密钥摘要、有限计数与到期时间。摘要密钥独立生成、由已有部署主密钥加密持久保存，所有节点使用同一安全状态；有限容量和有界过期清理，禁止普通缓存治理删除。具体阈值和迁移证据在M1b实施时固化。
- 文件通过存储公开接口支持已验证的共享文件目录/对象存储；本地隔离目录在 multi 模式拒绝伪装可用。[共享文件见证](P08-shared-file-witness.md)细化既有根目录/别名声明、跨进程实际读写和验证边界，不能把未完成的云适配器当作已交付。
- 密钥环一致部署，兼容轮换；生产不能各自自动生成 OpenAPI 主密钥。
- 定时工作基于 DB 认领/租约/幂等，可信租户枚举不只依赖本节点历史请求；失效和消息广播不能被单消费者抢走。
- 迁移受控发布，新旧应用共存 schema；插件/规则版本与节点就绪能力核对。
- 多实例 ID 生成须保证节点标识唯一，不能仅依赖进程/机器哈希“通常不碰撞”；部署预检及双节点并发写入验收覆盖主键分配、节点重启与时钟回拨行为。
- LB 转发 Authorization、WebSocket Upgrade；超时匹配心跳；仅信任已知代理传来的客户端 IP。
- readiness/liveness 分离；优雅摘流/停机；不能盲目重试可能已执行的写请求，业务幂等由明确契约保证。
- 应用多节点不消除 MySQL/Redis/文件存储单点，部署说明明确各依赖 HA 范围。

### 10.4 故障体验

| 故障 | 目标 |
| --- | --- |
| A 宕机 | 新请求到 B，登录保留；在途请求可能失败，不虚构零丢失；WS 重新取票重连 |
| Redis 缓存失败 | 限量回源，登录不因清空缓存丢失 |
| 广播暂时失败 | REST 可用，提醒可能延迟，补查恢复 |
| 会话数据库不可用 | 明确服务不可用，不用旧缓存放行 |
| 滚动升级 | 摘流、兼容 schema/配置/序列化、恢复连接，无需重新登录 |

## 11. 路径、兼容和验证

拟改路径已由本次授权确认：common/cache、common/internal/cache（持久类放 common/internal/persistence）、monitor、config、IAM 展示适配、rule 等注册适配；auth/message/openapi/file 的集群缺口；追加所属模块 Flyway；frontend-next/features/monitor 与兼容旧前端；部署工具、文档及规则。

不改历史迁移/已发布制品；API/SPI/HTTP 保留适配窗口，不把 SNAPSHOT 当正式兼容承诺。升级矩阵：旧 Local 基线、新 Local、新 Redis、新 None、混合滚动、回退新代次。热插件与独立服务能力不通过反射或内部 Bean 绕过。

验收必须包括：

1. 同代码三种 provider、结果一致、fallback/负缓存与异常语义、序列化版本、配额与租户隔离。
2. 回滚、旧请求回填、清理/回填竞争、重复乱序失效、节点断线恢复。
3. 真 Redis 的 standalone/Sentinel/Cluster 各自证据、超时/重启/故障恢复；Mock 不代表真实拓扑通过。
4. 基础数据全部写入口，实时权限/安全校验不被缓存替代。
5. 真实 LB＋双后端、关闭粘性：跨节点验证码/TOTP/登录/token/退出/强退/锁屏/权限撤销、单次消费并发。
6. A 票据 B 建连、A 事件 B 推送、广播断线补查、A 停机重连、A 上传 B 下载。
7. 管理 UI 双语/明暗/窄屏/键盘、权限拒绝、任务部分失败和旧前端协议。
8. 二开隔离夹具、架构门禁、真实构建产物兼容；根 reactor 标准验证。

所有破坏性验证只在专用可清空 MySQL/Redis、隔离端口和输出目录。当前开发库、运行服务及用户会话不用于故障演练。分阶段顺序和实际命令见实施进度。

## 12. S4任务协议细化

以下为S4c实施约束，是否已经交付仍以专项进度为准。

### 12.1 预览与提交

预览接受区域ID集合与owner/group/scenario交集筛选，不接受tenantId、用户ID、Redis键、脚本或任意节点地址。空筛选代表当前租户全部登记区域，必须展示完整结果后提交。服务端按稳定ID排序，保存操作、原因、发起人/portal、有效期、目标描述摘要、策略版本及跳过原因。未知、受保护、无能力、无管理权限的条目逐项说明，不悄悄扩大目标；没有获准目标时不能提交。上限128个目标；用户私有区域也必须明确说明治理影响覆盖当前租户哪些用户，不能把单个用户的数据键当管理边界。

预览ID是随机公开ID而非权限凭证。任务查询始终验证租户、发起人/portal和查看权；提交、取消还须对应操作权与区域管理权。已撤销操作权的发起者仍可用查看权查阅自己任务的拒绝结果。默认列表只展示当前发起者/portal自己的任务；后续若增加全租户任务查看，须独立权限与对象过滤，不随monitor:cache:view自动开放所有审计信息。

提交携带原预览ID与至少128位随机性的请求键；在既有RequestExecution的本地事务内，将预览转为QUEUED并固化逐项状态。预览只能提交一次。重复同键同载荷返回原任务；异载荷409。响应不明先按原键查询请求回执、按预览ID查询任务。回执UNKNOWN/RUNNING不自动重发新键。预览到期、注册元数据或策略版本变化，首次提交拒绝并要求重新预览；已成功提交的重放不因预览到期而创建新任务。业务数据revision变化不影响预览准确性，清理提交仍推进最新数据代次。

任务与每项明细、操作结果属于持久工作账本，不能由普通缓存清理、provider=none或Redis故障删除。预览有短有效期、创建频率和持久容量上限；过期未提交预览可由有界清理退役。已受理任务及幂等回执按照专用保留策略处理，不能为腾容量让旧请求键获得二次执行权。

### 12.2 认领、权限与取消

后台通过TenantWorkQuery分页发现可信租户，按持久任务恢复工作身份。每次执行项前重新检查租户状态、账号启用状态、portal、最新角色权限和数据范围；不存储可直接恢复授权的旧SmaPrincipal。队列中已撤权或停用的操作者产生拒绝明细。已经受理的任务可独立于原浏览器连接继续运行，但不会绕过停用或最新权限；需要取消时走任务取消接口。

领取采用短数据库事务、有限候选、租约和单调fence；没有租约不得执行，旧fence不能覆盖新worker结果。清理/控制类操作的权威变更与该项结果在同一个数据库事务提交，缓存网络通知仅在提交后执行，失败由持久版本核对补偿。数据库结果不明先读账本，不能把不确定提交当作可重试未执行。逐项提交支持部分成功，不把整批HTTP200表示为全部完成。

取消是幂等状态变更。尚未执行项转CANCELLED；已提交项保留结果，不反向恢复旧缓存或策略。在途预热只在批次边界停止，页面显示取消请求与实际停止的区别。失败重试使用原任务/项的围栏及恢复协议，不能以复制任务绕过版本或授权检查。

### 12.3 预热与节点观察

预热仅允许所属模块注册的分页加载器，执行正常公开查询和当前授权检查；固定总条数、每页条数、速率、最长运行时间、并发及取消检查。不存在加载器、None后端、暂停区域及用户私有区域不提供伪能力。加载器不能执行写业务、SQL/脚本解释或远程任意地址。重复读取可安全重试，但本批次失效/策略变化后，旧加载不得回填。Local预热必须标明实际执行节点，不能宣称所有实例已变热。

逻辑完成的依据是权威版本提交。节点确认另外报告每个已知相关节点的进程生命周期、最近心跳、已观察版本和确认时间；离线、未确认、登记发生变化分别显示。预览/任务捕获的节点集合不能冒充未来加入的全部节点；新进程冷启动仍必须先核对权威版本。逻辑失效、共享Redis代次更新、本地观察确认、物理空间回收是不同状态，TTL或异步UNLINK未结束时不填“空间已释放”。
