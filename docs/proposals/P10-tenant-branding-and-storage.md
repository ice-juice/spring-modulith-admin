# P10 租户品牌、登录模板、配置分层与业务存储

状态：2026-11-11 用户确认以上研究方案并授权开始实施；新增要求为删除旧 `/api/config/parameters/public`，SQL 执行统计按实际配置的数据源区分。本文是实施设计，不表示全部能力已交付。逐项证据见[实施进度](../tenant-platform-progress.md)。

## 1. 目标与范围

在同一个 Spring Boot / Spring Modulith 宿主内提供租户中心。租户独立配置系统名称、Logo、Favicon、版权、备案、域名和 login1/login2/login3 登录风格。平台集中管理身份、资源与运维；二开模块使用公开契约访问按租户绑定的业务 MySQL 和 Redis。基础字典和参数区分平台共享与租户独有。SQL 统计归属实际执行的数据源，并保留租户权限边界。

本任务属于基座维护，main 只增加可复用能力与隔离测试夹具，不增加真实客户业务。现有 P07 认证、P08 缓存、P09 应用身份/文件能力继续生效；保留已有工作区修改，不重启当前业务服务，不使用开发库清库验证。

### 已确认决策

- 保持模块化单体；分库不自动拆微服务。
- 平台库固定；业务库按可信租户＋业务存储组路由。共享库、同实例独立 database、独立实例使用同一套业务代码。
- 默认 Redis 共享实例＋租户命名空间；支持显式绑定专用资源。Redis DB 编号不作为强隔离边界，Cluster 使用 DB 0。
- 品牌保存草稿、发布、回退分开；登录模板使用编译内置的注册表，租户不能上传代码。
- 删除旧公共参数 HTTP 接口，不保留兼容代理。两套在用前端及测试、示例同步切换，采用同批前后端发布。
- SQL 统计使用稳定资源 ID＋资源修订标识，不能按 JDBC URL、线程当前租户选择或客户端传参猜测实际连接。
- 全部功能按本计划交付；阶段完成不能代替整体完成。

## 2. 当前依据与差距

- `config` 的参数和字典实体均继承 TenantEntity；builtin 仅表示内置，不表示平台共享。现有初始化会按当前租户复制种子。
- `frontend-next/src/stores/branding.ts` 读取通用 public 参数；登录页布局固定。需要类型化、白名单的已发布品牌 DTO。
- `common/internal/PersistenceConfiguration` 同时扫描平台与业务 Mapper，目前共用数据源。需拆分持久化装配而不是全局替换 DataSource。
- `CurrentUser` 与 TenantScope 仍有默认租户兼容行为；P09 ActorContext 已拒绝匿名默认身份。租户入口必须明确区分匿名访问范围和认证身份，不能把域名当成授权。
- P08 S2 已有 Redis 装配和持久失效；多实例、Sentinel/Cluster 完整验收另见 P08。分库必须重新绑定失效记录的事务资源。
- SqlTelemetry 拦截 MyBatis StatementHandler，按租户和 Mapper 聚合，统计为本进程生命周期，不是全库审计；不采集 SQL 正文/参数。游标不完整计行，批处理、直连 JDBC 等覆盖需在界面明确。

## 4. 租户与域名入口

租户状态：PROVISIONING、ACTIVE、SUSPENDED、MAINTENANCE、RETIRED。开通初始化由各模块公开契约执行，幂等、可续跑；暂停拒绝新业务请求并撤销/失效旧身份，恢复不能自动复活旧会话。

域名规范化为小写 ASCII/IDNA，无协议、路径、用户信息、通配符。校验端口、尾点、长度和有效标签；有效绑定全局唯一。同租户可多域名，每入口一个主域名。控制权、DNS、TLS 状态分别记录；绑定保存不表示 DNS 或证书已生效。

域名来源默认使用服务器收到的 Host；仅在显式可信代理与入口转发协议下使用 forwarded host。忽略任意客户端 X-Tenant-ID，不从请求正文授予租户身份。未知域名、停用域名拒绝，不隐式回退租户 1。旧单租户本地部署通过明确登记的 localhost/127.0.0.1 开发入口接入，不让生产允许任意 Host。

匿名入口上下文只有 tenantId、portal、domainId、入口修订，无用户权限。登录、captcha、MFA 挑战、session resolve、WS 票据都检查相同入口范围；认证后身份租户必须匹配。平台运维入口独立且有显式运维身份授权，不把租户 superAdmin 当平台权限。P09 机器/应用身份按各自安全链解析，不放宽后台人类权限。

同域 `/api` 代理为默认部署；跨域 SSO 不属于首版。多入口前端状态按租户和身份隔离，切换入口取消在途请求，清空旧品牌与草稿，防止迟到响应覆盖。

与并行安全防御的 BrowserRequestFilter 协调：Origin 同源检查与入口 Host 使用一致的受信代理边界；优先代理保留原始 Host。不能只让入口识别转发域名，而同源检查仍用内部服务域名；也不能为通过检查将所有租户域名设置为任意跨源许可。跨租户 Origin/Host/令牌组合纳入 S2d 拒绝矩阵。

## 5. 品牌与登录模板

字段：systemName/shortName/英文与中英文欢迎文案、logoLight/logoDark/compactLogo/favicon、登录背景、主色与皮肤策略、copyrightOwner/startYear/url、ICP备案号/url、公安备案号/url、官网/客服/帮助/隐私/协议链接。

继承、覆盖、明确隐藏为独立状态。法律主体字段不可盲目继承平台版权/备案。域名可覆盖备案信息；品牌默认按租户，可在有明确 portal 的入口覆写。名称与 tenant code 分开，改名不改主键/资源路由。

素材引用 file ID，发布时验证归属、扫描状态、格式、大小、像素；首版 PNG/WebP/ICO 采用受支持的安全解析/转换。不开放普通附件匿名下载，不执行 SVG 脚本。链接限制 http(s) 和允许用途，不允许任意 CSS/HTML/JS。

模板注册：login1（左右分栏）、login2（居中卡片）、login3（背景图）。模板 ID/版本/能力/启用状态由平台提供。统一 AuthForm 和认证状态机，复用验证码、MFA、错误处理、安全重定向、双语和键盘操作。模板按需加载，不加载所有大图；未知/停用模板回退可用 login1 并提示管理员。MFA 页与登录首屏共享品牌外壳，但无重复认证实现。

租户管理界面展示缩略图、桌面/移动/明暗预览、必填校验、保存草稿、发布和回退。草稿权限和发布权限分开。发布版本不可改写；回退生成新的发布记录。匿名仅白名单 DTO，带品牌修订，缓存包含 tenant/domain/locale；CDN Host 隔离。安全策略如 captchaEnabled 从认证策略单独取得，不允许品牌模板决定是否验证。

新入口契约：`GET /api/tenant/entry` 返回入口、已发布品牌、模板和允许公开的登录能力。管理 API 使用 `/api/tenant/tenants`、`/domains`、`/brands`、`/resources`、`/operations` 等复数资源。最终类型以代码与 API 手册为准。

S3/S4字段与目标接口详见[品牌契约](../tenant-branding-api.md)，其中未验收路由不能描述为已交付。

删除 `/api/config/parameters/public` 的 Controller 映射、Security 白名单及消费者；匿名不能通过新入口枚举任意 publicReadable 参数。旧品牌参数一次迁移到品牌 revision，之后唯一写入口为品牌服务，防止两份真相。旧安全/业务参数继续按自身契约管理。

## 6. 配置与字典分层

不能用统一“用户覆盖一切”顺序。每个定义声明 owner/key/type/scope/default/overridePolicy/validation/publicProjection/effectiveTiming。部署配置只用于运行时；平台定义有安全上限；租户仅覆盖允许项；用户偏好只影响已声明的外观/语言字段。安全策略由服务端强制，缓存陈旧不能放行。

平台共享定义与值使用独立平台表和运维 API，不借 tenant_id=0 绕过现有租户拦截。租户独有、租户覆盖继续保留 TenantEntity 与租户索引。平台值修改不会覆盖租户的显式值；删除覆盖恢复继承。JSON 参数整体替换，禁止隐式深合并；缺失、空字符串、null 的语义逐类型规定。

字典模式：PLATFORM_LOCKED（共享且不可改代码）、EXTENDABLE（共享项＋租户显示/排序/可隐藏覆盖＋租户新增项）、TENANT_ONLY。稳定 item code 不改，停用不能破坏历史数据展示；引用/提交校验与显示旧值分开。树节点不能越类型或跨租户引用；租户不能重定义平台代码含义，平台删除采用停用/版本升级。

定义与项、翻译、发布 revision 分离；有效读取合并平台发布版本与租户 revision，不给每个租户复制全部默认种子。现有租户值先保留为显式覆盖，逐条迁移；不以 reset 清除客户修改。跨模块读走 ParameterQuery/DictionaryQuery 的明确扩展契约。

缓存键覆盖平台修订＋租户修订＋语言。平台共享 DATA 缓存需要新增受审契约，不能绕过现有 CacheDescriptor 对 PLATFORM 的限制。失效应批量/分代传播，避免 N 租户全量重建。

## 7. 业务 MySQL 路由

平台账号/权限/会话/配置/品牌/文件元数据继续在平台库；因此“业务独立库”不代表全部租户数据物理隔离。要求身份/文件/日志全隔离的客户需另选完整部署隔离等级，不伪称当前模式满足。

资源绑定：tenantId＋businessModule/storageGroup → resourceId＋revision＋schemaCompatibility。资源记录地址、库名、TLS/池预算/超时/secretRef，接口脱敏，不保存密码到普通参数或 VITE。运维连接测试使用受控网络 allowlist 和连接预算，防 SSRF；禁止任意 JDBC 参数拼接。

平台固定 DataSource/SqlSessionFactory/事务管理器；业务独立 RoutingDataSource/SqlSessionFactory/事务管理器，平台 Mapper 和业务 Mapper 不交叉扫描。业务模块声明存储组，使用公开事务/路由契约，禁止自己 new 数据源、SELECT USE 切库或动态插入库名。相同业务代码可由不同租户绑定共享/独立资源。

事务前固定路由修订，事务期间拒绝切租户/组/资源；嵌套调用和自调用不能绕过检查。Spring TransactionSynchronization、连接和租约共同管理在途生命周期。后台恢复可信租户＋已持久工作项，不继承请求线程 ThreadLocal。

仍保留 tenant_id、DataScoped、block attack、分页上限、审计填充。查不到绑定、资源不可用、schema 不兼容则明确失败，绝不写默认库。

连接池按物理资源＋凭据修订共享而非按每个逻辑租户复制；懒加载、有限活动池、minIdle 受控、空闲回收、节点总预算、物理服务器总预算。旧修订排空在途后释放；不能关闭正在使用的连接。低层 API 不泄漏密码或物理 URL。

### 跨库一致性及迁移

一个本地事务只覆盖一个数据库资源。跨平台库/业务库联动使用业务库同事务 Outbox、稳定幂等键、重试/补偿。业务缓存失效和模块事件不能误写进平台事务后宣称原子。每个业务库的框架 Outbox/失效表由宿主存储运行时管理，业务不可访问其他模块 Mapper。

账本归属（[P11 跨专项资源归属](P11-cross-stream-resource-ownership.md)，S6 开工前必须先对齐）：要求与业务写同事务的账本随业务资源走。写入独立业务库的模块，其幂等执行权（`common_request_execution`/`common_request_mutex` 等价结构）、互斥记录与缓存失效登记必须落在同一个业务库；平台库只保留目录、跨库对账与运维视图，不得先提交平台账本再声称与业务写入原子。`common_id_block` 按块预分配，块内不需要跨库协调，继续留在平台库；各模块预算表本就独立提交，不随业务回滚，位置不变。

每个物理库持有独立 Flyway 历史，按模块与框架迁移登记执行。共享物理库只迁移一次；独立库仅执行声明归属的迁移，不把全部平台表复制过去。迁移锁、校验和、兼容版本、失败恢复、限量并发和状态均可审计。

换库为持久任务：预检→备份→建结构→复制/核对→停写并排空→最终同步→切换绑定修订→验证恢复。首版维护窗口；未完成状态不能直接激活。目标接受新写后回退必须处理新增数据，不能只改连接。备份恢复/退租保留期限和物理删除独立授权。

## 8. Redis 多资源

平台安全状态/协调与可重建业务缓存分开。业务区域由 CacheCatalog 声明存储归属，ManagedCache 根据可信租户绑定；平台缓存不会因为业务切 Redis 而迁移。共享实例复用客户端；独立资源才新增客户端/连接，统一有界网络线程、超时、TLS、ACL 和连接预算。DB 号属于连接固定配置，不在共享连接上执行逐请求 SELECT。

连接归属（[P11 跨专项资源归属](P11-cross-stream-resource-ownership.md)，S8 开工前必须先对齐）：部署级 Redis 仍由 P08 的受控连接工厂拥有，provider、地址、拓扑、协议版本与命名空间保持重启生效，不在网页在线换集群。本节的资源登记只决定“某租户的可重建业务缓存绑定到哪个已登记物理资源”，并提供客户端与连接池预算；不改变 P08 的区域语义、键布局、失效协议与配额实现。租户级改绑只对新解析生效，须走冷启动或限速预热，不对在途请求热切换。

切换可重建缓存可冷启动或限量预热；锁/票据/幂等等 PROTECTED 状态不能当缓存清掉或降级本地。缓存协议含环境、资源修订、区域、租户、格式和失效代次；Cluster 原子操作按区域/范围同槽，不能全应用一个槽。禁止任意 key/命令及 FLUSHDB/FLUSHALL。

故障只限速回源可重建数据，按资源＋租户隔离熔断/并发配额，避免一个故障租户耗尽宿主。P08 版本观察从 N 租户×区域×节点逐项轮询评估为活跃范围批量/增量补偿；可靠性不能退化为仅 Pub/Sub。

## 9. 按实际数据源统计 SQL

### 归属与展示

资源注册生成非敏感稳定 resourceId、展示名、revision；每次从具体物理 DataSource 借出连接时固定该身份，Statement 继续保留所属 Connection。SqlTelemetry 从实际 Statement 连接读取身份，不能使用请求期路由目标替代执行连接，不能按 Mapper 包猜业务库。平台 DataSource 同样登记；未标记连接单列 unknown，不冒充平台。

聚合键为 tenantId＋resourceId＋revision＋mapperId＋command。同一 Mapper 在两个库分别计数；旧在途连接保留旧修订，切库不把历史统计挪到新库。共享物理库在资源层同一 ID，查询仍强制当前租户，租户无权看到其他租户流量。平台跨租户统计另需平台运维授权。

SQL 页提供数据源选择、资源状态/修订、关键字、排序、分页、调用/错误/慢调用/平均/最大耗时/结果行、最后执行时间；无样本的已授权资源也出现在目录。定向重置必须验证资源权限并固定目标，不能 UI 选一个而服务端清全部。重置与在途调用采用代次/快照语义，明确重置前启动的调用不进入新窗口。

当前为本节点、进程内、有限容量统计；页面标明观察窗口/节点，不把多节点随机返回值称为全局总量。完整多实例聚合与 P08 集群门禁配套。容量控制包含总数、租户/资源公平性、过期与丢样计数，不能一租户占满导致其他租户完全失明。

不采集 SQL 正文、参数、密码、完整 JDBC URL。统计异常不得破坏原业务执行。慢阈值使用部署设置；不要为统计主动再借连接或查 metadata。MyBatis 缓存命中不计 JDBC 执行；游标行数未知、batch/直连 JDBC/Flyway 未覆盖时明确标记边界，不能将这些值解释为全库 SQL 总量。

### 验收

相同 Mapper 在两个真实 MySQL 库调用分别计数；租户 A/B 与 resource A/B 组合隔离；连接绑定后路由修改仍计实际旧资源；失败执行计一次、事务回滚不抹除执行事实；未知源、关闭/退役源、并发重置、容量、平台查询授权、敏感信息泄漏都覆盖。前端切换筛选丢弃迟到响应、重置目标固定。

## 11. 权限、性能与部署门禁

租户内品牌 view/edit/publish/rollback、域名申请、状态查看与平台资源管理/激活/迁移分权。平台权限不能由租户内超级管理员自行授予；审计不含 secrets。所有 Long ID 字符串传输。

性能比较同硬件/数据/请求混合下的单库基线、共享多租户、独立库、多 Redis、故障回源。记录 p50/p95/p99、吞吐、错误率、借连接等待、活动连接、JVM heap/线程、Redis 连接、缓存命中/版本查询 QPS、Outbox 最老延迟、迁移耗时。首轮至少覆盖 1/10/100 活跃租户和冷热混合，分别测试路由冷启动与稳态。数值为测量结果才可写交付结论，不预先承诺固定性能百分比。

容量评估先按资源而非租户数量计算：同一MySQL服务器的连接上界为所有宿主节点上该服务器各活动资源池maxPoolSize之和，再加迁移、运维、其他应用连接及预留。示例仅用于预算：3个节点、每节点20个活动独立库、每池上限5，就可能占用300条业务连接；100个租户共享4个物理资源、其他条件相同，则上界为60条，不能因租户总数相同而配同一容量。默认minIdle=0可降低闲置占用，但首次连接/TLS/池创建计入冷启动延迟；热点资源可显式预热，仍受节点和服务器总预算限制。线程池与请求等待队列都要有界，连接不足返回可识别的繁忙状态。

| 方式 | 性能与运维含义 | 选型边界 |
| --- | --- | --- |
| 同MySQL实例、不同schema | 路由查找通常不是主要成本；连接池增加，CPU/IO/redo仍共享 | 适合业务逻辑分库及独立迁移/备份，但不是独立故障域或硬资源隔离 |
| 不同MySQL实例 | 增加网络/TLS/连接维护；可隔离数据库负载与故障 | 配额按物理服务器核算，宿主CPU/线程仍需租户公平性 |
| Redis共享实例＋命名空间 | 客户端复用、成本较低；内存/淘汰/持久化/故障共享 | 默认方案；前缀只提供应用逻辑隔离，不能代替ACL和宿主授权 |
| Redis不同DB编号 | 数据命名空间不同，CPU/内存/故障仍共享 | 仅standalone受支持连接配置；不是每租户强隔离，Cluster仅DB0 |
| Redis专用实例 | 可独立配额与运维；客户端/网络线程/连接/轮询成本增加 | 合同或负载需要时绑定，按活动物理资源懒加载及回收 |

SQL统计自身的内存上界按租户×资源修订×语句标识预算；达到上限必须报告采样/丢弃计数，不能无限扩容。租户迁移产生的新旧修订需在明确窗口内展示，不能偷偷归并后声称同一数据源。负载测试还需覆盖一个慢库/断连Redis与正常租户并发，分别检查正常租户p95和失败资源预算，证明故障隔离而非只测健康环境总吞吐。

预计路由本地查找成本小，连接数/物理服务器共享 CPU IO/跨区域网络/版本轮询为主要风险。N 应用节点×活跃物理资源池上限是预算起点，并非 N 租户必然 N 池。分库仍共享宿主 CPU、线程、堆；只分 database 不等于资源故障独立。

部署采用前后端同批；先追加兼容 schema/品牌数据迁移再切入口和前端。旧 public API 明确删除，不支持旧前端继续调用；回退需旧前后端成套、保留迁移数据及写入核对。没有真实 DNS/证书/外部 MySQL/Redis 凭据时以隔离本地实例完成可验证范围，外部激活仍须单列证据。
