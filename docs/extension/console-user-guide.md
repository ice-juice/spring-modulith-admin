# 业务扩展管理使用说明

入口：新版前端 **业务扩展 → 扩展管理**（`/extension/manage`）。“业务扩展”为一级目录，实际管理页面为子菜单。该页面属于基座通用功能，使用当前鸢尾紫柔光主题、固定表格工作区，支持中文/英文和明暗主题。分组、功能选择和操作区在窄屏可滚动；数据、表头和分页在表格区域内操作。

## 首次使用

1. 管理员在业务后台为需要进入页面的角色分配 `extension:console:view`。该权限只开放页面，不赋予发布权。
   普通角色授权时自动包含一级目录 `extension:management`；使用超级管理员账号时，在权限资源中显式开启“扩展管理”的“超管默认权限”（目录默认开启）。目录下没有可见菜单时不显示空目录。原有根菜单升级时保留菜单 ID、授权和开关，已有导航分组关联迁至一级目录；修改后刷新页面获取最新菜单。
2. 页面自动使用当前后台身份连接，不需要再次输入账号或登录密码。发布管理员须先建立后台用户与发布权限的绑定；“未配置”“未绑定”“已停用”分别显示相应提示，不自动授予权限。
3. 首次使用点击“绑定安全验证”，输入管理员提供的注册票据和**发布操作密码**，将仅显示一次的种子录入验证器并填写验证码。完成后安全保存一次性恢复码。此密码和因素由发布服务独立验证，不会复制后台账号安全表或TOTP密钥。
4. 查看已有授权的分组、版本和记录不弹验证；上传、发布、回滚、配置/账号变更等操作在“核对并验证”后输入发布操作密码和新验证码。验证码在一个时间步只使用一次，刚完成绑定或上一次操作时需等待下一组验证码。

刷新或重新进入会自动连接。锁屏、退出或切换用户会清空页面敏感输入；解锁后恢复读取，未完成的敏感操作需重新核对。发布会话和机器凭据留在服务器，浏览器只向后台专用代理提交自己的后台凭据；操作密码、验证码、种子和注册/恢复票据不写浏览器存储。

验证器丢失时使用“恢复因素”，填写发布操作密码和一次性恢复码，旧因素与会话立即失效，再绑定新验证器。如果操作密码也丢失或恢复码不可用，联系发布管理员执行受审计的重置；后台超级管理员身份不能自行绕过。

## 分组、上传与校验

展开“分组与权限”，选择环境、JAR分组和插件；安全管理员可创建分组、插件，分配读权限及具体动作。可以按环境区分上传、校验、发布、灰度、回滚、删除等授权。按钮可见性只是提示，服务端每次重新检查。

在“制品版本”上传 `.jar` 或 `.java`。页面先计算文件SHA-256，展示名称、大小和摘要。源码上传还需构建清单；格式见 [SDK示例](../../examples/extension-echo/README.md)。

点击“核对并验证”，再次确认环境/分组/插件、参数和文件摘要，然后输入操作密码和新的二步验证码。授权后才发送分片；上传完成并不表示允许执行。选择“校验”另行授权，worker完成结构检查、隔离探测及漏洞扫描后才能进入发布流程。源码编译产生独立JAR，发布必须选择该产物。

查看“校验任务”了解排队、运行、失败和结果。容器/扫描不可用时任务会失败，不会用空结果当作通过。可以刷新查询，页面不会自动重提交敏感动作。

## 发布、灰度与回滚

- **稳定发布**：选择已校验制品和目标节点；可在同组选择其他插件组成协同版本向量，所有成员共同准备/切换。
- **灰度发布**：保留当前稳定向量和节点集合，选择要替换插件的新制品。第一次比例不超过10%；更高比例要求当前候选健康观察门禁。灰度由可信租户/主体固定分桶，用户不能用请求头指定代码版本。
- **灰度门禁**：固定当前修订、完整分钟最低调用数、最大错误率/慢调用率和截止时间。默认不自动晋升；可明确勾选“越过阈值时预授权回滚”。缺节点、样本不足、候选仍有在途执行或观察不完整时不得晋升。观察结果可查询。
- **晋升**：只有当前灰度候选和健康观察窗口才可晋升。
- **回滚**：从服务器返回的历史稳定向量选择；回滚产生更大的修订，不删除历史，也不反向撤销已经写入的业务数据。
- **取消准备**：填写原因，取消尚未激活的计划，仍有有效执行资格的稳定版本保持运行。

提交后查看“操作回执”和“发布管理”。ACCEPTED表示命令已受理，PREPARING表示等待所有目标节点准备，ACTIVE才表示控制面已经激活。各节点按协议对账，不保证所有机器同一毫秒切换。

## 结果未知与工作对账

上传或发布网络超时后页面先查原动作回执。若仍无法确认，使用“查询原动作”，不要更换幂等键重复提交。同一上传可继续传相同分片；整包hash仍由服务端核验。

“运行与工作”使用业务后台身份查询宿主运行状态和工作编号，仅能看到本人且仍有入口权限的工作。UNKNOWN/RUNNING不提供直接重跑按钮；“核验业务结果”必须具有 `extension:work:reconcile`，由稳定业务适配器查询权威结果并防止迟到执行。没有适配器或结果不确定就保持原状态和引用，不能强行释放旧版本。

## 账号、机器、信任与审计

账号创建、改权、因素重置、密码变更都需本次强化授权。最后一个有效安全管理员不能被禁用。注册票据只能创建会话领取一次，丢失/过期按受控因素重置流程处理。

机器类型为 NODE（业务宿主）、WORKER（编译扫描）、AUDITOR（独立审计镜像）、CONSOLE（后台身份连接）。各自独立凭据和环境，不可互换。机器token只能领取一次；轮换先暂存/领取，再安排配置更新，最后激活。`node-token-file` 可原子替换后零重启读取；签名公钥使用另一套stage/install/ack/activate/remove/retire流程，见 [部署手册](deploy/README.md)。

“发布审计”读取独立安全库审计，按序号继续查询。生产应部署独立AUDITOR镜像和不可变存储策略；本地链或页面查询不能替代外部留存。

资源策略和漏洞例外属于安全管理员高级功能。编辑JSON前核对后端手册；例外必须精确限定制品、环境、漏洞、依赖摘要、策略修订和期限，不能豁免扫描失败。

## 当前验收边界

浏览器截图使用固定模拟数据；真正的MySQL/TLS/MFA接口另有集成测试。当前机器无Docker和已审核固定镜像，真实容器编译/Grype扫描尚未验收；真实跨机切流/网络分区、持续负载、不可变存储和灾备仍需目标环境演练。已实现功能、命令、失败记录和未验证项见 [全栈进度](fullstack-progress.md)。
