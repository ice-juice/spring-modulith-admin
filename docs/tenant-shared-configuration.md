# P10 共享参数与字典实施设计（S5）

本设计细化已授权的[P10第6节](proposals/P10-tenant-branding-and-storage.md)，不代表S5已经交付。S4已验收，S5逐项结果记录在[进度](tenant-platform-progress.md)。

## 归属与影响路径

- `config/`拥有定义、共享修订、租户覆盖、旧数据迁移与有效读取；旧ParameterQuery/DictionaryQuery调用继续通过所属模块，不能跨表读取。
- `tenant/`继续拥有部署平台运维身份，并实现Config声明的最小授权SPI；可信目录分页复用现有`common :: security`的TenantWorkQuery。Config不能反向依赖Tenant内部类或产生模块环。
- `common/`只按新增平台元数据表的真实归属补充明确的持久化/架构约束，不允许业务数据绕过租户过滤；现有缓存契约保持默认拒绝PLATFORM DATA。
- 两套前端原有参数/字典入口接入有效来源和租户覆盖；平台共享管理在next提供独立页面、查看/编辑/发布权限。保持原租户独有配置的操作入口。
- Config已验收到V8，后续只追加迁移。原参数、字典、翻译及已有ID保留用于转换和回退核对，不修改已发布脚本、不删除客户修改。

## 定义由谁登记

受支持的静态基座/二开模块通过公开`ConfigurationCatalog`声明owner、唯一key、类型、作用域、默认值、覆盖策略、有限验证约束及生效方式。启动校验提供者实际包根/Modulith元数据与owner一致；业务参数使用`<owner>.`，字典类型使用`<owner>_`前缀。Config内置目录只对现有内置key保留原命名，不给业务冒用auth/system命名空间提供例外。

平台界面编辑已登记定义的共享值、文案、字典项及发布版本。执行代码依赖的类型/安全上限/公开投影不由表单随意改变。租户仍可通过原接口创建私有自定义参数和字典；新共享定义撞上既有租户私有同名数据时须在启动迁移中明确核对，不能静默夺取归属。未声明的任意JSON不成为系统安全策略。

定义的owner/key/type/tree模式/覆盖策略一旦发布，运行时不得原地改变；业务升级需要改变这些契约时附迁移方案。停用或发布新的默认值不能重定义稳定字典代码的业务含义。

注册器区分完整来源指纹与契约哈希：文案/代码默认值变化不自动重写已有草稿或平台发布，类型/上限/策略变化则必须显式迁移。参数key沿用原大小写不敏感的识别语义，重复别名不能注册两份定义；安全分类取命中的规范定义。共享字典代码和父代码按精确字符串识别，保留原值，不因翻译或显示格式转换代码。

## 参数解析

| 种类 | 没有租户值 | 允许的租户操作 |
| --- | --- | --- |
| TENANT_ONLY | 模块代码默认值或调用方fallback | 在当前租户创建/修改/删除；没有平台可变共享值 |
| PLATFORM_SHARED + LOCKED | 读取平台已发布值 | 查看来源，不允许保存覆盖或使用旧参数接口绕过 |
| PLATFORM_SHARED + OVERRIDABLE | 继承平台已发布值 | 保存显式覆盖、删除覆盖以恢复继承 |

优先级为定义允许的租户显式覆盖 → 平台已发布值 → 声明的默认值。租户私有定义保持原归属，不因同名平台记录出现被自动替代。用户偏好只影响原声明的外观/语言字段，不能覆盖参数安全边界。

缺少覆盖行表示继承；空字符串是显式值，按定义的allowEmpty校验；null只有定义显式允许时才是合法覆盖。JSON整体替换，不做深合并。INTEGER按Long范围、DECIMAL按有限长度/精度/scale、JSON按长度/深度/结构预算校验；约束是有限数据，不执行任意表达式或正则脚本。非法值明确拒绝，历史不合规值只报告租户/key，不截断、不输出值。

共享配置不保存凭据；连接密码/令牌继续使用所属服务的租户密钥契约。既有租户secret参数保持脱敏与留空保留语义，不被迁移成公开共享值。安全敏感与公开投影由定义决定，不能仅靠请求key的大小写前缀判断。验证码仍只经typed entry的固定投影公开，不恢复旧public HTTP接口。

旧Java查询方法的签名和fallback语义保留；新增有效值/来源/版本契约单独提供，不能把内部实体或Mapper放入公开签名。

## 字典解析

| 模式 | 平台职责 | 租户职责 |
| --- | --- | --- |
| PLATFORM_LOCKED | 共享类型及稳定代码，发布名称/排序/启停等受限变更 | 只读 |
| EXTENDABLE | 共享类型及稳定代码，维护平台发布版本 | 覆盖显示名称/翻译/排序、隐藏或恢复共享项、增加私有代码 |
| TENANT_ONLY | 无平台可变共享项 | 原租户私有类型/项目/树/翻译管理 |

租户不能改变共享项的代码、业务含义或父关系，不能将平台停用项重新启用。隐藏父节点时有效选择列表不产生孤儿子树；私有新节点只能引用同一有效类型下可用的共享或本租户父节点。全树验证拒绝越类型、跨租户、循环、自引用和超过深度/节点预算；以稳定code合成树，不以客户端ID猜测平台归属。

`options`继续返回当前可选树。历史代码展示与新提交有效性分别提供契约：停用/隐藏不会抹去历史标签，但不能作为新提交的合法选项。平台项采用停用，不能发布时物理删除仍有历史意义的代码；名称/翻译变更不会改代码。旧调用不因增加历史查询契约失去二进制兼容。

## 存储与发布

平台定义/发布指针与不可变发布修订使用Config自有平台元数据表；不放tenant_id=0，不借另一租户身份承载共享值。租户覆盖、私有新增项与迁移回执继续使用TenantEntity及租户唯一索引。共享正文中的定义、项目和翻译有明确schemaVersion，不能反序列化任意Java类型。

共享草稿与发布分开，expectedVersion防止覆盖他人修改；发布保存不可变修订并移动指针。所有动作继续使用当前请求治理和原操作者授权，平台身份与查看/编辑/发布权限同时满足。普通租户的superAdmin不能通过授予一个字符串权限获得平台权。平台/租户输入均不允许提交已验证来源、任意tenantId或内部生效指针。

同一平台数据库的写入使用已有LOCAL治理，不调用网络，不引入不必要的第二套回执。客户端结果未知先读取当前版本/发布状态核对，不能自动换键重发。跨资源Outbox属于S7，不把S5共享配置发布宣称为跨库事务。

平台管理路径在`/api/config/shared-configurations`下（S5b已验收，管理前端待S5e）：

| 方法与相对路径 | 权限 | 内容 |
| --- | --- | --- |
| GET `/` | config:shared:view | kind/keyword分页目录，最多50条；摘要不包含参数值或字典正文 |
| GET `/{id}` | config:shared:view | 登记定义、当前草稿版本与发布指针 |
| PUT `/{id}/parameter-draft` | config:shared:edit | expectedVersion、schemaVersion=1的参数内容；保存不发布 |
| PUT `/{id}/dictionary-draft` | config:shared:edit | expectedVersion、schemaVersion=1的字典内容；拒绝删除已发布代码或改父关系 |
| POST `/{id}/publications` | config:shared:publish | expectedDraftVersion、expectedPublishedRevisionId；追加不可变修订 |
| GET `/{id}/revisions`、GET `/{id}/revisions/{revisionId}` | config:shared:view | 历史摘要与同一配置的修订详情 |

全部接口还要求部署平台运维身份。写入携带Idempotency-Key；重复已完成请求遵循现有HTTP409＋最小完成回执，不能把它当成第二次发布或复用原业务DTO。可通过现有`/api/common/requests/lookup`按原键核对自己的结果，再走配置详情权限读取。菜单只在平台租户登记，不能代替操作授权。

代码目录最多256个定义、单定义序列化最多256KiB、总定义最多8MiB；共享正文最多256KiB，并受HTTP正文预算约束。每个定义最多1000份发布、累计32MiB历史正文；达到上限拒绝，不自动删除历史。头记录的历史计数与修订写入同事务。源码默认值变化仅提示来源指纹不同，不自动发布；不兼容契约阻止启动就绪。

## 缓存与性能

首版采用“定义来源指纹＋平台发布修订＋租户修订＋语言”的有效配置缓存键；来源指纹也区分代码默认值的升级。平台正文按不可变发布ID读取，租户层保持现有ManagedCache租户隔离和容量/TTL；平台发布切换修订使后续读取自然使用新代，不逐租户复制种子、不枚举N个租户重建缓存。旧代缓存由已有有界容量/TTL淘汰。

平台发布指针不放进普通有陈旧窗口的显示缓存；安全参数与敏感状态采用可信当前读，并保留现有事务内不回填共享缓存的规则。普通读取的版本查询成本必须纳入S10实测，不宣称“零开销”。当前不增加直接共享的PLATFORM DATA缓存；未来若要缓存此类数据，需另行审查专用契约及全平台操作权限，不能放宽CacheDescriptor的原有默认限制。

有效快照使用捕获的不可变平台修订加载，防止读取旧版本号却缓存新正文。租户覆盖提交与本租户缓存失效同平台资源事务完成；未提交或回滚不得影响他人有效读。预热复用同一解析器/版本键和较小预算，不保留旧版只查租户表的平行实现。

## 旧数据迁移与兼容

1. 平台登记代码目录和初始共享发布；新租户按定义继承，不再复制整套共享默认值。
2. 宿主通过已有TenantWorkQuery按可信租户目录分页启动迁移，每个租户一个短事务。Config处理自己的数据，不访问Tenant表；Tenant只提供受限目录，不访问Config表。目录接口仍拒绝来自已认证HTTP主体的全租户枚举。
3. 现有参数值、字典显示/翻译/排序/启停/私有新增项均保留为显式租户数据或覆盖，即使值恰好等于旧默认值，也不能猜测用户希望随平台变化。原行和ID保留，标记新归属与迁移版本/回执。
4. 发现类型、约束、代码/树或命名归属冲突时中止就绪，报告租户及字段/代码，不打印秘密内容。可以重入续作；重复迁移不产生第二份覆盖，不覆盖迁移后的用户修改。
5. 原初始化改为幂等确保目录可用，不重新复制共享项；重置只在明确操作下恢复继承/代码默认，不能被启动初始化触发。旧HTTP消费者同批适配来源与操作限制，保留仍受支持的原业务查询签名。
6. 只追加DDL。部署/回退须区分应用包与已经迁移的新配置：退旧程序前隔离写入并核对共享发布后的租户变更，不把单退JAR等同数据回退。

## S5c参数持久化落点

复用config_parameter，追加definition_contract和value_overridden；原ID、值、名称、排序和翻译不搬走。已登记定义的旧行必须先通过约束核对再绑定，旧值一律标为显式覆盖；secret或类型/约束/锁定策略冲突停止该租户迁移且不输出正文。显式null由可空param_value表示，value_overridden=false表示继承，两者不同。未登记的私有参数继续原管理契约。

config_write_lock追加parameter_revision，每个租户单调递增；不存在覆盖时也保留已推进的版本，防止覆盖→继承→覆盖出现ABA。参数写入和当前读统一先锁租户guard再访问参数行，平台发布只锁共享头、不回锁租户。管理修改要求同时匹配平台发布序号和租户参数版本；即使恢复到相同值也推进租户版本。当前读禁MyBatis缓存，旧REPEATABLE_READ快照不能覆盖已提交的新值。此阶段普通参数缓存的最终接线属于S5c-2，不把持久化服务等同缓存交付。

S5c-1新增DefinedParameterService、Config V7及专项测试；S5c-2再接内置目录/启动迁移/原ParameterQuery，S5c-3接HTTP。现有共享HTTP（S5b）已通过，两个前端租户表单及平台管理仍在S5e。上述中间状态不能独立部署到用户环境。

S5c-2普通参数读取以两个权威查询捕获租户版本与轻量平台指针，缓存命中不读取正文。未命中在短事务核对租户版本；发生间隙覆盖时改读当前一致快照，缓存拒绝将新版本放入旧地址。未发生租户变化时按原平台发布ID读取不可变正文，不能使用新指针正文填充旧key。安全参数完全旁路普通缓存，分类取代码定义；事务中的读取继续受原ManagedCache不回填约束。性能评估须计入这两个查询和现有缓存控制状态查询，不写成无数据库开销。

内置目录以13个现有非品牌参数为基础，保留旧值类型、数值安全范围和允许租户覆盖的规则。旧分组保留；启动不复制已登记参数。原ParameterQuery调用及fallback签名不变，旧未登记私有值和secret仍按旧契约读取/脱敏；已登记键不接受旧无版本create/update/delete。reset-builtins保留为明确的全量恢复继承命令（同租户事务、当前权限、LOCAL幂等），会使旧编辑版本失效；它不是按旧表单内容覆盖配置。前端和管理列表须同批适配后才可部署。

## S5c-3租户参数管理接口（后端已验收）

已登记定义使用`/api/config/effective-parameters`：GET分页目录（每页最多50条）和GET `/{key}`返回规范key、owner、定义/作用域/覆盖策略、有效值、来源、平台发布序号与租户版本。旧`/api/config/parameters`保留未登记私有参数的管理，不接受已登记键或已绑定行的写入。列表和详情都要求config:parameter:view；普通租户只能读自己的有效层，无草稿/平台历史管理权。

PUT `/{key}/override`要求config:parameter:update、Idempotency-Key、非空expectedPlatformRevision与expectedTenantRevision；value字段必须出现，显式null只有定义允许时通过。POST `/{key}/inherit`以同样双版本恢复继承，不删除原行/翻译。LOCKED定义拒绝这两个操作。按规范定义定位，不接tenantId/平台headId；页面不能拿全局共享ID当租户参数ID。

两项写入只执行平台数据库的配置/版本/持久失效及事件，使用LOCAL治理，无网络/跨库/独立提交。重放只给原操作者最小完成回执且重验当前权限；未知结果使用原键查询现有请求回执再读详情，不自动生成新键重发。保留大整数的字符串传输，明确“保存覆盖”“恢复继承”与平台“保存草稿”“发布”不同。

有效参数目录的group按代码定义归组，keyword按规范key搜索，分页先筛元数据再加载本页最多50项有效值；不为每页读取全部已登记正文。旧行的名称/翻译/排序仍用于租户展示；原分组字段保存在旧行中，但已登记定义的目录归组以模块声明为准。两种管理入口将由S5e用清晰的共享/私有分区呈现。

S5c-3补充显示来源标记：追加Config V8的presentation_overridden，旧行默认true以保留已有名称/翻译；新值覆盖设false，避免“只改值”意外冻结平台显示名称或丢失平台翻译。值覆盖和显示来源互不等价，恢复继承不删除旧显示元数据。当前没有任意租户HTML/模板注入或秘密值目录；V8为尚待验证的新迁移，不修改V7。

## S5d字典细化与代码冲突处理

平台可继续通过草稿/发布新增共享代码，不把该能力缩减成只能随代码发布固定枚举。为防止新共享代码覆盖现有租户私有代码，Config增加最小的全局代码归属登记：仅共享head ID、精确代码的SHA-256摘要、SHARED/PRIVATE归属和基座审计字段，不保存租户ID、显示名称、翻译、父关系或私有内容，也不提供目录/查询HTTP。它属于跨租户命名空间约束元数据；实际覆盖和私有项仍是TenantEntity，不能借此豁免业务表。

共享发布和租户新增私有代码在同一平台库事务内按头记录串行声明归属。同一个PRIVATE摘要可由多个租户各自使用；SHARED与PRIVATE不能互换，停用/隐藏/恢复不会释放历史代码。草稿保存不声明共享归属，发布才声明；失败回滚连同声明和计数回滚。每个共享字典最多65536种已声明摘要（含共享与历史私有代码），达到上限拒绝新代码，不清历史。现有共享代码由启动初始化幂等补登。读取不访问这个登记表，不增加普通字典查询的冲突检查成本。

锁顺序为租户guard→（需要新增私有代码时）共享head独占锁→代码声明/租户层；不能先持head共享锁再升级为独占锁，避免两个租户新增项时互相等待。平台发布只锁head和代码登记，不反向锁租户。代码比较保持精确字符串，不做大小写/空格归一化；后续租户层新表使用MySQL 8无填充的二进制排序规则。

S5d租户层采用独立的Config租户表，保留原字典类型/项目/翻译及旧ID，以legacy引用记录迁移来源；不改写原私有表的大小写唯一性。类型层保存定义绑定、旧类型引用、启停/显示覆盖；项目层分别保存共享覆盖和私有稳定代码。所有正文schemaVersion=1，租户dictionary_revision放在既有guard并单调推进。共享覆盖恢复继承不释放历史代码；私有项以停用退出选择列表，仍保留历史标签。

旧类型存在时，已有共享项目的名称/翻译/排序/隐藏状态全部转为显式覆盖，即使与默认相同；旧类型中缺少的共享代码标为隐藏，避免恢复旧租户已移除的选项。已有非builtin私有项与共享代码相同、父关系不符、超过512项/32层或其他约束冲突时停止该租户迁移，保留原数据并要求明确处理；不能静默合并不同业务含义。原类型不存在的新租户直接继承，不复制整套共享项。旧未登记字典仍走原私有管理/查询，不能给它们强加新的512普通读取上限。

首批既有内置字典声明EXTENDABLE，保留原可调整显示和增加私有代码的能力；PLATFORM_LOCKED与TENANT_ONLY继续作为受支持声明模式并独立验证。普通DictionaryQuery.options签名保留；历史标签/可提交性通过EffectiveConfigurationQuery的完整实现提供。预热使用同一有效解析/版本缓存，补上没有租户类型行的新租户共享定义枚举，使用新loader格式版本，拒绝旧游标混用。
