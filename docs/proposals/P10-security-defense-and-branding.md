# P10：基座安全防御、攻击监控与品牌配置

日期：2026-11-11。归属：可复用基座能力。状态：**用户已授权按阶段实施，密码策略保持当前规则**。实际交付和验收见[安全专项进度](../security-defense-progress.md)。

最初两轮为调查与方案补充；用户随后授权实施，明确不调整密码策略。本方案中的默认值、接口、表和性能数字以专项进度的真实验收为准。前后端防抖、防重复操作、接口限流与业务幂等设计详见 3.6 节。仓库同时存在租户平台 P10，本文保留原路径以免断链，后续称“安全专项”。品牌/域名/平台运维身份以[租户平台](P10-tenant-branding-and-storage.md)的单一实现接入；其已确认删除旧 public API 的决策取代本文原兼容桥接建议，不重复创建品牌表或管理页面。

## 1. 推荐方案

在现有 Spring Security、IAM、租户/数据范围、文件安全和审计能力上补齐防御闭环：**预防 → 检测 → 关联分析 → 告警 → 有限处置 → 复盘**。

- 新增静态 Modulith 模块 `defense`，统一攻击事件、诱捕端点、事件关联、告警规则和处置记录；随宿主运行，不默认拆独立服务。
- 认证和授权仍由 `auth/iam/common` 负责，攻击检测不能替代这些权威判断。
- 品牌管理按后续已确认的租户平台方案归 `tenant`，提供类型化配置、资产发布、预览/发布/回退和独立权限；不在 `config` 重复实现。
- 前后端统一防重复操作：查询输入防抖、写操作立即锁定、慢响应与结果未知提示；服务端分层限流、在途互斥和持久幂等，保证响应慢时不会因重复点击产生重复业务效果。
- 外围使用反向代理/WAF 限流和请求规则；应用负责身份、对象权限、租户以及业务上下文。边缘拦截事件也进入防御中心。
- 首期优先确定性规则、基础漏洞治理和可靠告警；行为模型、AI 分析和完整 SIEM 对接作为后续选项。

成功标准不仅是“能拦截测试请求”，还包括正常业务不被误伤、告警能够到达、匿名攻击不会错归租户、攻击流量不能拖垮事件存储。

## 3. 防御能力清单

### 3.1 SQL 注入预防与检测

1. 数据值全部参数绑定；动态表名、列名、排序方向由服务端固定映射选择。审查 MyBatis `${}`、字符串拼 SQL、`apply/last`、原生 JDBC、报表/导出和规则扩展。常量 `FOR UPDATE` 等允许通过明确门禁保留，不能一刀切禁止 API 名称。
2. 建立静态规则与审查例外清单：例外必须证明输入可信、归属明确并有反例测试。不能用统一删除引号、关键字黑名单或字符串转义代替参数绑定。
3. 分离迁移账号与运行账号。运行账号不具有 DDL、FILE、GRANT、管理员权限；迁移流程改造需覆盖当前 Flyway 启动方式和回退操作。
4. 注入特征优先由成熟 WAF 规则检测，可选 ModSecurity/Coraza 与 OWASP CRS，需先验证实际代理兼容性。应用仅检查有界、已解析的适用输入，关联路由、规则、身份和结果。
5. 关键词命中为“疑似注入”；是否到达数据库、是否被拒绝、是否发生异常分别记录。WAF 无法取代参数化，也不能证明所有攻击已被发现。
6. 正常 SQL 示例、技术文章、富文本等字段需独立策略；签名 API 检测不得改变原始字节、重复参数或正文顺序。

### 3.2 XSS 与浏览器安全

- 普通文字使用 Vue 默认转义；富文本统一经过服务端允许列表和前端 SafeHtml。清洗后不能再拼接不可信 HTML，禁止直接散落使用 `v-html/innerHTML`。
- URL 使用解析器校验 scheme、域名、端口和用途，拒绝危险协议及非预期协议相对地址；动态 CSS 只允许固定属性和有限值。
- CSP 首先使用 Report-Only，验证 Monaco、图标、二维码、资源加载、WebSocket 和必要 worker 后逐项收紧；覆盖真正返回 HTML 的静态站点，不能只给 API JSON 加头。
- 页面策略覆盖 `script-src`、`object-src 'none'`、`base-uri`、`frame-ancestors`、`connect-src`、`img-src` 等；不以全站允许任意内联脚本作为兼容方案。CSP 是附加防线，不能代替清洗。
- 补齐 HTTPS/HSTS、nosniff、Referrer-Policy、Permissions-Policy 和敏感响应 no-store；HSTS 子域策略按实际域名部署确认。
- 安全中心显示攻击参数时只显示转义文本，禁止直接预览攻击 HTML；CSV 导出同时防公式注入。CSP 报告接口有大小、速率和字段限制，报告可伪造，不能单独触发封禁。

### 3.3 CSRF、CORS 与身份入口

| 入口 | 策略 |
| --- | --- |
| 当前后台 Bearer API | 在凭据只来自显式 Authorization、无 Cookie/Basic 回退的前提下保留对应 CSRF 豁免；验证跨站表单无法形成有效授权请求 |
| 登录及敏感浏览器操作 | 严格 Content-Type、方法及 Origin/Fetch Metadata 策略，覆盖跨站登录/登出；缺少 Origin 的受支持客户端按入口定义处理，不能全局一刀切 |
| 未来 Cookie 会话/刷新 | Secure、HttpOnly、合适 SameSite，写操作验证绑定会话的 CSRF token，配套来源检查；SameSite 不是唯一防线 |
| Google/OIDC | 对接 P09 的 state/nonce/PKCE、精确 redirect URI、一次性登录事务；不能套用后台 Bearer 豁免 |
| 机器 OpenAPI | 保留独立签名/时间戳/nonce/撤销策略；不能因免 CSRF 放宽认证，不能把机器 secret 下发浏览器 |
| WebSocket | 精确 Origin、短时一次性票据、有效会话及连接/消息预算，日志不得保存票据 |

CORS 默认同源；确有跨域时使用精确来源白名单，不回显任意 Origin，也不将 CORS 当作服务端授权机制。GET/HEAD 等安全方法不得承载业务状态变更。

### 3.4 越权与租户隔离

- 每个请求同时校验身份类型、tenant、portal/audience、操作权限和对象归属；按钮隐藏及难猜 ID 均不构成授权。
- 查询、详情、更新、删除、分页计数、批量操作、导出、附件下载、回收站、异步任务和 WebSocket 订阅纳入相同检查矩阵。
- 请求 DTO 只接受允许修改的字段，拒绝通过 mass assignment 写入 tenantId、owner、角色、状态或审批结果。
- 无可信身份/租户的 HTTP 请求不能沿用初始化任务的默认租户；对后台任务使用显式可信作用域。与 P09 身份上下文改造协调。
- 权限撤销、角色变更、账号禁用及租户切换后，缓存不能继续授权。复用 P08 权威版本和失效机制，不能只清单节点内存。
- 统一拒绝对外响应，内部记录权限不足/对象范围不足等原因，减少对象是否存在的泄漏。检测短时批量枚举和跨对象拒绝，不将一次普通 403 当成攻击。
- 告警关联的租户必须来自可信认证或服务端已验证的域名/入口绑定，绝不使用请求体/header 的 tenantId 给事件定归属。

### 3.5 补充防护

| 风险 | 建议 |
| --- | --- |
| 撞库、密码喷洒、验证码滥用 | 按账号、来源、应用和全局组合限流；识别同来源多账号/同账号多来源；避免攻击者用失败请求长期锁死受害账号 |
| 账号与高危操作 | 生产运维账号强制 MFA；关闭防御、修改通道、导出证据、解除封禁需独立权限和重新认证；紧急恢复路径可审计 |
| 密码策略 | 用户明确保持当前 P07 策略：新登录密码 8～12 位字母数字并拒绝弱密码，安全操作密码 6～8 位字母数字，两者双向不同；旧密码验证规则不变。本专项不调整长度、字符或弱密码策略 |
| SSRF | 邮件/Webhook、远程导入、云 endpoint 等统一受控出站；协议/域名/端口允许列表，校验 DNS 和每次跳转，限制回环、内网、链路本地和元数据地址，处理 DNS 重绑定；内网合法目标需显式登记 |
| 上传、路径穿越、压缩炸弹 | 对接 P09：真实类型检查、隔离扫描、大小/像素/解压比/数量限制、安全存储键、绑定权限、扫描失败保持隔离；不重复实现第二条上传管线 |
| 资源耗尽 | 请求体、header、分页/导出、规则执行、正则、连接、队列和并发预算；高流量拦截放边缘，应用不承担大流量 DDoS 清洗 |
| 配置与信息泄漏 | 管理端点/文档/诊断仅对需要的角色或管理网开放；健康检查只暴露必要信息；错误响应不含堆栈、SQL、目录或内部版本 |
| 密钥与依赖 | 密钥独立保管和轮换；秘密扫描、Java/npm 依赖漏洞扫描、SBOM、制品来源与完整性；高危例外有负责人和失效时间 |
| 宿主与插件 | 继续 P05 签名、来源、依赖和发布控制；同 JVM 插件不能被宣传为不可信代码的强隔离沙箱；不可信执行需独立进程/容器另行设计 |
| 规则引擎 | 保持只读、类型约束、时间/大小预算和禁任意 Java/Bean 调用，向 defense 上报拒绝原因 |
| 灾备与应急 | 演练撤销会话、轮换密钥、回退策略及备份恢复；区分检测到尝试、已阻断、疑似失陷和已确认失陷 |

### 3.6 前后端防抖、防重复操作与接口幂等

目标：用户遇到慢响应时能清楚知道操作仍在进行；同一次操作即使连点、重复回车、网络重试或跨节点重发，也不重复创建、发送、发布或扣减；操作过快时服务端能有界拒绝，不积压无限请求。这里同时需要防抖、在途互斥、限流和业务幂等，单纯规定“两秒内不许再点”无法覆盖长请求。

#### 3.6.1 前端统一交互

| 场景 | 默认设计 | 边界 |
| --- | --- | --- |
| 搜索、联想、输入筛选 | 输入停止后约 300ms 发起查询，允许场景在 250～500ms 内配置；中文输入法组合期间不发查询，显式搜索立即提交并清除待执行计时器 | 新查询取消旧读请求并校验响应代次；服务端可能已执行被取消的请求，仍需后端预算 |
| 刷新、分页、相同数据加载 | 同一读取作用域/同一参数的在途请求合并；不同参数保留最新意图，避免旧页结果覆盖新页 | key 包括可信身份作用域、路由及参数，切账号/租户/portal 时清理；授权/安全状态查询不能使用陈旧缓存凑去重 |
| 保存、删除、提交、发布、批量操作 | 第一次触发立即在处理函数入口取得同步操作锁，再进入确认/异步校验/请求；关联按钮显示 loading 并禁用 | 鼠标、回车、快捷键和其他入口共用门禁；取消确认或本地校验失败可释放，不只依赖下一帧 disabled 渲染 |
| 同对象互斥操作 | 保存/删除/启停等冲突动作共享对象级在途锁；服务端仍需独立并发控制 | 不同对象的无关操作保持可用，不给整站加全局大锁；批量操作明确作用对象和原子性 |
| 慢响应 | 立即显示“正在处理”，建议 3 秒后显示“处理时间较长，请勿重复提交”；可预期长任务返回任务编号并展示真实进度/状态 | 不伪造百分比，不因等到固定秒数就解除提交锁；轮询有退避、抖动和上限，隐藏页面降频 |
| 请求超时、断网、主动中断 | 标记“结果待确认”，保留当前操作编号，提供“查询处理结果”；得到明确失败或允许安全重试的回执后才继续 | 超时和关闭弹窗不证明后台未执行；禁止默认再次生成操作编号重发写请求 |
| 确定失败或成功 | 确定未提交的校验/业务失败恢复编辑并保留输入；成功后刷新真实数据和释放锁 | 服务器 5xx、连接断开不自动归为“确定失败”；迟到响应不能更新已切换用户或新表单 |

封装建议：新增统一 `useSubmitGuard`（暂名）及操作状态登记，复用现有 `EditorDialog`、上传组件、请求客户端和 `useRequestGate`。覆盖主按钮、行内操作、确认弹窗、批量入口及各 feature 的真实业务处理函数，不能只改 Button 外观。旧前端仍受服务端保护，新旧客户端兼容在接口清单中登记。

操作状态至少包含 READY、SUBMITTING、PROCESSING、UNKNOWN、SUCCEEDED、FAILED；PROCESSING 是服务端确认已受理，UNKNOWN 是尚不能确认结果。普通短请求不强制都变异步任务。用户离开页面时提示正在处理；可恢复任务仅持久化受身份隔离的 operationId、作用域和必要状态，不保存密码、OTP、正文或 token。重开页面先查结果；同浏览器多标签可用通知机制同步状态，后端才是最终防线。

#### 3.6.2 服务端按接口分类治理

所有 API 登记策略：身份域、路由、查询/写入/长任务类型、限流预算、并发预算、是否幂等、幂等键/业务键来源、互斥范围、超时、回执、重试与例外。新接口必须声明策略；旧接口逐项接入并记录覆盖状态，不能直接全局套一个间隔。

预算口径（[P11 跨专项资源归属](P11-cross-stream-resource-ownership.md)）：各模块预算表（auth `SecurityRateLimit`、openapi `LoginBudget`、identity `IdentityEmailBudget`/`IdentityLoginBudget`、file `TaskBudget`、common `RequestBudget`、tenant `BrandWorkBudget`）保留各自语义、不合并实现，但接口清单必须为每项登记 scope：`shared` 表示数据库持久、跨实例累计，`node` 表示单进程并发门禁。节点级门禁（当前 `/app/**` 默认 64、`/api` 写默认 8）不是集群总量，N 个实例下实际受理容量为 N 倍，部署文档据此给出总量。任何“每分钟最多 X 次”的表述都要注明属于哪一类。

| 防线 | 服务端行为 | 注意事项 |
| --- | --- | --- |
| 请求限流 | 按主体/应用、路由、租户及必要来源 IP 组合令牌桶或时间窗，允许受控短突发；匿名入口用独立来源/场景预算 | 超额立即 HTTP 429，返回 Retry-After 和双语提示；共享 NAT 不以 IP 单维误伤，多 IP/多账号仍受总预算 |
| 在途并发门禁 | 同主体对同对象的冲突操作只允许限定数量执行，其他请求快速返回处理中/冲突 | 重复请求不在工作线程无限等待；不同节点共享原子状态，本地 Map 或“先查再写”不构成可靠门禁 |
| 持久幂等 | 同逻辑操作携带稳定 Idempotency-Key；同键同输入复用结果或返回原 operationId，同键异输入拒绝 | 对象创建/发送/发布等有副作用操作必须按清单适配；需要幂等键的接口缺键时明确拒绝，兼容窗口须声明 |
| 业务一致性 | 业务唯一约束、版本号/条件更新、领域状态机保证同一业务动作不能重复生效 | 两个标签或脚本可能发送不同幂等键；相同业务动作仍须业务键保护。确实允许创建两条相同内容的场景不能被全局正文哈希误拦 |
| 后台任务与外部动作 | 建立持久任务/回执，事务 outbox 与下游幂等或对账配合 | “受理一次”不保证邮件/第三方动作恰好执行一次；外部结果未知先对账，不盲重发 |

建议初始值用于隔离验收：输入 300ms；同一提交意图在途并发 1；手动刷新可设 500～1000ms 冷却；服务端读、普通写、发送验证码/邮件、导出等分别配置速率。具体每秒/分钟配额由正常业务负载确定，不给所有用户/接口硬编码“一秒一次”。自动保存另用串行合并最新编辑和版本校验，不能丢失最终编辑。

#### 3.6.3 幂等协议、事务和异常恢复

1. **操作标识**：前端在一次提交意图建立时生成高熵随机键；该意图的安全重试复用原键。服务端作用域至少绑定环境、可信租户、主体类型/ID、portal/audience、稳定操作编码和具体目标对象。不能按客户端声称的 tenantId 或裸键全局复用结果。
2. **输入一致性**：服务端按接口契约计算有界请求指纹，涵盖影响业务效果的路径、参数、正文和版本；相同键不同输入返回 HTTP 409 `IDEMPOTENCY_CONFLICT`（拟定）。普通 JSON 规范化规则与版本明确；插件/签名入口保留原字节摘要契约，不能统一重编码。指纹不包含 Authorization 等秘密，不把敏感正文作为账本内容。
3. **原子占位**：持久唯一索引保证并发只取得一次执行权。建议 MySQL 作为幂等权威，状态为 RUNNING、SUCCEEDED、FAILED_FINAL、UNKNOWN；普通可清空缓存不保存唯一防重证据。高流量限流可使用共享原子存储，但与不可清理的幂等账本分开。
4. **本库短事务**：执行权占位可短事务提交；业务事务必须锁定/核验该执行权，并将本模块写入、必要 outbox 与 SUCCEEDED/结果引用在同一数据库事务提交。common 只能操作自己的账本，由业务通过正式契约协作，不能跨模块改表。任意失败后需证明业务已回滚才释放或转可重试状态。
5. **长任务与进程崩溃**：工作租约、执行代次/fencing 或数据库锁防止旧 worker 迟到提交。租约超时不等于可安全重跑；先查业务权威记录再恢复。已存在的 extension 工作账本继续按原协议处理，不叠加一层自动重跑或改变原 bundle 固定规则。
6. **回执与权限**：完成时返回原业务结果的安全快照或受权限保护的结果引用；处理中返回 HTTP 202 和原 operationId/受权状态地址；同对象不同意图冲突返回 HTTP 409。每次重放和状态查询仍检查当前身份、权限及对象范围，不能借旧回执绕过权限撤销；状态地址只能是受控同源路径。
7. **秘密与重新认证**：密码、OTP、登录令牌、一次性 secret 不做通用响应缓存。认证/绑 MFA 等接口保留专用挑战和原子消费语义；重试不得复用消费凭据绕过验证，可查询脱敏结果或要求新的重新认证证明，操作键本身不授予执行权限。
8. **有效期**：普通写操作可先按 24 小时幂等窗口设计，必须向客户端声明保留期；长任务、未决状态和外部回执不得到期直接删除重跑。重要业务键/唯一性保留期独立于短期回执。窗口外不能再承诺普通随机键防重；持久业务键或服务端发行且可判定过期的操作标识保护跨窗口重试，并提示先核对结果。
9. **存储故障**：要求幂等的写接口若无法原子占位，返回 HTTP 503 并明确未受理，不绕过保护直接执行；执行中丢失响应/存储连接则保持 UNKNOWN 并对账。基础设施故障与用户超频分别提示，客户端不自动重试不安全写操作。

客户端 HTTP 包装增量提供 operationId/Idempotency-Key、状态查询、Retry-After 与明确错误分类，保留现有调用签名兼容。跨域场景显式允许幂等请求头并暴露必要响应头；签名机器调用把操作标识绑定到受认证请求，兼容已有协议，不能新增未受保护的关键控制头。

#### 3.6.4 与安全中心、架构及验收衔接

正常重复点击优先视为体验和负载问题：只记聚合指标，不逐次告警或封号。长期超频、持续换键绕过、并发枚举等与其他信号关联后再升级安全事件。监测被合并查询数、被阻止重复提交数、429 比率、幂等重放/冲突、UNKNOWN 数量及持续时间，不采集表单正文。

通用请求治理建议放 `common` 的专用公开契约（暂名 `common :: request`）及内部实现，业务拥有语义幂等键、业务唯一性和回执投影；`defense` 接收事件并管理允许的运维策略，不能成为业务提交正确性的必需依赖。鉴权限流和插件账本先保持既有契约，按适配器复用，避免同时大改多套安全机制。

必须覆盖的验收场景：

- 模拟后台延迟 10 秒，用户连续点击/回车 20 次：同一意图前端只发送一次写请求，服务端业务结果只产生一次；超过 15 秒默认 HTTP 超时后显示结果待确认，恢复网络查询到原结果。
- 绕过前端，两个实例并发发送同键同输入请求：一个执行者，其余获取同一回执；同键异参拒绝；不同租户/主体不能互查或冲突复用。
- 不同键对同一不可重复业务动作并发：由业务唯一性/版本/状态机阻止重复生效；允许重复内容的独立创建仍正常工作。
- 服务端提交成功但响应丢失、执行前/事务中/提交后进程终止、worker 租约失效及迟到提交：恢复后不产生重复副作用，无法确定的结果保持 UNKNOWN，不假报失败或成功。
- 搜索连续输入/中文组合输入仅按策略发请求；旧响应不覆盖新结果；分页、不同对象、不同用户的正常并行操作不被错误合并。
- 429 有可读取的 Retry-After，503 与已受理未知状态区分；达到冷却后允许新意图；幂等存储故障、过期/清理、权限撤销、跨标签/刷新恢复均有反例。
- 上传按 uploadId/分片号和内容摘要治理，不能因全局防抖影响正常并发分片；批量操作按已声明原子性/逐项回执恢复；OTP/签名 nonce/插件幂等原回归继续通过。

## 4. 攻击监控与诱捕设计

### 4.1 采集与关联

采集来源包括边缘 WAF/访问日志、入口请求拒绝、认证/权限拒绝、业务对象检查失败、诱捕命中、安全配置变更和文件扫描结果。一次请求用统一 traceId/eventId 关联，避免边缘与应用重复计数。

HTTP 入口采集必须覆盖 MVC 之前的拒绝与未知路由；在受信代理解析之后采集网络身份，在认证结果可用后附加可信主体。对于根本没有到达应用的请求，从边缘补充事件，不能宣称应用过滤器能看到全部网络攻击。

检测链路：信号 → 规范化与脱敏 → 持久事件 → 时间窗关联 → 事件单 → 告警投递 → 有限处置。规则有 ID、版本、严重度、置信度、范围和动作。首版仅允许有限匹配/计数/时间窗条件，不提供任意脚本执行或无预算正则。

### 4.2 陷阱接口

采用低交互诱捕。接口可以表现为废弃管理入口、历史诊断入口或备份索引，但只提供固定、无害响应；不实现真实命令、查询、上传或调试功能。

| 类型 | 发现方式 | 处理 |
| --- | --- | --- |
| 常见扫描路径 | 扫描器猜测配置、版本库、备份、旧管理入口 | 边缘识别并返回通用拒绝/404，聚合扫描事件；不创建真实敏感文件 |
| 部署专属诱捕路径 | 使用部署独有路径，必要时在受控诱饵内容中放非凭据标识链接 | 命中记录 trapId；可给更高置信度，但仍校正授权扫描、预取和误点 |
| 假凭据标识 | 诱饵内容中的随机无权限标识，被用于访问时关联 | 标识不能是有效密码/API Key，永远不能换取令牌或读写权限；后续阶段可选 |

“完全隐蔽”与“可被发现”需要取舍：无人知道的随机路径也不会自动引诱扫描者。首期组合常见扫描识别与少量受控诱饵；不依赖 robots.txt 保密，不在正式菜单、SDK 或正常 API 文档中暴露诱捕入口。

安全约束：

- 精确匹配已登记路径/方法，部署前检查与现有及插件路由冲突；不得以 `/api/** permitAll` 等宽规则开放真实 API。
- 常见 `.env/.git` 等优先留在代理层识别；不要为了诱捕放松 Spring HTTP firewall 或静态文件保护。
- 不回显用户输入，不访问真实数据库/文件，不建立出站连接，不维护长时间交互，不使用真实生产备份/凭据作诱饵。
- 固定小响应、无状态、有速率和总预算；攻击者反复触发时聚合计数，防止诱捕反成放大和资源耗尽入口。
- 支持启停、轮换、版本、误报标注和演练标记。已授权扫描降噪但保留审计，不能加入完全不记录的名单。
- 单次命中代表访问了诱捕入口，不等于确认是黑客，更不等于系统已失陷。

### 4.3 来源与攻击手段记录

每条事件保存：eventId、发生/接收 UTC 时间、环境/节点、traceId、直连 IP、受信解析的客户端 IP、代理链摘要与可信等级、请求方法/路由模板/状态、可信主体类型及 ID、可信 tenant/portal/audience（如有）、规则 ID/版本、攻击分类、严重度、置信度、证据摘要、阻断结果和 incidentId。

攻击分类包括疑似 SQLi/XSS、路径遍历、配置探测、撞库、喷洒、对象枚举、权限拒绝聚集、签名重放、诱捕命中等。记录“观察事实”与“系统推断”两列；不存在足够证据时结果为未知，不能把检测命中写成利用成功。

- 受信代理 CIDR 显式配置，入口代理覆盖外来 Forwarded/X-Forwarded-For；按可信链解析。直连后端限制到允许的代理网络；IP 处理覆盖 IPv4/IPv6。
- IP、ASN、粗略地域可辅助研判，不等于真实人员身份，NAT/VPN/代理会影响归因。GeoIP 不是封禁的单一依据，优先离线数据库。
- 不保存 Authorization、Cookie、密码、OTP、票据、AppSecret、完整正文或全量查询字符串。只保留字段名、受限脱敏片段和必要的带密钥指纹；低熵敏感值不能用普通哈希当作充分脱敏。
- 大小有界，处理 CR/LF 和日志注入；认证请求默认不采正文。边缘同样执行脱敏，不能应用不记录而 Nginx 全量记录。

### 4.4 告警与处置

| 等级示例 | 条件示例 | 默认动作 |
| --- | --- | --- |
| 低 | 单次扫描路径/普通异常参数 | 记录和聚合，不逐请求通知 |
| 中 | 短时多路径扫描、对象枚举、重复失败 | 生成事件单，限流；按通知策略发送摘要 |
| 高 | 部署专属诱捕命中并有其他信号，持续攻击认证入口 | 尽快告警，可配置短期封禁/挑战或要求重新认证 |
| 严重 | 有证据的高权限会话滥用、安全策略篡改或疑似失陷 | 立即升级通知，按已批准处置策略撤销相关会话/隔离来源，人工调查 |

阈值必须经过观察期调优，不能把示例当成统一硬编码。分开记录事件严重度和检测置信度。

通知通道：站内通知、邮件、企业微信/钉钉/飞书等受控 Webhook。首期建议站内通知加一个用户选定的外部通道；邮件依赖 P09 的 mail 实际交付，不把已有站内 message 当作 SMTP。通道通过公开 API/SPI 集成，不直接调用对方 internal。

- 按环境、范围、严重度配置收件组/值班组。平台告警走平台专属通道；租户告警只发本租户被授权运维，秘密配置只保存安全引用。
- 事件与告警 outbox 持久化，独立 worker 使用租约/幂等处理；去重、冷却、指数退避、失败重试、死信和备用通道齐备。应用线程不等待外部网络投递。
- 同一事件窗口合并通知，保留次数、首末时间、最高严重度；严重度升级突破冷却。区分已入队、通道接受、发送失败、结果未知和人工确认，不能把 HTTP 200 宣称为人员已阅读。
- 目标：额定负载、事件存储和通道正常时，高危事件 p95 在 5 秒内创建告警任务，p95 在 30 秒内被至少一个外部通道接受。演练实测后才写入承诺。
- 超过建议 5 分钟无人确认时升级到备用值班组，支持维护窗口但严重事件仍留存。通知正文不携带攻击原始内容或敏感参数，只给受权限保护的详情链接。
- 支持观察、限流、二次验证、短期封禁和人工解封。规则从观察模式逐项转阻断；自动封禁默认有 TTL，不因单次访问永久封 IP，更不能直接封整个共享网段。
- 封禁、解除、关闭检测和更改通知目的地都有独立权限、重新认证及审计；提供带审计的管理网恢复路径，避免误封后无法自救。

### 4.5 多租户、可靠性与数据预算

匿名扫描通常不能证明属于某个租户。此类事件进入 **PLATFORM 范围**，仅平台运维可见；有可信归属的事件进入 TENANT 范围。不能借用默认租户 1，也不能因为 URL 中出现租户号就赋予归属。

建议 PLATFORM 与 TENANT 使用物理独立的事件/事件单表和访问路径：平台表无普通租户读写入口，任何租户管理员包括其租户超管都不能读取平台或其他租户事件。若平台表需要成为框架租户豁免表，须作为显式基座变更评审并加架构/授权测试，不通过通用 ignoreTenant 绕过。

- 安全事件采集不能随被拒绝业务事务回滚；对持久事件和 outbox 明确独立提交边界，避免仅 afterCommit 记录而丢失失败行为。
- 入口处理限时、有界；普通检测存储失败不能让全站无限等待。权威认证/授权及明确阻断仍拒绝，检测故障不得使拒绝变放行。
- 事件库故障时使用有容量上限的本地持久缓冲或外部日志接收端，恢复后按 eventId 补传；容量满时优先保留高危摘要，记录丢弃计数并触发独立运维监测。不得承诺无限无损。
- 高危规则发布、封禁策略变更、证据导出等管理动作若必需审计不可持久化，则拒绝该管理动作。
- 多实例以共享权威策略、规则版本、工作租约和撤销状态为准；不能仅本地 HashMap 封禁或去重。P08 缓存不成为可随意清理的安全权威状态。
- 初始预算建议：事件查询在线 30 天、聚合统计 180 天、单条脱敏证据不超过 2 KiB，实际按容量和需求调整；大流量先聚合，不将每个扫描包写进业务 MySQL。
- 法证留存与普通保留期分开；归档加访问控制、加密和不可变存储选项。普通业务管理员不能编辑证据，处置备注以追加记录保存。数据库管理员仍有较高权限，不能只凭应用“禁止编辑”宣称防篡改。
- 持续监控事件延迟、告警队列、失败率、丢弃量、磁盘/数据库空间和 worker 心跳；安全中心故障需要独立于自身的可用性告警。

## 5. 品牌配置（已由租户平台取代）

**本节原有的品牌字段、发布管理与公开接口设计已被[租户平台方案](P10-tenant-branding-and-storage.md)取代，不再作为实施依据。** 品牌只保留租户平台一处实现（`tenant` 模块的草稿/修订/发布指针与素材引用），本专项不重复建表、不重复建管理页面，也不保留原兼容桥接建议——旧公共参数 HTTP 接口按租户平台已确认的决策直接删除。

本专项对品牌只保留安全验收职责，范围为：资产类型与 URL 策略、公开投影字段最小化、权限不外溢（改品牌不得顺带获得关闭验证码/MFA/防御或改密钥的权限）、发布与回退的重新认证，以及未知域名回落平台默认、拒绝由 tenantId/Host/Forwarded 注入跨租户配置。

验收顺序（[P11 跨专项资源归属](P11-cross-stream-resource-ownership.md)）：品牌素材经 file 模块上传并通过匿名白名单入口对外投影，而 P09 的文件安全流水线尚未完成。因此品牌资产的安全验收不排在本专项队尾，提前到攻击采集 S2 之前；在 P09 C4d 完成前，公开入口只接受已验证的受限图片类型，不因租户平台已标记完成而跳过。

## 6. 模块、路径与数据模型草案

| 拟改路径 | 职责与影响 |
| --- | --- |
| `backend/src/main/java/com/sma/admin/defense/` | 新安全事件、规则、诱捕、事件单、告警和处置静态模块；需要 Modulith 依赖、权限目录和路由登记 |
| `backend/src/main/java/com/sma/admin/common/security/` 及相关 internal 适配 | 最小安全信号契约、可信来源/作用域类型；已有模块按统一契约发信号，common 不依赖 defense |
| `backend/src/main/java/com/sma/admin/common/` 专用请求契约及内部实现、各模块服务入口 | 通用限流/执行权/幂等账本协作，各业务自行声明语义唯一性；保持 auth 限流、extension 工作账本和签名协议兼容，不跨模块写表 |
| `backend/src/main/java/com/sma/admin/auth/`、`iam/`、`openapi/` | 鉴权/授权结果信号与现有防护补强，复用各自正式 API，不让 defense 直接改会话/角色表 |
| `backend/src/main/java/com/sma/admin/config/` | 参数/字典的安全治理（避免普通参数误标公开、security 设置混入品牌权限）；类型化品牌配置与发布版本已归 `tenant`，本专项不在此实现 |
| `backend/src/main/java/com/sma/admin/file/`、`message/`、P09 `mail/` | 通过正式契约提供品牌资产与通知适配；缺失契约先补最小通用公开面 |
| `backend/src/main/resources/db/migration/defense/`、`config/`、`common/` 及适用业务模块 | 追加事件、品牌、请求治理账本及必要业务唯一性迁移；实施时再确认版本号，旧脚本不原地改写 |
| `frontend-next/src/features/defense/`、`features/config/` 与语言包 | 攻击中心/品牌页面、权限/路由；沿用现有组件和双语规范，保留旧前端 |
| `frontend-next/src/api/`、`composables/`、`components/business/`、各 feature 操作入口 | 统一输入防抖、提交门禁、慢响应/未知状态、幂等头和回执查询；覆盖实际事件处理，不只禁用按钮；保留身份隔离与旧接口兼容 |
| `backend/src/test/`、`frontend-next/e2e*/`、部署示例/验证工具 | 拒绝路径、双租户/平台隔离、真实浏览器安全头、代理链、多实例及容量演练 |
| `README.md`、相关 AGENTS/专项规则、实施进度与运维手册 | 实施后同步真实能力、配置/恢复方法和未验证范围 |

依赖原则：生产模块通过 common 的最小信号契约报告；defense 消费信号并通过既有公开 API/SPI 发通知或请求撤销。auth/iam 不反向依赖 defense，避免循环。信号接收必须有持久化/故障语义，不能仅有不可恢复的内存事件。

建议表族：`defense_platform_event/incident`、`defense_tenant_event/incident`、规则及版本、诱捕登记、告警策略/outbox/尝试、处置及追加记录。共享表如需承载多个范围，须有数据库一致性约束及专属访问层；不能把 scope 仅作为前端筛选字段。正式 DDL、索引、分区/归档方式在 S0 容量评审确定。

品牌发布数据归 `tenant`（见第 5 节与[租户平台方案](P10-tenant-branding-and-storage.md)），本专项不在 `config` 另建品牌表或平行参数系统。凭据存引用，不落在品牌或攻击规则明文 JSON。

安全中心页面建议：总览、攻击事件、事件单详情/时间线、诱捕管理、规则与观察模式、封禁与例外、告警策略/投递记录、证据访问记录。明确显示“疑似/已阻断/待确认/已处理”，不以世界地图代替事件排查。

权限区分租户安全查看、事件处理、规则管理、告警管理、证据导出和平台全局安全权限；平台权限必须同时验证可信平台运维身份，不能仅靠 tenant 内的字符串权限自授。新增权限按现有目录登记，不自动扩充普通角色。

## 7. 分期实施与验收

用户已授权按以下顺序实施（排除密码策略变更）。细分任务和证据维护在[专项进度](../security-defense-progress.md)，每项完成并验证、更新记录后才进入依赖项。

| 阶段 | 范围/依赖 | 验收标准 |
| --- | --- | --- |
| S0 | 威胁建模、API/身份/数据资产清单、平台运维定义、部署拓扑、数据预算、公开契约 | 确认路径、平台/租户边界、通知通道和迁移/回退方案；完成逐接口防抖/限流/幂等/互斥策略清单；核对 P07/P08/P09 并行状态 |
| S1 | SQL/XSS/CSRF/越权基础补强；依赖 S0 | 每个已识别入口有正常与拒绝用例；动态 SQL 门禁，跨租户/对象/身份矩阵，真实页面 XSS/CSRF 与安全头验证通过 |
| S1a | 通用请求治理契约、限流/并发预算与持久幂等；依赖 S1 | 原子竞争、同键异参、双实例/双租户、故障/回执/过期/撤权测试；auth 和插件原协议不退化 |
| S1b | 各写接口业务幂等/唯一性/状态查询适配；依赖 S1a | 按 S0 清单逐项验证；不同键重入、事务/响应丢失、外部未知、批量/上传例外；未覆盖项不能标记全站完成 |
| S1c | 统一前端查询防抖、提交锁、慢响应与结果未知交互；依赖 S1b | 真实处理函数/多入口覆盖，迟到响应/身份切换/中文输入/重试与刷新恢复；兼容旧前端消费者 |
| S1d | 前后端联合慢网、断连与高并发验收；依赖 S1c | 完整执行 3.6.4 矩阵：10 秒慢请求连点 20 次仅一次业务效果；15 秒超时结果核对；无误合并正常操作 |
| S2 | 可信来源、安全事件、事件查询和容量控制；依赖 S1d | 记录匿名/过滤器拒绝/未知路由；业务回滚不丢事件；平台和租户完全隔离；伪造代理头无效；秘密不入日志；普通重复点击不触发攻击封禁 |
| S3 | 轻量诱捕、关联规则、站内与一个外部通道；依赖 S2 | 受控命中→事件→告警任务→测试通道接收全链路；失败/未知/重试/去重/洪峰/渠道故障测试；邮件须等待 P09 mail 验收 |
| S4 | 品牌安全验收（页面与发布实现归租户平台）；依赖 S1 及必要文件公开契约。按 [P11](P11-cross-stream-resource-ownership.md) 提前到 S2 之前执行 | 双租户与登录前解析、私有资产不能公开、危险 URL 拒绝、公开投影字段最小化、权限不外溢、双语明暗/移动端验证 |
| S5 | 短期封禁/挑战、观察转阻断、外部 WAF 接入；依赖 S3 | 正常业务回放无不可接受误伤；来源可伪造测试、TTL/人工解除、多实例一致性、配置回退和管理网恢复演练 |
| S6 | 全量安全门禁、隔离 DAST、容量/故障/恢复和文档；依赖全部 | 根 reactor 标准验证、新前端 verify、指定 E2E、迁移/回退演练；逐项列明真实外部联调和生产部署未验证项 |

首个可用版本以 S0～S4（含 S1a～S1d）为目标：基础防护、前后端防重复操作、接口限流与幂等、攻击可见、轻量诱捕、可靠告警和安全品牌管理。自动封禁在采集到正常流量基线后逐规则开放；不等待 AI/复杂行为模型才交付基础能力。

必要负例：SQL 符号合法输入、富文本合法内容、跨域伪造写请求、Cookie 自动携带场景、匿名和 APP_USER 冒用后台入口、同租户不同对象及跨租户批量操作、代理头伪造、诱捕路由冲突、恶意日志/CSV、Webhook SSRF、队列满/数据库断连/通道超时、两节点重复消费、品牌回退和来源域名串租户。

检查命令以仓库规则为准：根目录 `pwsh -NoProfile -File tools/dev/verify-backend.ps1 -Standard`，新版前端目录 `npm run verify`，再运行本阶段约定的专项 E2E。若本机 pwsh 别名不可用，核实后使用 `powershell.exe` 对应入口。所有重建表/攻击/容量测试使用独立可清空库、独立端口和输出目录；不对正在运行的用户实例发攻击流量。

测试通过不代替部署验收：Nginx/WAF 实际规则、HTML 安全头、外部消息送达、生产代理 IP、多节点网络和恢复演练各留独立证据。

## 8. 取舍与待确认事项

建议默认采用：同源部署；MySQL 持久权威状态；独立 defense 静态模块；低交互诱捕；先观察再自动阻断；品牌固定 DTO 和本地受控图片；站内通知加一个外部通道。

部署时需配置公网入口/受信代理、平台运维身份、外部通道及接收组、保留/容量预算。本地使用隔离夹具验证，不自动给真实人员发送告警；缺少外部配置不能记为真实送达。品牌跟随租户平台已确认的域名/资产规则；密码策略不变。

以下资料于本次调研读取，用于设计依据；未将其等同于本项目已通过认证或完整安全审计。

- [OWASP SQL Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html)：参数绑定、动态标识白名单、最小权限；不推荐靠手工转义防注入。

- [Spring Security CSRF](https://docs.spring.io/spring-security/reference/features/exploits/csrf.html)：无状态不等于无 CSRF；Cookie/Basic 自动附带凭据、JSON、登录及上传均需按场景处理。
- [OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)：默认拒绝、每请求校验、对象级授权及静态资源保护。
- [OWASP Logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)：安全日志与业务审计的区别、事件上下文、秘密排除、信任等级、日志防注入与可用性。
