## 1. 已确认要求与设计建议

### 1.1 用户已确认的要求

1. 用户绑定 TOTP 后，每次新登录先输入用户名和登录密码，再进入独立的 TOTP 验证页；第二步通过前不得获得业务访问权限。
2. 锁屏解锁只验证登录密码，不重复验证 TOTP。解锁仅恢复原有有效会话，不是新的登录或会话续期入口。
3. 安全操作密码为 **6～8 位 ASCII 字母和数字的组合**，至少包含一个字母和一个数字；不要求同时包含大小写，不要求特殊字符。
4. 安全操作密码不能与登录密码一致。
5. 安全操作密码本期只建设底层、表结构及管理能力，暂不用于现有敏感业务操作。
6. 首版不提供弱验证恢复入口。
7. 先完善方案并落文档；2026-11-11 用户随后授权开始实施，按分阶段计划推进。
8. 登录密码调整为 **8～12 位，至少包含一个字母和一个数字**；不要求大小写同时出现，不要求特殊字符。弱密码（例如 `123456`、`aaa` 等）不能通过校验写入数据库。该写入规则统一覆盖创建、初始化、本人修改和管理员重置，不只校验修改页面。

### 1.2 本方案采用的建议默认值

以下是实施基线建议，不能记为用户逐项明确确认：TOTP 6 位 / 30 秒、挑战有效期 3 分钟 / 最多 5 次、待绑定有效期 10 分钟、安全操作密码连续失败 5 次锁定 15 分钟；已绑定用户取消长期自动登录；安全配置改变后统一撤销旧会话。

具体认证库版本、Argon2id 参数压测、前端兼容发布组合和数值配置，在实施准备任务 S0 中核验并锁定。不得因此改变第 1.1 节已确认的密码格式、解锁方式及恢复边界。

## 3. 安全目标和信任边界

可验收目标是：没有完成账号要求的认证步骤，不得产生或恢复可访问业务的会话；挑战不能冒充会话，客户端不能决定认证状态，所有人类登录入口执行同一策略。

TOTP 不提供对实时钓鱼、已登录 Token 被盗、浏览器恶意代码或服务器被完全控制的绝对防护。必须同时保持 HTTPS、前端注入防护、会话失效及部署密钥保护。当前方案不宣称“通过任何手段都不可能攻破”，也不把增加一个前端页面当作安全边界。

- 租户来自可信服务端入口和认证上下文；保持现有首版租户入口语义，不信任任意请求头或请求体中的 `tenantId`。
- 密码通过后由服务端确定 userId、tenantId、portal 及版本，写入挑战；验证接口不接受用户自行替换这些值。
- 尚未完成 TOTP 时，不创建具备 `isAuthenticated` 权限语义的人类身份。内部访问使用受控租户上下文和明确服务方法，不沿用半认证 `SmaPrincipal` 调用受保护业务。
- 超级管理员不免除 TOTP；应用身份 `/open/**` 不能兑换人类会话或管理人类安全凭据。
- 密钥、数据库或安全状态查询失败时拒绝认证，不降级为密码登录。部署开关最多关闭新绑定，不能跳过已有绑定账号的验证。

## 4. TOTP 生命周期

### 4.1 标准与登录状态机

采用 RFC 6238，建议 HMAC-SHA1、6 位数字、30 秒周期，每账号至少 160 位安全随机密钥；兼容主流验证器。使用经过审查的库并用 RFC 标准向量核验，不自定义 OTP 算法。最大时间容差为前后各一个周期，服务器配置时间同步并监控偏差。

状态顺序：`未认证 → 密码通过 / 等待 TOTP → 完整认证会话`。

1. `/api/auth/login` 先执行图形验证码、登录限流和密码校验，错误信息不泄露账号是否存在或是否绑定。
2. 未绑定账号按既有规则登录；绑定账号仅返回 `MFA_REQUIRED` 和短期挑战，不签发正式 Token，不加载权限，不执行单终端顶替，不记录最终登录成功。
3. 前端清空密码并进入独立 TOTP 页面。挑战仅存前端内存，不写 URL、localStorage、sessionStorage 或埋点；刷新或丢失挑战需重新登录。
4. 用户提交动态码和挑战；服务端重新校验挑战状态、用途、账号启用状态、portal、凭据版本、安全版本、TOTP 及账号限流。
5. 原子消费挑战及时间步后签发正式 Token，执行单终端会话替换，记录成功事件并加载用户权限。

挑战使用至少 256 位安全随机值，数据库只存 SHA-256 哈希，有效期 3 分钟、最多尝试 5 次。挑战是用途受限的能力凭据，不能被 TokenAuthenticationFilter 解析成登录 Token。

记录每个有效密钥已接受的最大时间步；同一步及更早时间步拒绝重复使用，跨挑战和跨登录同样有效。绑定确认用过的时间步也记录；紧接着登录可能需要等待下一周期，页面给出可理解的提示。

### 4.2 首次绑定、换绑与解绑

| 动作 | 前置验证 | 成功后的状态 |
| --- | --- | --- |
| 首次申请绑定 | 有效且未锁屏的完整会话＋再次验证当前登录密码 | 生成待绑定密钥与绑定挑战，尚未启用 TOTP |
| 首次确认绑定 | 同一绑定会话、挑战、版本与待绑定密钥的有效动态码 | 原子启用 TOTP，增加安全版本，撤销旧会话和旧挑战 |
| 换绑申请 | 完整会话＋当前登录密码＋当前有效 TOTP | 保留旧密钥有效，另建待确认密钥 |
| 换绑确认 | 同一会话、换绑挑战、版本与新密钥动态码 | 原子替换密钥，增加版本，撤销旧会话及挑战 |
| 解绑 | 完整会话＋当前登录密码＋当前有效 TOTP | 删除有效密钥材料并禁用，增加版本，撤销旧会话及挑战 |
| 取消或过期 | 取消只允许所属会话；过期由服务端判断 | 清除待绑定密钥，不影响原有效密钥 |

绑定挑战建议 10 分钟有效，绑定到发起会话和服务端版本；确认时重新检查会话、账号及版本。重新发起使旧申请失效，不能累积无限待确认密钥。所有写操作均校验对象归属并审计。

二维码在本地生成，不调用外部二维码服务；响应 `Cache-Control: no-store`。密钥仅在本次绑定流程展示，普通状态查询、用户列表和审计永不返回密钥。已启用的密钥不提供重新查看明文接口。

### 4.3 密钥保护

- TOTP 验证需要恢复密钥，采用 AES-256-GCM 加密，不用不可逆哈希代替密钥。
- 每次加密使用新的随机 nonce，保存版本化密文封装；AAD 绑定租户、用户、portal、用途及密钥版本。不得跨账号搬用密文。
- 密钥环和当前写入 keyId 通过受保护文件或部署密钥管理，命名空间为 `sma.auth.*`。不读取其他模块 internal 中的加密实现。
- 解密密钥不入数据库、日志、Git、前端配置或普通参数管理；数据库和密钥分别备份，明确保管权限及恢复演练。
- 轮换时保留旧密钥读取能力，分批可重入重加密并核对；完成且退出恢复窗口后再退役旧 keyId。禁止丢失旧密钥后自动关闭 TOTP。

## 5. 锁屏、会话与恢复边界

### 5.1 锁屏解锁只验证登录密码

遵循用户决定：解锁只输入并验证登录密码，不重复输入 TOTP。

但解锁必须同时满足：

1. 请求携带原正式会话 Token，且账号、租户和 portal 匹配。
2. 原会话未过期、未撤销、凭据版本和安全版本一致；绑定账号的原会话必须已完成 TOTP。
3. 会话处于锁屏状态；挑战令牌或密码第一步结果绝不能用于解锁。
4. 正确密码仅把原会话从 LOCKED 改为 ACTIVE，更新活动时间；不重置绝对过期时间、不补签新会话、不伪造或刷新 `mfa_verified_at`。
5. 解锁有独立的账号与来源限流；不允许通过正常登录或反复锁屏清空失败计数。

已过期或被撤销的会话必须回到完整登录流程；绑定账号仍需密码＋TOTP。未锁屏的重复解锁请求按无状态变更处理，不产生新的认证证明。

### 5.2 会话恢复与版本

- 正常刷新页面或恢复尚有效的会话不是新登录，不对每个请求重复验证 TOTP。
- 绑定账号建议取消长期“记住登录”，不提供信任设备免 TOTP；服务端强制处理，不能只隐藏前端选项。绝对会话期限及空闲锁屏时长在 S0 明确，解锁不延长绝对期限。
- 会话记录 IAM `credential_version` 和 auth `security_version` 快照，绑定账号还必须有 `PASSWORD_TOTP` 认证方式与有效 `mfa_verified_at`。
- 绑定、换绑、解绑、安全操作密码设置/变更/重置均提升安全版本并撤销旧会话和挑战；当前操作者也需重新登录。IAM 改密、禁用等继续按原凭据版本失效。
- REST、WebSocket 票据签发、握手及存量连接检查使用统一安全判定。同步版本检查是权限失效依据，提交后事件用于及时关闭连接和审计，不依赖异步事件完成后才拒绝。
- 旧会话缺少认证字段不能自动补成已通过 TOTP。绑定开启时撤销此前会话；新字段默认值只用于未绑定用户的兼容。

### 5.3 首版不提供弱验证恢复入口

首版不提供短信/邮件替代 TOTP、安全问题、固定万能码、备用登录码、仅密码解绑、普通管理员一键清除或使用安全操作密码替代 TOTP。

重置登录密码只改变登录密码，不清除 TOTP。丢失验证器且没有可用的已验证路径时，界面明确提示无法自助恢复，不偷偷降级认证。首次绑定前提示妥善保管验证器及其安全备份。

受控人工恢复作为后续单独方案：必须定义独立身份核验、审批角色、审计、通知及限时重绑权限后才能开放；仅能进入重绑流程，不能直接取得业务会话。本期不建设该入口，也不把“人工恢复”写成已存在能力；不得以手工改库代替恢复设计。

## 6. 安全操作密码

### 6.1 格式及交互

服务端和前端采用相同规则：

```text
长度：6～8 个 ASCII 字符
字符集：A-Z、a-z、0-9
组合：至少一个字母，至少一个数字
参考正则：\A(?=[A-Za-z0-9]{6,8}\z)(?=[A-Za-z0-9]*[A-Za-z])(?=[A-Za-z0-9]*[0-9])[A-Za-z0-9]+\z
```

上式为 Java 风格语义示意，Java 字符串需正确转义；前端使用等价的完整字符串检查，不能直接复制 Java 锚点。验收时检查末尾换行等异常输入，不能仅依赖宽松的 `$` 匹配。

大小写敏感；不 trim、不转小写、不做全角半角转换；空格、特殊字符、纯字母、纯数字和非 ASCII 字符拒绝。允许 `a1b2c3`、`Ab12Cd34` 这类格式，不要求额外的大小写组合或特殊符号。示例仅说明格式，不作为默认密码或推荐实际密码。

用户文案：`请输入6～8位字母和数字组合，且不能与登录密码相同。` 设置/修改包含确认输入；前端不持久保存密码，提交完成后清空。不存在系统默认安全操作密码。

### 6.2 不得与登录密码相同

新登录密码为 8～12 位，安全操作密码为 6～8 位，**两者在 8 位时重叠**，不能再依靠长度不同保证独立性。相等判断遵循密码验证本身的大小写敏感、原值语义，不比较两种不同算法生成的哈希字符串。

| 写入方向 | 同步校验方式 | 拒绝条件 |
| --- | --- | --- |
| 设置、修改、重置安全操作密码 | 持有凭据写锁后，通过 IAM 公开 `AccountQuery.matchesPassword` 校验候选值与当前登录密码 | 相同即拒绝，不向 auth 暴露登录密码哈希 |
| 创建、修改、重置或初始化登录密码 | IAM 在编码/写入前调用自己定义的 `AccountPasswordPolicy` SPI（拟定名），auth 实现方校验候选值与目标用户当前安全操作密码 | 已设置且相同即拒绝；确实未设置可继续；查询/解密密钥等异常不得当成未设置 |

该同步 SPI 纳入本期实施，接口属于 IAM 的公开契约，auth 只实现它，IAM 不反向引用 auth。策略适配器只依赖 auth 自有凭据读取、锁及哈希验证组件，不能再注入调用它的 IAM 用户服务造成 Spring Bean 循环。已装配 auth 安全密码能力时，策略实现缺失必须启动失败，不能以空策略列表静默跳过。新用户 ID 在服务端分配后再执行相关校验；接口不得接受客户端指定的任意归属。

同时定义 IAM 公开凭据写入协调 API（拟名 `AccountCredentialGuard`），不暴露内部 Mapper 或通用任意回调。首版可封装现有 IAM 租户级写锁，明确锁粒度与性能边界；它只在同一已有写事务中生效，校验可信租户及目标归属。两种密码所有写入口统一先取得此锁，再取得 auth 账号安全记录锁，锁持有至提交；安全操作密码比较必须读取锁获得后的最新已提交登录凭据。采用锁定读取/明确隔离语义，不能依赖事务早先建立的旧快照。不能使用仅进程内锁或提交后的事件保障不同。

并发验收：两种密码同时改成同一 8 位候选值，最终最多一笔写入成功，另一笔按最新状态拒绝；管理员重置与用户修改并发也适用。已有权限及对超管的保护保持有效，公共协调 API 不授予额外写权限。本人操作可提示“两种密码不能相同”；管理员重置对目标凭据冲突返回通用安全策略错误，不透露目标安全操作密码状态。

### 6.3 生命周期与公开能力

| 动作 | 必须验证 | 结果 |
| --- | --- | --- |
| 查询是否设置 | 有效未锁屏的人类会话 | 仅状态、修改时间及必要锁定提示，不返回哈希 |
| 首次设置 | 再次验证登录密码；已绑定账号同时验证当前 TOTP | 校验格式、两次输入一致及不同于登录密码后写入 |
| 修改 | 登录密码＋原安全操作密码；已绑定账号同时验证当前 TOTP | 独立新哈希及版本更新 |
| 忘记后的自助重置 | 登录密码＋已绑定 TOTP，且仍有完整会话 | 无需旧安全操作密码，但不得使用弱验证路径 |
| 未绑定用户忘记密码 | 不提供仅凭登录密码重置入口 | 明确提示无可用自助重置路径；可先按正常流程绑定 TOTP，再走强验证重置 |
| 后续敏感操作验证 | 完整未锁屏会话＋业务权限＋安全操作密码 | 验证失败、未设置或被锁定均拒绝 |

本期提供管理 REST API 和公开 Java 验证 API，业务从可信当前用户取得身份；不开放匿名猜测密码的接口，不允许调用方传任意用户 ID 探测密码。通用公开签名不暴露 Mapper、实体、密码哈希或框架实现。

暂不接入已有业务操作、不增加全站“已验证”状态、不实现通用操作授权票据。后续业务必须在服务端敏感操作入口校验，不能相信前端 `verified=true`。若将来确需分两次请求验证与执行，授权票据必须绑定会话、动作、对象、参数摘要及版本，短期有效、一次性消费，并与实际业务提交协调事务。

### 6.4 哈希及限流

6～8 位密码的搜索空间有限，不能仅依靠慢哈希或客户端按钮防止猜测。采用独立 Argon2id 哈希及随机盐；建议增加独立于数据库的 pepper，以带版本标识的 HMAC 预处理后再进行 Argon2id，具体实现和参数由 S0 安全评审及部署压测确定。pepper 不复用 TOTP 加密密钥，不落库；轮换需保留旧 keyId 验证能力，用户下次成功验证后迁移，丢失时不能绕过验证。

建议连续错误 5 次锁定安全操作密码验证 15 分钟，叠加账号时间窗口预算和来源 IP 限制。锁定只阻止该类验证，不自动封禁正常登录；设置/修改/重置的重新认证也分别限流。换会话、换 IP、服务重启不能清空账号级预算。限流按服务端时间和共享原子状态执行，避免无限续锁造成持久拒绝服务。

### 6.5 登录密码：8～12 位及弱密码拒绝

#### 格式与校验顺序

新登录密码长度为 8～12 位（含边界），至少包含一个 ASCII 字母及一个数字；不要求同时含大小写。建议新设值沿用字母数字字符集 `A-Z / a-z / 0-9`，不增加特殊字符要求；该字符集选择是实施建议，历史已设置的特殊字符密码仍按原值验证。前后端使用同一明确契约，禁止 trim、大小写转换、截断或全角半角转换后再存储。两次输入确认一致仅是交互检查，不能代替服务端策略。

服务端在任何登录密码编码和持久化之前依次执行：**必要授权及旧凭据验证 → 长度/字符/组合 → 弱密码检查 → 与安全操作密码不同 → 编码写入**。依赖查询异常时拒绝写入。错误不会修改原哈希、凭据版本或会话，不产生“改密成功”事件；成功才沿用凭据版本递增和会话失效。

用户提示：`登录密码为8～12位，须同时包含字母和数字，不能使用常见弱密码，也不能与安全操作密码相同。` 不以模糊的前端强度分数代替硬性服务端判定，不引入特殊字符、混合大小写或强制更长等额外复杂度要求。

#### 弱密码判断

`123456`、`aaa` 本身会被长度和组合规则拒绝，但只修改正则不足以识别满足长度的弱密码。首版增加可版本化的本地弱密码规则与词表：

| 类别 | 判定规则与示例（仅供拒绝用例，不是可用密码） |
| --- | --- |
| 格式不合格 | `123456`、`aaa`、`12345678`、`abcdefgh` 拒绝，分别命中长度或字母数字组合规则 |
| 常见字典及键盘/顺序组合 | 本地词表至少覆盖 `password1`、`Password123`、`admin123`、`qwerty12`、`abc12345`、`123456ab` 及大小写变体；完整词表在 S0 固定版本及来源，不把这几个示例当成全部覆盖 |
| 整串短周期重复 | 整个密码由长度 1～4 的短串重复两次及以上组成则拒绝，例如 `ab12ab12`、`a1a1a1a1`；不因为随机密码内部偶然出现一段重复就拒绝 |
| 简单重复字符拼接 | 整串为同一字母重复至少 3 次＋同一数字重复至少 3 次，或反向排列，则拒绝，例如 `aaaa1111`、`1111aaaa` |
| 与账号直接相关 | 候选值等于用户名，或等于用户名＋1～4 位数字 / 1～4 位数字＋用户名时拒绝（完整候选同时落在 8～12 位）；使用目标用户的可信用户名，不能使用操作者用户名 |

弱密码词表和上述模式使用候选值的临时 ASCII 小写副本进行匹配，防止仅改大小写通过；**实际密码哈希、登录校验和两种密码相等判断仍按原始大小写敏感值处理**。词表由 IAM 持有，作为经过审查的本地版本资源随制品交付，记录来源、许可证、版本和摘要；不上传用户密码或哈希到第三方接口。内置词表缺失/损坏时不得启动接受新密码写入的服务，不能静默关闭检查。无需新增保存明文密码或弱密码样本的业务数据库表。

词表更新与规则回归纳入发布检查；不能声称有限词表可以识别所有可猜测密码。格式合法且未命中词表、模式或账号关联规则的值可通过弱密码检查，例如用于测试的 `m7K2v9R4`；测试样例不作为生产默认口令。弱密码规则在本次新增范围中针对登录密码，安全操作密码保持第 6.1 节的格式与第 6.4 节的限流设计，不混淆两种长度策略。

#### 所有写入口一致执行

| 入口 | 约束 |
| --- | --- |
| 本人修改登录密码 `/api/iam/users/me/password` | 验证旧密码及授权后，执行完整新密码策略；同一事务中双向不同校验后写入 |
| 管理员重置 `/api/iam/users/{id}/password` | 已有权限/目标保护继续有效；管理员不能跳过格式、弱密码或与安全操作密码不同的检查 |
| 创建用户 `/api/iam/users` | 初始登录密码也执行相同规则，不能通过创建接口写入弱密码 |
| 初始化管理员 `bootstrap` | 首次实际创建前执行同一策略，环境变量不免校验；失败明确报配置错误且不生成账号/默认口令，不在日志打印候选值 |
| 未来导入、批量创建或新增内部入口 | 必须调用 IAM 统一策略和凭据写服务；禁止 Controller、Mapper、SQL 导入或直接 PasswordEncoder 写入未经校验的候选值 |

应用通过服务层门禁保证受支持写入口不接受弱密码；不声称数据库能从 BCrypt 哈希还原并判断强度。数据库运维权限单独治理，不提供绕开策略的明文/哈希导入接口。

#### 历史密码及前端兼容

新规则应用于本次功能上线后的新设、修改和重置。旧密码可能超过 12 位或包含特殊字符，数据库只有哈希，不能凭长度字段或哈希内容扫描出其原值，也不能截断、强行重写或假定已经合规。

历史账号登录、锁屏解锁以及绑定/改密时验证旧密码，保留原有输入容量及原值匹配能力，不能套用新密码 8～12 位校验而锁死旧用户。当前方案不新增全量强制改密；用户下一次修改/重置时必须通过新策略。用户若另行要求历史弱密码清退，需单独设计受限改密流程，不能偷偷绕过 TOTP。

新旧前端中“新密码”的帮助文案、长度限制、确认输入和校验工具同步更新；“旧密码”“登录密码验证”“解锁密码”输入不使用新设值的最大长度限制。登录密码继续使用 IAM 既有 BCrypt 存储，安全操作密码使用独立哈希；本次策略调整不更换旧哈希算法、不需要修改 IAM 密码列。

## 7. 并发、事务及审计

所有登录最终签发、绑定/换绑/解绑和安全凭据变更均围绕同一账号安全记录串行化；首次创建记录采用唯一约束处理并发，再取得行锁。未绑定用户的直接签发也必须进入该临界区，防止与开启 TOTP 并发时拿到错误版本的密码单因素会话。

涉及两种密码写入时，执行第 6.2 节统一顺序：IAM 凭据写锁 → auth 账号安全锁 → 最新凭据读取与比较 → 写入并提交；不得先持有 auth 锁再申请 IAM 写锁。登录等只需 auth 锁的流程不在持锁后调用会取得 IAM 写锁的方法。安全操作密码验证依赖自身已提交版本；不通过异步事件补救两种密码已经写成相同值的情况。

第二步成功路径在同一事务中完成：锁定相关状态 → 重新校验账号和版本 → 原子接受新的时间步 → 消费挑战 → 创建正式会话。任何一步失败都不能留下已授权半成品。挑战保存的是第一步版本快照，禁止重读新版账号后将旧密码证明自动升级为新版本。IAM 在检查之后变更的情况，仍由每次请求的凭据版本检查拒绝旧快照会话。

失败计数必须在错误响应之前可靠提交；不能把计数更新放入随后抛出异常并回滚的同一事务。实现可使用明确的独立事务或返回失败结果后提交，由 S1/S2 测试验证。固定锁顺序，失败计数、挑战消费和密钥行更新不得形成死锁循环。

保留既有登录/操作审计，补充挑战失败、锁定、绑定、换绑、解绑、密码设置/修改/重置及会话撤销事件。密码第一步通过只记阶段事件，不能记最终 SUCCESS。失败审计不得随认证事务回滚丢失；记录可信租户、用户标识、动作、结果、来源与关联 ID，不记录密码、动态码、二维码、密钥、哈希、Token 或完整请求响应。

客户端写入超时不盲目重试。登录挑战若已消费但 Token 响应丢失，重新开始登录，不二次兑换；绑定等操作重新查询状态，旧会话失效则按新流程登录。来源 IP 仅信任受控代理配置，不能直接相信任意转发头。

## 8. 数据设计

本节是逻辑/字段设计，不是已发布 DDL。所有新表继承本仓库 `TenantEntity` 约定：`id BIGINT`（assign_id）、`tenant_id BIGINT`、创建/更新人和时间、`deleted TINYINT(1)`；InnoDB、utf8mb4；时间为 UTC `DATETIME(3)`。列的空值、默认值和约束在 S1 完整 DDL 中验证。

### 8.1 新表

| 表 | 主要业务字段 | 约束与索引 |
| --- | --- | --- |
| `auth_user_security` | `user_id BIGINT`、`portal VARCHAR(32)`、`security_version BIGINT NOT NULL DEFAULT 0` | 每账号有效记录唯一，用作串行化锁与安全版本源 |
| `auth_totp_credential` | `user_id`、`portal`、`status VARCHAR(16)`、`secret_ciphertext TEXT NULL`、`key_id VARCHAR(64) NULL`、`last_accepted_step BIGINT NULL`、`enabled_at DATETIME(3) NULL`、`pending_secret_ciphertext TEXT NULL`、`pending_key_id VARCHAR(64) NULL`、`pending_challenge_id BIGINT NULL`、`pending_expires_at DATETIME(3) NULL` | 每账号有效记录唯一；待绑定过期清理索引；ENABLED 必须有完整密文和 keyId |
| `auth_security_password` | `user_id`、`portal`、`password_hash VARCHAR(255)`、`pepper_key_id VARCHAR(64) NULL`、`credential_version BIGINT`、`changed_at DATETIME(3)` | 每账号有效记录唯一；无记录表示未设置，不能回退到登录密码 |
| `auth_challenge` | `token_hash BINARY(32)`、`user_id`、`portal`、`purpose VARCHAR(32)`、`source_session_id BIGINT NULL`、`account_credential_version BIGINT`、`security_version BIGINT`、`expires_at`、`consumed_at DATETIME(3) NULL`、`attempt_count INT`、服务端确定的会话策略快照 | 令牌哈希唯一；租户/过期时间清理索引；用户/用途检索索引 |
| `auth_throttle` | `scope VARCHAR(32)`、`subject_hash BINARY(32)`、`failure_count INT`、`window_started_at`、`locked_until DATETIME(3) NULL` | 租户/用途/主体有效记录唯一；窗口及锁定清理索引 |

`user_id` 均为 BIGINT，`portal` 均为 VARCHAR(32)。账号凭据有效唯一键包含 `tenant_id`、`user_id`、`portal`，按仓库既有 `active_*` 生成列方式支持软删除后重建；索引命名使用 `uk_` / `ix_` 并检查 MySQL 长度限制。挑战 token_hash 为二进制精确比较，不受默认大小写不敏感排序规则影响。

TOTP 未启用时有效密文可空，待绑定状态独立；换绑期间原密文和时间步仍有效。解绑及时清除密钥材料而非只打软删除标记，审计保留动作元数据。挑战用途至少区分 LOGIN_TOTP、TOTP_ENROLL、TOTP_REPLACE；用途不匹配一律拒绝，不建设可绕过强验证的通用挑战。

不对 IAM 表建跨模块外键、join 或直接 Mapper 查询。auth 仅拥有自己的凭据；IAM 用户删除后的清理通过公开事件和可信租户处理，立即失效依靠账号状态检查。

### 8.2 扩展 `auth_session`

新增 `security_version BIGINT`、`authentication_method VARCHAR(32)`、`password_verified_at DATETIME(3)`、`mfa_verified_at DATETIME(3) NULL`。认证方式使用明确枚举，例如 PASSWORD、PASSWORD_TOTP；不能由前端传值。

原 `credential_version` 保留。迁移初期为旧会话采用安全默认值，但绝不伪造 MFA 时间；未绑定旧用户兼容策略和开启绑定时强制失效在 S1/S2 验证。API 中 Long ID 继续按字符串传输。

## 9. 接口与前端契约

以下均为拟定契约，未实现。沿用 `ApiResponse`、显式权限注解和现有错误码/i18n 规范。

| 接口 | 登录要求 / 作用 |
| --- | --- |
| `POST /api/auth/login` | 匿名入口；校验第一步，返回完整登录或 MFA_REQUIRED |
| `POST /api/auth/login-challenges/verify` | 匿名可达但必须验证挑战；仅完成对应 TOTP 登录 |
| `GET /api/auth/security-settings` | 完整未锁屏人类会话；查询绑定与安全密码状态 |
| `POST /api/auth/totp-enrollments` | 强重新认证；发起首次绑定或换绑，服务端决定类型 |
| `POST /api/auth/totp-enrollments/confirm` | 所属会话＋挑战＋新密钥动态码；确认绑定 |
| `POST /api/auth/totp-enrollments/cancel` | 所属会话取消；不影响旧有效密钥 |
| `POST /api/auth/totp-credentials/disable` | 登录密码＋当前 TOTP；解绑，不在 URL 传密码 |
| `POST /api/auth/security-passwords` | 首次设置，必须满足第 6 节前置验证 |
| `PUT /api/auth/security-passwords` | 修改，必须验证旧安全操作密码等条件 |
| `POST /api/auth/security-passwords/reset` | 仅登录密码＋已绑定 TOTP 的强验证重置 |
| `POST /api/auth/unlock` | 保留既有接口；仅验证登录密码及原完整会话，详见第 5.1 节 |

新客户端以 `data.status` 区分：

```text
AUTHENTICATED: status, token, expiresAt
MFA_REQUIRED:  status, challengeToken, expiresAt
```

MFA_REQUIRED 不包含 token、权限、菜单或用户敏感详情。旧客户端不认识该分支时必须失败，不能收到一个可访问业务的临时 Token。未绑定登录保留 token / expiresAt 原字段，严格 DTO 客户端仍需实际兼容验证。

公开路径只精确增加挑战验证端点，不能放开整个 `/api/auth/**`。设置类 API 使用登录注解加人类身份、未锁屏、重新认证和归属校验，关键动作显式审计；授权异常不以 HTTP 200 表面成功掩盖。

新版前端新增 TOTP 验证页和个人中心安全设置，并同步创建用户、修改/重置登录密码的 8～12 位规则及弱密码错误提示。显示挑战过期、错误、限流、绑定待确认及提交状态；写入期间禁重复点击，服务端仍执行幂等/并发保护。所有文案和 aria-label 同步 zh-CN/en-US，覆盖明暗主题和移动端。

旧前端作为兼容基线做最小登录状态与 TOTP 页面适配，同时更新新设登录密码规则并回归仅密码锁屏解锁及旧密码输入兼容，不搬迁重写旧工程。如决定停用旧版入口，应作为发布决策明确记录，不能隐含假设。

## 11. 发布、兼容和回退

1. 备份当前制品、数据库形状及密钥，记录版本组合。先追加兼容迁移，不修改既有迁移。
2. 部署支持二步验证的全部后端节点，并检查旧节点已退出；未完成前禁止开放绑定。
3. 发布并验证新旧客户端组合、代理路径、匿名精确白名单、WebSocket 及锁屏；严格客户端未知枚举失败需要明确处理。
4. 配置并验证密钥可读性、恢复能力和时间同步，再开放用户绑定。
5. 已存在绑定数据后，禁止回退到不识别 TOTP 的后端，也不能关闭功能开关来免除 TOTP。只允许回退到具备同等安全强制能力且兼容当前 schema / keyId 的已验证制品；否则隔离流量并修复。
6. 数据库回退单独处理，不假设 MySQL DDL 可事务回滚；备份恢复必须同时考虑安全版本、挑战消费及密钥时间点，恢复后撤销潜在旧会话/挑战，不能复活已消费认证凭据。
7. 登录密码策略必须与双向不同 SPI、写锁和词表同批生效；旧节点未退出前不可开放 8 位新密码写入。回退制品也必须强制弱密码拒绝及两种密码不同，不能退回只支持旧长度/无弱密码校验的写入口。校验初始化配置中的密码是否满足新策略，但不自动替换已存在账号凭据；恢复与回归覆盖超过 12 位/含特殊字符的旧密码登录和解锁。

本方案让认证挑战和限流具备共享持久状态，不代表整个系统完成集群化；现有 WebSocket 分发等仍遵循其单实例边界，不能仅复制进程即声称集群可用。

### 12.1 不可省略的拒绝路径

| 类别 | 必须证明的结果 |
| --- | --- |
| 半认证 | 密码正确但无 TOTP 时不签发会话；挑战作为 Bearer 请求 me、业务、文件、WebSocket 票据和 unlock 全部失败 |
| 重放与并发 | 同一码、同一步、同一挑战最多一次成功；多挑战、多实例竞态不能扩大账号预算 |
| 版本竞态 | 第一步后改密/禁用/绑定/换绑不能用旧挑战登录；未绑定直接登录与绑定并发不能生成可用单因素旁路 |
| 旧入口 | 旧客户端、超管、已有 Token、锁屏、应用身份不能绕过已绑定策略 |
| 锁屏正向 | 完成认证的有效锁定会话用正确登录密码解锁，无需 TOTP；MFA 时间和绝对过期时间不变 |
| 锁屏拒绝 | 无原 Token、挑战 Token、过期/撤销/旧版本会话，即使密码正确也不能解锁或续期 |
| 安全操作密码格式 | 6/7/8 位合规字母数字通过；5/9 位、纯字母/数字、特殊符号、空白、末尾换行、Unicode 拒绝；不要求大小写混合 |
| 登录新密码格式 | 8/9/10/11/12 位非弱字母数字组合通过；7/13 位和纯字母/数字拒绝；不要求大小写混合；字符集按第 6.5 节最终契约测试 |
| 弱密码拒绝入库 | `123456`、`aaa`、`12345678`、`abcdefgh`、`password1`、`Password123`、`admin123`、`qwerty12`、`abc12345`、`123456ab`、`ab12ab12`、`a1a1a1a1`、`aaaa1111`、`1111aaaa` 及账号直接关联值拒绝；覆盖创建、修改、重置和首次初始化，原哈希/版本不变、无成功事件 |
| 密码独立 | 任一种密码的新值等于另一种时拒绝；候选为同一非弱 8 位值并发修改时最多一方成功；管理员重置同样生效；真实未设置与读取异常分开处理 |
| 词表与契约故障 | 词表缺失/损坏、已装配能力缺少策略实现、读取/验证异常均不得跳过检查；模式不误伤仅内部偶然重复的非弱候选；大小写仅弱密码检测归一化 |
| 历史密码兼容 | 原有超过 12 位或含特殊字符密码仍可登录、解锁及验证旧密码；修改后的新密码必须满足新规则；不截断旧值或把已有哈希标为已通过新规则 |
| 锁定与错误 | 错误计数不回滚、不因换 IP/重启清空；安全密码未设置不能通过；限流状态不跨租户污染 |
| 强验证管理 | 只有登录密码不能解绑/换绑已启用 TOTP，也不能重置已绑定用户的安全操作密码；管理员重置登录密码不移除 TOTP |
| 故障与泄露 | 密钥缺失、解密/存储异常拒绝认证；日志、审计、导出、普通 API 无明文凭据及二维码 |
| 数据恢复 | 恢复旧备份不能复活已失效会话或挑战；不支持 TOTP 的旧制品不可接入绑定用户流量 |
