## 1. 设计判断

当前 `src/styles/theme.css`、`layouts/AdminLayout.vue` 已有语义主题、明暗模式和 shadcn-vue 基础组件。传统感不主要来自技术栈，而来自连续的导航层、重复的容器边框、近似等重的卡片与偏弱的版面主次。

建议把方向定为 **Softlight Workspace / 柔光工作空间**：雾白底、石墨文字、鸢尾紫主色，使用留白和字体建立层次，使用局部柔光与半透明材质建立识别度。它应同时适合有表现力的工作台和长时间阅读的业务表格。

| 层次 | 设计方式 | 典型位置 |
| --- | --- | --- |
| 品牌与情绪 | 柔和色场、抽象轨道雕塑、少量玻璃浮片、大标题 | 登录页、工作台欢迎区、空状态 |
| 工作空间 | 安静侧栏、轻量面包屑、清晰选中态、低对比边界 | 管理壳、导航、个人区域 |
| 高频任务 | 实色表面、明确列头、稳定行高、单一主操作 | 列表、筛选、表单、权限树 |
| 状态与反馈 | 语义色 + 文字/图标；原位反馈、明确保存状态 | 待办、错误、保存、禁用态 |

## 3. 主题与组件语言

默认推荐 **鸢尾紫**，同时提供 **青瓷绿**、**琥珀棕** 的可切换样例。选择品牌主色与选择明暗模式相互独立。青瓷绿更接近当前品牌；鸢尾紫与现有界面的区别更明显。

| Token / 规则 | 浅色默认 | 深色默认 |
| --- | --- | --- |
| 页面背景 | `#F6F7FA` | `#15161D` |
| 内容表面 | `#FFFFFF` | `#1D1E28` |
| 主文字 | `#252638` | `#EEEEF4` |
| 主色 | `#6B55C7` | `#B7A4FF` |
| 轻选中背景 | `#EEE9FC` | `#332B4B` |
| 次级文字 | `#707180` | `#A3A3B4` |
| 边界 | `#E9E9F0` | `#30313D` |
| 成功 / 警示 | 各自独立语义变量 | 各自独立语义变量 |

- 圆角按用途分层：控件约 8–10px，数据容器 13–14px，品牌区域 17–20px；不把所有区域都做成同样的大圆卡片。
- 标题约 24–30px；主数据 28–32px；数据表正文 13px、次级身份 12px；装饰英文小字不承载关键操作。正式落地建议提供标准/舒适密度，继续验证中文长文本和 200% 缩放。
- 间距采用 4px 基准；桌面内容边距约 32–40px，移动端 18px。信息组间留白大于组内间距。
- 主按钮有清楚的实色填充；次级按钮细边界；普通行操作使用低强调图标或文字。删除等危险行为继续使用独立 destructive 语义。
- 图标使用现有 Lucide；头像用身份首字及柔和底色。立体几何为装饰，不表达权限、告警等业务语义。
- 模糊只用于少数浮层；弱设备/不支持 `backdrop-filter` 时保留半透明或实色底；正式版进一步验证降级后的文字对比度。

## 4. 四页样板各验证什么

**工作台**：欢迎区建立视觉识别；四项指标提供快速扫描；趋势和待办以不等宽布局区分主次；快捷入口减少查找。趋势数字由同一组模拟数据计算。正式版指标只能映射现有 API 可提供的事实，缺项不伪装成已交付能力。

**用户管理**：柔光概览让页面有品牌感，表格采用实色与水平分隔。姓名与邮箱合并为身份列，状态有文字，筛选与主操作分开。已实现本地搜索、启用状态过滤、选中计数、空结果、添加成员表单预览；表单不创建账号、不发送邀请。

**角色权限**：左侧角色，右侧权限范围，权限按模块分组。选中数量和保存区域可见；角色间切换保留样板内临时勾选。实际权限树的独立勾选、隐藏选择、禁用项、未保存拦截及服务端授权规则必须原样保留，本样板不证明这些真实规则已迁移。

**登录页**：左侧品牌叙事与柔光雕塑，右侧安静表单。移动端压缩品牌区，保留完整表单。登录请求关闭，不读取或存储真实凭据。生产迁移需完整保留当前认证与安全状态，不改变后端协议。

## 5. 动效与响应式

- 本版有约 180ms 的颜色/表面反馈及约 350ms 的轻页面切入；“我的待办”支持平滑定位。减少动态效果偏好下关闭动画和滚动动效。
- 正式版建议按钮/选择状态 120–180ms、抽屉/对话框 180–240ms、局部内容入场不超过 350ms。数据更新保留原布局，不使用大幅飞入。
- 目前柔光背景与雕塑为静态。若希望更强动感，确认后可在登录页增加低频局部光场移动，并按可见性、减弱动态偏好和设备能力暂停。管理列表不加持续动画。
- 桌面完整侧栏；中宽屏缩成图标栏；手机抽屉。手机指标两列、主体区域一列，表格仅在容器内部横向滚动。
- 本版演示 Ctrl/Cmd+K 定位成员搜索、Escape 关闭原生表单对话框/手机导航。正式版导航与弹层迁回现有可访问性组件，继续验证焦点约束和返回。

## 6. 确认后才执行的重构顺序

1. **确认基调**：默认品牌色、柔光/玻璃强度、页面密度，以及是否接受登录页品牌表达。
2. **主题层**：统一 `theme.css` 的语义变量、明暗与品牌组合、字体/间距/材质 token。保留现有主题偏好键的兼容性，不重置用户偏好。
3. **管理壳**：调整 `AdminLayout`、导航、顶栏、工作标签、页脚。当前样板省略了业务顶部导航与工作标签，生产版必须保留其功能；建议合并视觉层级，标签行按用户偏好显示，不能直接删功能。
4. **基础与业务组件**：原位完善已有 Button/Input/Select/Dialog/Sheet/Table，以及 PageHeader、FilterBar、DataTable、EditorDialog 等组合。统一焦点、加载、错误、禁用、空状态、校验和密度。
5. **先迁移四个代表页面**：工作台、用户、角色、登录，接入现有 API/i18n/权限，确认通过后按页面类型迁移其他路由。
6. **覆盖完整路由并验收**：28 个现有路由按实际清单回归；明暗/中英/窄屏、键盘、200% 缩放、滚动与长表单；模拟 API 与真实后端分别记录。执行现有 verify 与相应 e2e/real 门禁。
7. **发布与回退**：正式静态包单独构建校验，保留旧产物、原部署指向、现有 UI 偏好兼容。数据库、后端授权和热插件发布链不因视觉改版而更改。

这属于基座管理壳与通用 UI 维护，可在基座主线交付；样例仅使用通用用户/角色/工作台概念，不引入业务二开模块。本轮只新增独立预览及提案文件，保留已有未提交改动。
