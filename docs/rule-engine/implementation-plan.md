## 1. 技术接入决定

**规则界面确定在现有 Vue 3 工程 `frontend-next/` 实现，采用 Vue Flow 作为流程画布，Monaco 作为表达式编辑器。** 管理页面继续使用现有 shadcn-vue / Reka UI、Tailwind、Pinia、Vue Router、VeeValidate 与 Zod 体系。后端推荐组合仍为 LiteFlow + QLExpress 4，通过 RE0 锁定具体发行版本及接入实现。

“确定采用”指技术方案选择；“当前工程已成功集成”需要 RE0 的安装、构建与浏览器证据。截止本计划制定时，只完成代码 / 约束检查与包元数据核验，未安装上述新依赖。

### 1.2 next 中的接入方式

- 页面与领域状态建议放在 `frontend-next/src/features/rule/`；画布与表达式封装为 `RuleFlowEditor`、`RuleExpressionEditor`，由统一规则编辑页使用。
- Vue Flow 只管理画布节点、边、选择和布局事件；平台领域模型是数据源，保存时校验并转换，避免把库的运行时内部对象当成长期业务格式。
- Monaco 直接使用 ESM，配置 Vite 同源 Worker。只加载编辑器基础及所需规则语言支持，实际包体由构建验证；不加载不需要的 TS / JSON 等完整语言服务。
- 规则路由延迟加载；进入表达式 / 流程编辑模式时再加载对应编辑器。运营模板目录和参数表单页面不下载 Monaco / Vue Flow。
- 双向绑定由封装层控制，区分用户输入、外部版本载入、只读查看和模拟定位，避免响应式更新形成循环或覆盖未保存内容。
- 复用现有业务参数表单和 Zod 4 适配方式；服务端参数约束为权威，不能将前端校验实现当作服务端契约。
- 画布使用 next 主题变量；Monaco 使用显式编辑器主题同步，不依赖全局 CSS 强行覆盖其内部布局。明暗切换、英文、字体缩放和全屏工作区分别验证。
- 路由离开和用户切换时释放 Monaco model / listener、Vue Flow 实例及后台任务；Provider 按语言受控注册，避免全局重复注册或跨用户串模型。
- 针对标签关闭 / 重新打开、编辑模式切换、隐藏标签恢复和容器变尺寸处理布局。草稿是否可离开统一接入 next 的确认与保存反馈机制。
- 桌面承担完整专业编辑；窄屏优先查看、模拟和运营参数调整。复杂画布与代码编辑提供可达入口和明确布局，不承诺手机具备完整桌面编辑体验。

### 1.3 不能推迟到后期的基础能力

租户与权限、输入类型和金额精度、不可变版本、草稿冲突、发布与停用、最小回滚、执行错误区分、表达式访问和资源边界、参数隔离从第一个可用版本开始具备。后期增强的是批量治理、灰度和集群等能力，不是补救首期缺失的数据隔离。

## 2. 分期原则与发布里程碑

采用“每期交付可执行闭环”，避免先把所有列表和编辑页面做完再补后端执行。四种编辑方式保持总目标，但不要求在第一个可用版本一次交齐。

| 阶段 | 优先级 | 用户可见结果 | 依赖与发布里程碑 |
| --- | --- | --- | --- |
| RE0 接入验证与契约冻结 | 最高，先行门禁 | 取得画布 / 表达式集成证据和统一执行契约 | 无；验证通过才进入开发基线，非业务发布 |
| RE1 首个可用闭环 | 最高，核心能力 | 专业人员用表达式 / 条件制作模板；运营选用、填参、试算；可发布执行和回滚 | RE0；M1 内部可用版本 |
| RE2 可视化流程编排 | 高 | Vue Flow 编排串行、分支、表达式和子规则，逐节点查看执行 | RE1；M2 流程编排版本 |
| RE3 决策表与模板复用 | 高 | 四种编辑方式齐备，表格进入流程，模板升级有差异和迁移预览 | RE2 的组合入口及 RE1 版本体系；M3 标准功能版本 |
| RE4 管理与运行增强 | 中 | 用例批跑、影响分析、批量参数迁移、更完整监控与执行查询 | M3；M4 治理增强版本 |
| RE5 按场景扩展 | 需求驱动 | 复杂组合、受控并行、灰度、集群、外部应用或标准交换 | 针对需求分别准入，不要求一次全做 |

顺序说明：专业配置者用表达式可以先覆盖判断与计算，条件构建器提供常用判断；模板 / 实例闭环让运营尽早用起来。流程编排是第二个重点里程碑，决策表随后补齐。RE0 同时验证两种编辑器，让流程组件的接入问题提前暴露，而非拖到 RE2 才发现。

## 3. RE0：接入验证与最小契约

### 3.1 任务

1. **RE0-01 基线与版本**：记录当前 next 和后端依赖基线、相关未提交修改；隔离验证工程，核验候选版本 LICENSE 和 peer 依赖，禁止强制绕过依赖检查。
2. **RE0-02 Vue Flow 验证**：在 next 同等工具链上绘制开始、条件、结果，增删连接，导出 / 重新载入；验证自定义节点、错误定位、容器变化、主题及样式隔离。
3. **RE0-03 Monaco 验证**：在 next 同等工具链上按需加载、Worker 本地打包、受控规则语法高亮、字段 / 函数补全、行列错误和多模型隔离；验证切页释放。
4. **RE0-04 后端组合验证**：Java 21 / Boot 4.1 / Jackson 3 下运行 QLExpress 4 的十进制、空值和访问限制样例；LiteFlow 用受控 Java 节点调用同一适配器，检查多版本隔离。
5. **RE0-05 契约冻结**：定义 `input / params / context`、输入输出类型、原因码和错误类别，规则 / 模板 / 实例 / 绑定修订、受限 AST / 图模型和版本策略。
6. **RE0-06 验证决策记录**：记录版本、依赖树、构建与浏览器证据、包体积、限制及退出结论，决定是否进入正式工程。

### 3.2 验收

- Vue Flow 的保存载入、连线与主题交互真实可用；Monaco 的编辑、补全、诊断及 Worker 无运行错误。
- 在当前 next 工具链构建成功，不通过降低 TS 严格性、全局关闭检查或使用强制安装解决冲突。
- 暂存发布产物在既有 base 路径与同源静态资源部署方式下运行，Worker 和懒加载资源不出现 404；后续离线不依赖 CDN。
- 记录编辑器入口、Worker、CSS、首次加载与重复进入成本；保留既有首页门禁，不把编辑器隐藏在动态加载后就宣布总体体积合格。
- 后端推荐组合跑通可复现的表达式节点；能力边界、精度与失败行为有证据。
- 有明确结论才锁定正式依赖；如出现实际阻碍，记录具体问题并先解决封装或版本冲突，不悄悄换掉技术方案。

| 任务 | 交付内容 | 验收要点 |
| --- | --- | --- |
| RE1-01 模块与持久化底座 | `rule` Modulith 模块、Flyway、规则 / 模板 / 实例版本、草稿修订及发布记录 | 模块与租户约束通过；不跨业务模块查表 |
| RE1-02 场景与能力目录 | 最小输入输出契约、字段 / 枚举、预注册纯函数、参数定义 | 能查询可用能力；缺失、空值与类型错误行为明确 |
| RE1-03 表达式规则 | Monaco 编辑、服务端语法 / 能力校验、输入输出校验、模拟与基础追踪 | 保存不执行；模拟不写业务数据；非法能力被拒绝 |
| RE1-04 条件规则 | 受限嵌套 AND / OR / NOT、类型化比较及明确结果 | 基本边界、空值、短路正确；与表达式共用数据契约 |
| RE1-05 专业模板制作 | 从表达式 / 条件封装模板，参数 Schema 与最小参数表单配置、说明和用例 | 至少两个模板可选择；逻辑版本及参数表单一起发布 |

| RE1-07 执行 API 与缓存 | 内部 Java API、可信上下文、固定实例 / 模板 / 依赖版本、受控有界缓存 | 同一请求不混版本；调用不能覆盖模板参数或租户 |
| RE1-08 最小发布治理 | 并发编辑保护、模板与实例发布分权、停用、单实例版本回滚、最小操作审计 | 加载失败维持旧版；模板 v2 不自动影响 v1 实例 |
| RE1-09 next 页面与联调 | 规则 / 模板编辑、目录、实例、最小发布 / 执行详情；接入权限、i18n 与时区 | 真实后端闭环通过；模拟页面证据单独记录 |

### 4.2 范围边界

首期采用单实例部署能力、内部同步纯计算、单次调用选择一个使用实例；绑定多个候选时只支持明确的确定性单选策略或拒绝冲突。流程图和决策表编辑入口在对应期可用后才出现，不挂空页面。

参数表单首期支持必要的数字、比例、枚举、字符串、布尔和授权对象选择，具备基本分组、必填、默认值和范围校验；不先建设独立通用低代码表单设计平台。

以商品折扣机制为验证样例时，制作“固定比例折扣”和“满额比例折扣”两个示范模板。默认采用单品行、单币种、单实例及已明确舍入口径，作为待业务确认的演示契约，不替代用户具体促销规格。

若现有工程无商品 / 活动模块，使用隔离联调调用方验证绑定授权和执行契约，不能为完成样例新建整套电商系统。M1 的“平台可用”与“真实业务生产上线”分别记录：后者仍要求业务方完成实际接入和口径验收。

### 4.3 验收场景

1. 开发人员发布两种模板，运营可选择其中一种并建立实例；同一模板的两个实例可以使用不同参数。
2. 运营试算得到结果与原因；保存草稿不生效，发布后新请求使用新修订，旧请求保持原修订。
3. 修改模板产生新版本，不影响已有实例；改实例参数重新试算并发布；可切回此前仍有效的实例版本。
4. 越权编辑模板、跨租户执行、伪造业务绑定、非法参数、并发覆盖和调用覆盖参数被服务端拒绝。
5. 无命中、输入错误、未配置、停用、超时和引擎错误能分别识别，日志有脱敏和访问权限。
6. next 主题、语言、保存失败保留草稿、标签关闭、重复进入、窄屏参数操作通过浏览器验证。

验收：专业人员在 next 从零配置流程并成功保存、模拟、发布为模板，运营选用后真实 API 执行；对分支、子规则失败、非法连接、旧版本回滚和重复进入编辑器完成检查。

| RE4-05 性能与运维验收 | 编译与执行基准、容量边界、清理归档、备份恢复与故障演练 | 真实端到端与纯计算指标分开记录，有可执行运行手册 |

首期已有的权限、审计、回滚和单次模拟持续保留；本期扩充规模化管理与可维护性。

## 8. RE5：后续按需求拆分

以下各项独立立项，不绑定同一大版本，也不作为 RE1～RE4 的交付前置：

- **组合计价**：叠加、择优、互斥组、整单分摊和退款回放；实际促销需求确认后固定口径。
- **受控并行**：分支数据隔离、汇合、超时、失败策略及资源限制。
- **多环境 / 灰度 / 集群**：节点就绪、修订一致性、灰度路由、回滚与撤销传播；验证后才宣称集群能力。
- **外部应用调用 / 事件 / 批处理**：应用鉴权、限流、幂等、任务恢复和审计。
- **标准交换或复杂推理**：DMN / FEEL 与 dmn-js，或 Drools；与现有语义边界分别验证。
- **评分卡与跨租户模板分发**：按具体业务、授权及契约版本处理。

## 9. 跨阶段开发与验收规则

### 9.1 依赖和数据演进

RE0 提前设计可扩展制品类型与结构版本，RE1 只实施必要表和功能；不能为了“以后可扩展”一次创建所有空接口与表。后续 Flyway 只追加迁移，已有规则 / 模板 / 实例版本内容不可原地改写。

前端菜单按阶段上线，仅展示实际可用且有权的功能。新规则路由维护独立清单与测试，不通过修改旧前端源码让迁移清单勉强包含新功能；需要调整检查器时保留既有保护并增加新模块覆盖。

业务对象绑定验证通过宿主定义的受控授权契约完成，避免规则模块为了查询商品 / 活动而反向依赖所有业务模块。相关 SPI 如需跨模块贡献，按现有 common 命名接口模式设计并做无环验证。

### 9.2 每期完成的定义

每项任务按“实现 → 适当验证 → 记录证据 → 标记完成”推进。状态采用待开始、进行中、实现待验证、完成；阻塞记录具体原因和可继续任务。

- 后端：Maven verify、Modulith 与架构约束、类型 / 租户 / 权限 / 发布语义和真实执行测试。
- next：当前 verify、baseline 与新增规则路由覆盖，编辑交互与真实后端联调；修订检查脚本时保留保护范围。
- 专业编辑：桌面主要宽度、明暗、双语言、200% 缩放、键盘、容器变化和草稿恢复。
- 运营选用：窄屏表单、参数校验、保存失败、试算、发布权限与停用反馈。
- 记录本期已覆盖的能力和已知限制；单元、模拟页面、真实联调、人工业务 / 视觉验收分别说明。

### 9.3 排期与风险处理

按 RE0 → RE1 → RE2 → RE3 → RE4 推进，RE5 依据实际业务插入。RE0 产出验证结果后，按实际人员可用时间估算每期工时和发布日期；当前不在缺少人员与业务契约的情况下承诺精确总工期。

如需压缩首发范围，优先缩减示范模板数量、表单样式、检索维度和高级编辑便利性，保留模板选用闭环及版本 / 隔离 / 执行边界。流程和决策表可以按既定里程碑交付，不能将“已确认需要”改回永久不做。
