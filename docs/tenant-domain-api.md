# P10 域名验证与启用设计（S4c实施中）

本文细化已授权P10的域名部分。网络组件、持久化生命周期、HTTP权限与旧库升级已通过本地验证，管理页面已通过模拟浏览器及隔离真实目录联调。后者覆盖正常登录后的登记/挑战与未验证启用拒绝，不代表生产公网DNS/TLS通过。不能从“登记成功”推断域名控制权、DNS路由或TLS可用。交付状态以[进度](tenant-platform-progress.md)为准。

## 权限与归属

平台租户、admin门户、部署登记的平台操作者以及具体操作权限必须同时满足。租户内superAdmin不能自行取得平台身份。租户/域名管理页面使用既有平台目录接口；不提供任意tenantId切换普通品牌接口的后门。品牌仍在当前可信入口内配置。

域名hostname、归属租户、portal登记后不可原地换绑；域名全局唯一。禁用保留登记和证据，不删除后立即转租。版本号用于并发控制，Long仍以字符串传输。

## 验证链

1. 登记域名，状态PENDING，不开放登录入口。
2. 平台操作者生成有时限的随机DNS TXT挑战，记录名固定为`_sma-tenant.<域名>`，值带受控协议前缀。TXT证明控制权，不能由表单提交“已验证”标记代替。
3. 读取域名A/AAAA，并核对部署显式配置的入口IP允许清单。没有清单或解析到未授权地址时不探测、不启用。支持内网部署时也必须显式登记实际入口IP，不能自动信任任意私网地址。
4. TLS只连接已解析并核准的固定IP、443端口；设置实际域名的SNI及HTTPS主机名校验，使用部署JVM信任链，验证证书有效期。不能重新按hostname连接、关闭证书校验、跟随HTTP重定向或把任意URL作为探测输入。
5. 控制权、DNS路由和TLS检查结果分别记录。全部成功后，操作者再显式启用，仍须租户ACTIVE、证据未过期、版本未变化。证书过期不得继续以READY开放入口。

这里验证部署的证书，不负责申请、续签或安装反向代理证书。DNS传播、不同边缘节点和证书续期由部署运维管理；界面显示探测时间与证书有效期，不把单次探测宣称为永久可用。

## 执行与并发

验证包含外部DNS/TLS调用，使用NATIVE协议，不能套通用LOCAL同库事务。先以短事务登记操作ID、挑战/域名版本和有时限的在途标记；释放数据库连接后探测；最后以短事务核对操作ID、版本和租约再保存结果。迟到结果、禁用期间的结果、已轮换挑战的结果不能启用域名。

同一域名同时只允许一次验证，进程级网络工作数有界。DNS重试、连接、读取和整体期限分别有界；结果未知时查询已有状态，不自动重发验证。超时标记不代表外部动作撤销，也不允许旧工作覆盖新检查。平台其他租户的正常登录不应等待验证网络调用。

现有有效入口重新校验时保留其上次有效证据直到证书过期或被显式禁用；一次网络超时不能悄悄把全部现有会话停用。新的启用操作必须使用近期成功证据，不能用失败结果放行。

## 状态与主域名

- PENDING：已登记，尚不能作为入口。
- ACTIVE：显式启用，解析入口时仍核对验证、TLS和租户状态。
- DISABLED：显式禁用，保留域名占用、历史证据和审计。

控制权、DNS、TLS及最近检查状态独立展示，不能把已登记和已启用合并为一个开关。启用/禁用/主域名变更使用并发版本；主域名按租户和portal维护，防止两个操作者同时产生多个主域名。禁用入口时提升租户安全代次，使重新启用后旧认证材料不能复活。平台最后一个可用入口受保护，防止误锁死平台管理。

租户创建仍进入PROVISIONING。S4c目录界面不把它描述为已完成业务库、账号和数据初始化；完整开通编排属于S7。

## 拟改路径与验收

沿用P10授权范围：`tenant/internal/service`的验证/生命周期、`tenant/internal/persistence`和追加tenant迁移、目录Controller与权限目录、双语消息；next的`features/tenant`目录/域名页面及路由。既有DomainController的LOCAL登记和平台授权回调保留，网络验证方法使用显式NATIVE覆盖。外部网络不放进数据库锁事务。

验收覆盖：平台身份与权限拒绝、挑战不符/过期、DNS未授权、TLS主机名/信任/期限失败、未验证无法启用、实际连接IP固定、并发与迟到结果拒绝、主域名唯一、最后入口保护、禁用恢复认证代次，以及UI对登记/检查/启用的区分。网络组件以独立可控DNS/TLS夹具验证；没有实际公网域名与生产代理证据时，明确不宣称完成生产DNS/TLS验收。

## 管理接口与页面契约

下列路径均在`/api/tenant/domains`下，除了已登记的部署回环入口，不允许用页面字段替代网络证据。ID、version和安全代次在JSON中保持字符串。

| 方法与相对路径 | 权限 | 语义 |
| --- | --- | --- |
| GET `?tenantId=...`、GET `/{id}` | domain:view | 当前目录及证据投影；不接受调用方声明验证结果 |
| GET `/tenant-options?page=...&keyword=...` | domain:view | 分页最小租户选项，不要求租户管理权限，不返回安全代次 |
| GET `/verification-settings` | domain:view | 部署是否配置验证及入口IP清单；只读，租户不能编辑 |
| POST `/` | domain:create | hostname、tenantId、portal；登记后PENDING，每租户最多20个域名 |
| POST `/{id}/challenges` | domain:verify | expectedVersion；生成或轮换24小时TXT挑战，取消原在途检查 |
| POST `/{id}/checks` | domain:verify | expectedVersion、operationId；NATIVE短事务/网络/短事务；不自动启用 |
| GET `/{id}/checks/{operationId}` | domain:verify | 只允许原操作者查询原回执；未找到不证明没有提交 |
| PUT `/{id}/enabled` | domain:update | expectedVersion、enabled；启用需租户ACTIVE及当前挑战的24小时内成功证据 |
| PUT `/{id}/primary` | domain:update | expectedVersion；仅有效ACTIVE域名可设主入口，按租户与portal串行维护 |

权限完整前缀为`tenant:`。写请求沿用现有来源防护和请求治理；LOCAL操作携带Idempotency-Key，NATIVE检查以operationId绑定域名、输入版本和原操作者。检查30秒租约，网络总预算最多12秒、每进程最多4个；每域名最多1000条持久检查回执，达到上限明确拒绝，不自动删除UNKNOWN/历史回执。

页面分别展示登记状态、控制权、DNS、TLS、证书截止和最新检查状态。`activationReady`仅说明证据满足激活要求，页面仍须结合租户ACTIVE和操作权限，最终由服务器判定。挑战复制只使用当前详情；域名归属/portal登记后不可编辑。刷新详情、切换租户或重新登录须丢弃旧请求结果；同身份切换语言不清空未提交表单。

网络错误或超时保留原operationId，后续仅查询原回执；RUNNING、EXPIRED、未观察到结果都不能等同成功。LOCAL写入未知结果先读回目录/详情核对，不能自动创建新键重复登记、轮换挑战或启停。用户选择离开未确认操作时须明确提醒，不能用关闭弹窗暗示服务端已取消。

租户页只登记目录及管理状态。PROVISIONING不是业务库/初始账号/迁移已成功的证明，目录状态变为ACTIVE也不提供此保证。S7交付之前页面明确说明须另外完成部署准备，不使用“一键开通成功”等文案。
