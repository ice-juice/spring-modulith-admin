# 开放平台约定

对应 P4-1～P4-2。后台管理接口为 `/api/openapi`；应用调用接口为 `/open/**`，由独立安全过滤链处理，不复用管理员会话。

## 应用中心

保留 JBolt 的 13 种应用分类、名称、简介、AppId、启停、签名开关和关联对象元数据。类型 101 仅保留分类，不自动签发浏览器内置客户端。微信、打印与 AI 的业务集成不在本期。

AppId 使用 128 位随机标识，AppSecret 使用 256 位随机值；密钥只在创建和轮换时返回一次，普通列表和详情不返回密钥。数据库用 AES-256-GCM 加密，AppId 作为附加认证数据。`SMA_APP_MASTER_KEY` 可提供 Base64 编码的 32 字节主密钥；本机开发未配置时持久化随机密钥到忽略版本控制的 `data/keys/openapi.key`。部署需保存该密钥，备份时与数据库分开保管。

应用管理受租户、portal 和部门/本人数据范围约束。关联对象为类型、ID、名称元数据，不授予关联对象的访问权；有关联对象时先解除关联再删除。应用更新和密钥轮换增加凭据版本，使旧应用令牌立即失效。

## 令牌与签名

`POST /open/token` 使用 AppId/AppSecret 签发短期不透明令牌，数据库只保存令牌 SHA-256 哈希。应用身份来自凭据或令牌，不能由调用者传租户请求头。仅凭据启动查询和令牌哈希启动查询允许按全局唯一值定位归属，定位后立即恢复可信租户上下文。

开启签名时，令牌签发与后续请求都需要 `X-App-Id`、`X-Timestamp`（UTC Unix 秒）、`X-Nonce`、`X-Signature`。时间允许前后 300 秒，nonce 使用数据库唯一约束防重放。签名采用 HMAC-SHA256，密钥为 AppSecret 的 UTF-8 字节。

签名原文按以下顺序使用换行符连接，最后一行后不追加换行：

```text
HTTP_METHOD
RAW_PATH
CANONICAL_QUERY
TIMESTAMP
NONCE
SHA256_BODY_HEX
```

HTTP_METHOD 大写；RAW_PATH 是不含查询串的原始编码路径；查询参数解码后按键和值排序，再逐项按 RFC3986 编码，重复参数保留，用 `&` 连接；空查询串对应空行。正文使用实际发送的字节计算 SHA-256，小写十六进制；空正文也计算其 SHA-256。`X-Signature` 为签名结果的十六进制。签名开关关闭只跳过签名，仍必须通过 AppSecret/令牌校验。

开放接口只提供明确列出的应用能力，不赋予用户管理权限。初始提供应用身份查询与回显用于集成验证；新增业务 API 必须声明范围并遵守模块边界。普通管理员令牌不能调用 `/open/**`，应用令牌不能调用 `/api/**`。认证错误返回真实 HTTP 401/403，正文沿用 ApiResponse 与双语言错误码。
