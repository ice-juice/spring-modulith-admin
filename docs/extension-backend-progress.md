## 构建结构

根 Maven reactor 包含 `extension-sdk`、`extension-protocol`、`extension-runtime`、`extension-security`、`extension-worker`、`backend`。SDK 无外部依赖；协议与运行时可分别复用；安全服务是独立 Boot 可执行包；工作节点是独立命令行 JAR；业务宿主不持有签名私钥。

`extension-security` 独立包 `com.sma.release`，不被业务宿主扫描。MySQL 是目标持久层，安全服务事务测试使用随机 H2 内存库。`tools/dev/verify-backend.ps1` 已改为根 reactor 验证，包含上游模块；单独在 backend 构建前须安装上游模块或改用 reactor。

### 代码审查关注点

- `ArchiveSnapshot` 才是递归的不可变字节读取器；旧的浅层 `ArchiveInspector.inspect` 已删除，保留路径校验工具。需要继续验证未知嵌套包、资源冲突、ZIP 边界、被遮蔽库和解析资源耗尽。
- `DeploymentService.desired` 在待发布人的会话被撤销时取消新计划并保留旧稳定版本；已签发离线租约仍存在最长 15 分钟窗口。独立撤销清单优先于普通同步获取，避免扫描拒绝阻断撤销传播。
- `LocalBootstrap` 有严格本机文件权限要求，但数据库提交后结果文件写入失败的恢复仍需完善；不能把初始化成功却丢失注册票据当作可接受完成。
- `NodeControlClient` 只使用 HTTPS、不重定向，信任公钥来自本机预置文件，缓存 hash 每次核验；配置 / 公钥轮换和缓存物理保护需继续验证。默认未启用，不应为跑通测试开启无验签捷径。
- `ReleaseDatabase` 是低频控制面的事务串行实现，目前 document 列表查询再过滤，有规模限制与分页优化待办；不要将它用于高频业务执行。
- Worker 的容器缺失、镜像未预置、数据库更新失败都应失败关闭；当前测试只验证参数及解析器，未证明真实容器执行成功。
- 不对正在运行的开发服务、数据库或模型执行重启。保留用户已有修改；不创建前端页面。
