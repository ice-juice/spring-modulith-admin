# 消息协同实现约定

对应开发计划 P3-2～P3-4，前端在 P3-7 交付。打印设计器与 AI 中心不在本期范围。

## 系统通知

通知保存标题、内容、类型、优先级、接收范围、附件、portal 和发布者部门快照。接收范围支持全部、角色、部门、岗位、用户。IAM 通过公开只读 AudienceQuery 提供有效用户，不允许 Message 查询 IAM 表。全部指发布者数据范围内的全部有效用户；显式选择不存在、跨租户、跨 portal 或不可见对象时拒绝，不能悄悄忽略。

发布时展开接收人，保存不可重复的接收人快照；后续组织或角色变化不悄悄改变既有通知的受众。每条通知最多 10000 位接收人，超限明确拒绝。管理列表受发布者部门/本人数据权限约束；个人收件箱按接收人关系授权，两种授权不可互相替代。阅读时间仅在第一次阅读时写入，重复阅读不增加已读数。

编辑通知替换接收人时保留仍在范围内用户的阅读时间，新接收人未读。管理操作通过通知行锁串行；回收站隐藏收件箱和附件，恢复后保留原接收人及阅读记录。普通删除进入回收站，本期不提供永久清空。

附件必须由当前用户上传；编辑时允许保留该通知已经引用的文件。新增引用前调用 FileQuery 校验并锁文件行，禁止跨模块 SQL。Message 贡献 FileAccessPolicy：发布者、有效接收人或具备该通知管理数据范围者可以读取；仍被通知（含回收站）引用的文件禁止删除。策略只依赖 Mapper，不能依赖消息 Service。

内容首版支持安全 HTML 子集，服务端清洗，前端仅渲染清洗结果。链接只允许 http/https，禁止脚本、事件属性、iframe 与内联样式。正文图片以受控附件展示，避免浏览器绕过 Bearer 下载校验。

## 待办、私信和汇总

待办区分发布管理接口与本人处理接口，状态为待处理、已完成、已取消。完成/取消只能从待处理进入，完成时间与取消时间由服务端写入。保存截止时间、是否已读、来源系统、外部消息/流程 ID、来源 URL、第三方收发人标识。外部 URL 只允许 http/https，内部链接使用站内绝对路径。

私信只允许同租户、同 portal 的有效用户之间发送，查询只能是发件人或收件人；阅读标记只能由收件人写入。正文按普通文本显示。消息中心返回通知未读数、待处理待办数及私信未读数，不返回不可见对象。

## 实时推送

WebSocket 只作事件提醒，通知、待办、私信及会话状态以 REST 查询结果为准。浏览器使用一次性短效握手票据，URL 不传长期 Bearer；连接绑定租户、portal、用户、会话。跨模块事件保留租户 ID，通过 Modulith 可靠监听恢复租户上下文；离线或丢消息后重新查询汇总。强制下线事件关闭对应会话连接，前端清除登录态并跳转。

## 验证重点

- 五类受众、空受众、无效/跨租户/跨 portal 目标和范围上限。
- 编辑受众后阅读时间保留、重复阅读幂等、回收与恢复后的可见性。
- 附件归属、接收人授权、引用保护、回滚与租户隔离。
- 正文 XSS 清洗、越权查看和修改、数据范围与收件箱权限分离。
- 待办状态机、UTC 截止时间、外部来源字段、私信双方隔离和未读汇总。
- 一次性 WebSocket 票据、无效/过期/重放拒绝、按用户与会话推送、强制下线。
