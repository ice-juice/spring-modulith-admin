# 单实例二开存储契约

本文件对应已通过本地验收的[单实例二开基线](secondary-development-baseline-release.md)，固定输入与证据见交付说明。完整Redis多资源和多实例能力仍按后补阶段验收。

## 业务MySQL

平台表/权限/配置仍使用平台库。业务Mapper进入显式`BusinessLedger.open(storageGroup)`会话，使用`query`或`executeLocal`；业务表、幂等回执、互斥、缓存代次、Outbox属于同一物理资源事务。禁止先开平台事务再切库。ID分配由平台号段统一提供，实体与工具路径一致；预留号段独立提交，业务回滚不退款。

`StorageCredentialResolver`是部署适配SPI，读取部署秘密，不接受HTTP明文密码。正式开通按持久任务的storageGroup查`BusinessSchemaCatalog`，执行`db/business/<module>`及独立`flyway_schema_history_business_<module>`，与框架schema均成功后才激活；缺目录或脚本保留失败回执。已有ACTIVE资源升级需维护窗口显式执行同位置/历史的追加版本并validate，再部署匹配制品；旧provision成功回执只重放原结果，不承担后续升级。教学样例见[shop-storage](../examples/shop-storage/README.md)。

## 共享缓存与未来多资源

平台`ManagedCache`及其治理语义保持。分库业务必须有专用公开入口，把可信租户、存储组、固定MySQL资源身份与实际业务库代次共同纳入读缓存流程；不能把平台`CacheRevisionStore`误作业务写的失效权威。

B2已增加`common :: cache`的`BusinessCacheCatalog`和`BusinessCache`，复用P08的类型/范围/容量/Redis键协议。目录在模块内声明，宿主校验真实owner及重复区域；只允许可重建DATA，平台会话/验证码/票据/限流等PROTECTED不允许登记。读取在事务外按目录存储组打开会话，加载器由宿主在该固定资源的只读事务执行；业务写仍通过`Session.invalidate(region)`同事务登记。新增`Session.resourceIdentity()`保留既有会话方法，通过default拒绝未知旧provider；旧provider若要启用业务缓存须显式提供物理身份。

首版只复用已配置的部署共享Redis客户端（或单实例本地/禁用缓存策略）。缓存命名空间还需区分业务物理源ID/修订，切换MySQL后不能误读旧源同名键或旧代次。平台与业务目录互不混入，尚未实现的业务缓存运维动作不可用平台清理接口替代。

共享Redis连接地址/拓扑/DB/ACL/TLS仍是部署启动配置，不从租户请求创建客户端。入口应有宿主总量与租户配额，旧读取保持原会话到结束，故障只对可重建值受控回源。未来X2b/S8通过宿主资源解析替换共享客户端，不要求业务代码取得RedisTemplate或更换事务协议。

## 验收与版本

单实例部署也必须保持`sma.cache.nodes.enabled=true`及有效节点租约，业务会话在平台持久登记准入并在关闭时释放。缓存命中仍需解析绑定、登记/释放会话并读取实际业务库代次；不能按纯Redis GET估算延迟。禁止为提速绕过这些一致性检查。

启动/重启后先确认当前进程已取得有效节点租约，再开放业务入口；旧进程租约尚有效时不能删除记录抢占。当前Outbox仅轮询已打开的物理资源，重启后的未打开资源不会自动建池扫描；持续投递场景须先打开需要恢复的业务资源并监控积压，自动资源发现另行增强。B4的打包重启证据覆盖品牌与审计持久化，业务事务与Outbox由独立样例/真实库专项覆盖，不把两类证据混称为完整业务冷启动恢复。

当前默认业务连接预算为每进程最多8个物理池、合计32连接、同主机16连接，每资源目录上限8连接，空闲5分钟可回收；平台池、号段独立连接和最多一个并发迁移使用的2连接另计。本地业务缓存独立占用至多`sma.cache.max-bytes`/`max-scopes`预算，并在最多8个源槽间分摊；平台缓存另有自身预算，不能把该设置理解为全进程共享总内存。Redis模式的字节/条数门禁按租户与区域作用域执行，进程内元数据槽数受限；不能将其宣传为整个Redis实例的总内存上限，实例仍须配置容量、过期与淘汰策略并监控键基数。业务缓存入口默认最多32并发，同租户最多8，底层加载还遵守既有P08门禁；复用部署Redis客户端，不按租户新建线程/客户端。以上是可配置的资源上限，未做生产规模吞吐或P95承诺；接入方须按实际SQL、平台库往返和Redis延迟压测。

- 两个真实业务库和两个租户：提交、回滚、同键重放、动态工厂ID、缓存失效和Outbox均核对实际物理落点。
- 缓存：未登记/PROTECTED/非法租户拒绝、事务内误用拒绝、源ID/修订隔离、故障回源及租户预算；共享Redis使用真实高端口测试资源与专属命名空间。
- 业务样例只进入隔离验证工程或不参与main构建的教学目录；真实客户代码不进基座main。
- B4通过后登记基座源码摘要/提交、可用公开API、验证组合及迁移方式。后续增强优先新增可选契约，破坏式变更仍按升级规则执行。

不承诺在线无停写搬库、多实例就绪、全业务表自动复制、专用Redis改绑或完整SQL运维UI；这些由后补阶段单独验收。
