# P08 多实例主键分配补充

归属为基座基础设施，沿用用户对P08完整实施的授权。作为M1d双JVM写入验收的前置，已完成迁移、分配器和实际宿主专项；分轮结果及完整回归失败/复验边界见[进度](../cache-governance-progress.md)。没有部署到用户运行服务，不等同完整多实例验收。

## 决策

采用共享MySQL号段分配，不依赖机器哈希、进程编号或时钟生成ID。Common拥有唯一分配状态，每次独立事务领取有限且互不重叠的号段；进程只在已确认提交的号段中递增。范围领取确认丢失则丢弃该范围，不猜测提交结果；进程退出和业务回滚不退还未用ID。仍返回正Long，HTTP仍使用字符串，既有ID不重写。

MyBatis实体自动分配与既有`IdWorker`调用统一接入相同生成器，不能只修改其中一路。号段耗尽时用独立短连接领取，避免业务连接池耗尽时等待自己的额外连接；连接继承宿主实际MySQL认证/TLS配置，采用有界等待、网络和SQL超时。领取失败明确拒绝，不降级随机数、本地雪花或Redis。

当前支持基座默认的Hikari＋MySQL JDBC URL连接，数据库须明确写在URL中；拒绝另行设置catalog/schema/connectionInitSql，避免主池与短连接使用不同数据库。也拒绝自动重连和隐式useConfigs，URL中的连接/读超时不得无界或超过2秒/5秒。迁移账号需要临时过程的CREATE ROUTINE、EXECUTE、ALTER ROUTINE及原DDL/读取权限；过程执行后删除。运行时仅对固定号段表SELECT/UPDATE，不执行业务表扫描。

ID是不可解释的唯一标识，不承诺生成时间或跨实例提交顺序。默认“最近”列表改用createdAt再以ID打破同时间平局；分页与后台游标检查是否错误依赖全局连续递增。现有租户工作分页循环会回到起点，字典预热有持久数据代次检查，不能把单次游标扫描宣称覆盖未来插入。

## 路径与影响

- Common内部生成器、配置及平台分配状态；追加Common迁移，登记为PROTECTED，普通缓存管理不得清空或回收未用号段。
- 配置沿用宿主主库连接，保持单写权威来源；平台表例外进入精确架构名单。业务显式提供ID必须遵守已有对象归属与ID契约，不能猜测或占用平台分配范围。
- 涉及按ID倒序冒充“最近”的IAM、配置/文件、消息、开放应用、规则与集成服务列表，仅改明确的默认时间排序，保留权限/筛选/自定义排序。
- 测试覆盖两个独立分配器并发、重建/重启、业务回滚、提交确认丢失、容量耗尽、两个分配入口及旧库迁移；再执行实际双JVM及根标准回归。

## 首次升级与回退

首次从旧雪花写入器切换时必须停止旧写入器并完成备份，再执行迁移、启动全部新版本。迁移只读取本库数值ID列的最大值以保留已有标识，初始化分配下界；不读取或输出业务载荷。此通用结构迁移不构成业务跨模块查询的例外。新空库另设高于内置固定种子的保留起点。

这一步是有维护窗口的初次基础设施切换，不能承诺旧雪花写入器和新号段写入器混跑。一旦启用新分配器，回退版本也必须保留该适配器；不能直接回到不知道号段协议的旧JAR。后续兼容版本可以共享同一分配状态滚动替换，不需要重新登录或改写ID。

数据库恢复、迁移或克隆时先停写并退出所有持有旧号段的进程，再核对分配下界与已有数据；禁止在活跃写入器旁恢复旧分配快照。MySQL HA须保证单写和已确认分配的持久性；异步复制可能丢失已确认提交时，不能声称无条件唯一且零数据丢失。此要求与会话/安全状态的数据库权威边界一致。
