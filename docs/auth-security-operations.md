# P07 认证安全运维与验证

状态：本机8080当前服务已于2026-11-11部署，详情见[实施进度](auth-security-progress.md)；不代表生产环境部署。

## 密钥文件

部署通过 `SMA_AUTH_SECURITY_KEY_FILE` 指向仅服务账号可读的受保护文件。文件使用 Java properties 格式；每个密钥为独立生成的 32 字节安全随机数的 Base64，不能复用加密密钥和 pepper，也不能使用仓库测试密钥。以下为格式占位，不能直接运行：

```properties
encryption.active=enc2026
encryption.enc2026=<独立随机32字节的Base64>
pepper.active=pwd2026
pepper.pwd2026=<另一独立随机32字节的Base64>
```

配置为空时不生成默认密钥，绑定和安全密码设置不可用；已有需要密钥的认证也不能降级。指定但不可读取/格式错误的文件使启动失败。keyId 只允许 1～64 位 ASCII 字母、数字、下划线或短横线。TOTP issuer 默认 `SMA Admin`，通过 `sma.auth.security.issuer` 配置，不能包含冒号。

密文保存 `v1.keyId.nonce.ciphertext` 封装，认证附加数据含格式版本、keyId、租户、用户、portal 和用途。轮换时增加新 keyId、切换 active，并保留旧键用于读取；重启才重载密钥环。旧密文不能仅改 keyId 字段，必须解密并用新键重新加密。pepper 迁移依赖用户成功验证后重哈希，不能只修改数据库标识。

密钥备份与数据库备份分开授权保管。缺少旧密钥不能关闭 TOTP，应恢复匹配密钥；任何恢复、退役旧密钥与制品回退都需在测试环境演练，不能复活已消费挑战或失效会话。

### 轮换操作

1. 先备份旧密钥环。增加独立的新加密键与新 pepper，切换各自 active，旧键继续保留；部署所有节点后才进入旧键退役阶段。
2. 服务每分钟针对已观察到的租户（包含默认租户1）执行一次 TOTP 重加密，每批最多100行，行锁与事务保证整批失败回滚，重复运行只处理旧键。包括已绑定和待绑定密文，不改变启用状态、挑战、版本或已接受时间步。未活跃租户会在下一次密码登录阶段加入维护范围，因此不能只凭经过一段时间判断迁移完成。
3. DBA 在受控只读会话检查全部租户的非删除 `auth_totp_credential`，用 `SUBSTRING_INDEX(secret_ciphertext,'.',2)` 与 `SUBSTRING_INDEX(pending_secret_ciphertext,'.',2)` 汇总旧版本数量；两个字段全部迁移或过期待绑定材料清理后才能退役旧加密键。不得把完整密文导出到普通日志。轮换失败有不含密文的服务端告警；必须修复缺失键或损坏材料，不能禁用 TOTP。
4. `auth_security_password.pepper_key_id` 只有在用户成功安全密码验证/改密后迁移；没有全部迁移就必须保留旧 pepper。当前没有业务消费场景，不能承诺按固定天数完成退役。
5. 在隔离环境只保留新加密键，验证已迁移密文能解密、正确验证码可用、重放仍失败；仅更改 active 不等于完成迁移。密钥文件只在重启时读取，部署重启由运维安排。

### 数据库恢复与回退

恢复必须在所有节点停止或流量完全隔离的窗口进行，不允许在线对运行库执行恢复脚本。

1. 恢复匹配的数据库与密钥环，使用可信 binlog/安全变更记录，将备份后的绑定、换绑、解绑、账号禁用及两类改密重放至已确认的恢复点。只清理会话无法弥补绑定状态倒退；无法证明恢复状态完整时继续隔离流量，禁止退回密码单因素放行。
2. 在明确选择的恢复 schema 执行 [auth-security-restore.sql](auth-security-restore.sql)。脚本撤销全部旧会话和挑战、清除待绑定材料、推进安全版本，并将 TOTP 防重放时间步提升到当前窗口之后；不删除已绑定密钥，不重置安全密码，不清空限流。可重复执行，重复只会进一步撤销，不会恢复旧权限。
3. 校准时钟并保持隔离至少15分钟，覆盖备份回退可能遗失的最大尝试窗口；若存在未来时间步仍须等待其过去。先以新密码登录＋新动态码完成恢复验收，验证旧 Token、旧挑战、旧动态码与过期解锁均失败，再放开流量。
4. 已有绑定数据后，只能使用支持 P07 相同强制规则及当前 schema/keyId 的制品。不得启动不识别 TOTP 的旧版；不支持相同规则的回退只能保持隔离后修复。部署演练必须覆盖实际代理、节点与备份工具，本地自动化验证不能替代生产演练。

### 兼容组合与验证边界

| 组合 | 结果/要求 |
| --- | --- |
| P07 后端＋当前新版前端 | 已有真实浏览器验证；密码通过后进入独立TOTP页，成功后才保存正式Token |
| P07 后端＋本次同步适配的旧版前端 | 已有独立登录、TOTP、安全设置和解绑的真实浏览器验证 |
| P07 后端＋未适配的旧客户端 | 已绑定用户只得到MFA_REQUIRED且无Token；未知分支必须失败关闭。没有承诺第三方严格DTO解码器兼容，需接入方升级后验收 |
| 不支持P07的旧后端＋已绑定数据 | 不支持，禁止混布和回退；必须先退出全部旧节点再开放绑定。不能声称旧二进制会自行强制新规则 |

本轮未做生产压测、外部渗透测试、实际备份工具的全链路灾备或生产部署。算法/并发/恢复专项与真实浏览器的通过说明已验证范围，不构成“任何攻击都不可能绕过”的绝对保证。

## 当前验证环境

根 Maven reactor；JDK 21。测试使用默认专用 `springboot_modulith_admin_test`，测试启动会清空重建，只能串行运行数据库验证。不要指向业务库。输出目录 `backend/target/p07/target` 保持 ArchUnit 默认测试排除路径语义。

迁移专项 `AuthSecurityMigrationIT` 显式运行，不能与已启动的测试应用并行。该测试清空专用库、迁移到 auth V3、写入历史会话、升级 V4，并验证旧会话没有虚构 MFA；随后验证空库迁移及 Flyway 校验。它没有执行业务库迁移。

算法采用 java-otp 0.4.0（MIT）、Spring Security Argon2id 和 Bouncy Castle 1.83（Bouncy Castle Licence）；测试覆盖 RFC 6238 SHA1/256/512 全部六个时间点，生产 TOTP 固定 SHA1/6 位/30 秒。

## 实现与方案字段映射

登录新密码的后端策略为 8～12 位 ASCII 字母数字，至少包含一字母、一数字；登录、解锁与重新认证仍验证原始历史密码，不对旧值截断或施加新设长度。所有凭据写入口共享 IAM 策略，词表资源和摘要在 `backend/src/main/resources/iam/password-policy/`。SecLists 派生词表 v1 共 2082 条，SHA-256 为 `ddbe906c330547a70a0c72d8a2e137101ee524757027e406fe2fdb1d8a43a78e`，源许可证与过滤过程同目录保存；资源缺失/摘要不符使启动失败。规则只在服务端写入前检查，数据库中的哈希本身不能证明密码强度。

IAM 的 `AccountPasswordPolicy` 是同步写入 SPI；auth 实现只读取自己的安全密码凭据，不依赖 IAM 用户服务，避免模块与 Bean 循环。`AccountCredentialGuard` 只协调当前人类账号写入，必须在已有写事务中调用；锁顺序为 IAM 租户凭据锁/用户行 → auth 账号锁。不能在持有 auth 锁后申请 IAM 写锁，不能用异步事件修复已经写入的相同密码。

- 挑战哈希使用项目已有 SHA-256 十六进制表示，列为 `CHAR(64) CHARACTER SET ascii COLLATE ascii_bin`，与方案 BINARY(32) 等价地保留 256 位摘要及精确比较。
- TOTP keyId 随加密封装保存，不另外重复列；已启用状态用 `enabled`，待绑定材料独立保留。
- 限流使用数据库时间的固定窗口预算预占，计数在 `REQUIRES_NEW` 事务提交，不依赖失败后更新；尝试预算包含成功请求。此选择比仅计失败更严格，避免并发验证和回滚退还预算，UI 文案不承诺“只计错误”。
- 维护清理与重加密在 auth 内部执行；没有新增绕过认证的管理 HTTP 入口。部署结果与验证边界以实施进度为准。
